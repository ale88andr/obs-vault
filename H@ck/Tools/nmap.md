## Что такое Nmap и пять вопросов

Nmap — сетевой сканер, который отвечает на 5 вопросов:

1. **Кто есть в сети?** (обнаружение хостов)
2. **Где открыто?** (порты и их состояния)
3. **Что там работает?** (служба, версия, ОС)
4. **Что с этим не так?** (проверки через NSE-скрипты)
5. **Как это записать и сравнить?** (отчёты, Ndiff)

## Стенд и установка

- Учебный стенд: несколько виртуальных машин в локальной сети (жертва/сервер + сканирующая машина, обычно Kali Linux).
- Установка: `apt install nmap` (Debian/Kali), `brew install nmap` (macOS), установщик с nmap.org + **Npcap** (Windows).
- Проверка: `nmap --version`.

> Важно: часть режимов (SYN-скан, `-O`) требует **прав root/sudo**; на Windows — запуск от администратора.

## 1. Основы сканирования

Базовый синтаксис: `nmap [тип скана] [опции] {цель}`

```
nmap 192.168.1.10                 # топ-1000 портов TCP
nmap -F 192.168.1.10              # быстрый режим, 100 портов
nmap -p 22,80,443 192.168.1.10    # конкретные порты
nmap -p- 192.168.1.10             # все 65535 портов (долго)
nmap 192.168.1.0/24               # вся подсеть
nmap 192.168.1.10,20,30           # конкретные адреса
```

Что важно понять из первых запусков:

- по умолчанию сканируются **1000 самых популярных TCP-портов**, а не все;
- вывод даёт порт/состояние/службу, но **служба угадывается по номеру порта** — это ещё не доказательство;
- `-v` — подробнее, `--reason` — почему порт получил такое состояние, `--open` — показывать только открытые.

## 2. Кто есть в сети

**Цели (targets):**

```
nmap 192.168.1.0/24                 # CIDR
nmap 192.168.1.1-50                 # диапазон
nmap -iL targets.txt                # список целей из файла
nmap 192.168.1.0/24 --exclude 192.168.1.1,192.168.1.10 # исключить из скана
nmap -n 192.168.1.0/24              # без DNS-резолва (быстрее)
```

**Три режима обнаружения хостов:**

- `-sn` — ping-scan: только найти живые хосты, **без сканирования портов** (замена старого `-sP`);
- `-sL` — list-scan: просто перечислить цели, ничего не отправляя (удобно проверить, что вы сканируете именно то);
- `-Pn` — не проверять доступность, считать хост живым и сразу сканировать порты.

**Когда нужен `-Pn`:** если хост блокирует ICMP/ARP-проверки, Nmap может решить, что его «нет». Тогда `-Pn` помогает, но резко увеличивает время скана (порты проверяются у всех целей).

Трассировка

Флаг `--traceroute` сделает трассировку маршрута

```
sudo nmap -sn --traceroute 192.168.1.1
```

## 3. Где открыто: порты и состояния

### TCP-рукопожатие

SYN → SYN/ACK → ACK. По тому, как цель отвечает на эти пакеты, Nmap делает вывод о состоянии порта.

| Ответ на запрос  | Состояние |
| ---------------- | --------- |
| "да" - `SYN-ACK` | open      |
| "нет" - `RST`    | closed    |
| тишина           | filtered  |

**`-sS` против `-sT`**

|                     | `-sS` (SYN, half-open)                            | `-sT` (connect)                              |
| ------------------- | ------------------------------------------------- | -------------------------------------------- |
| Как работает        | отправляет SYN, при SYN/ACK рвёт соединение (RST) | полноценно устанавливает соединение через ОС |
| Права               | нужен root                                        | работает без root                            |
| Скорость/скрытность | быстрее, меньше следов в логах приложений         | медленнее, соединения видны в логах сервиса  |
| Когда               | стандарт для пентеста (Linux)                     | без root, или если SYN блокируется           |

`-sS` - `SYN-скан`: "Алло" и повесить трубку

однако не все службы используют протокол `tcp` 
### UDP (`-sU`)

UDP не имеет рукопожатия: Nmap шлёт пакет и ждёт ответа. Открытый порт может не ответить вообще, закрытый — прислать ICMP «port unreachable». Поэтому UDP-скан **медленный и неоднозначный**, часто даёт `open|filtered`.

### Порты

`-p` какие порты проверять

```
sudo nmap -sS -sU -p T:80,443,U:53,161 192.168.1.5
```

`-F` fast - 100 популярных портов
`--top-ports` N популярных портов
### Шесть состояний порта

- **open** — сервис принимает соединения;
- **closed** — порт доступен, но сервиса нет (пришёл RST);
- **filtered** — ответа нет: фильтр/фаервол/IDS дропает пакеты;
- **unfiltered** — порт доступен, но открыт он или закрыт, неясно (обычно после ACK-скана);
- **open|filtered** — Nmap не может отличить открытый порт от отфильтрованного (типично для UDP и некоторых TCP-режимов);
- **closed|filtered** — не может отличить закрытый от отфильтрованного (редко, в IPID-сканах).

> `--reason` - почему nmap принял решение о состоянии порта(syn-ack,reset,no-response)

> `--packet-trace` - показать отправленные и полученные пакеты

Именно эти состояния — главный «язык» вывода Nmap, и их ну1жно читать, а не смотреть только на `open`.

## 4. Что работает: службы, версии, ОС

### Порт ≠ служба

Номер порта — лишь соглашение. На 80 может висеть что угодно, SSH могут повесить на 2222. `/etc/services` — справочник, а не истина.

### Как работает `-sV`

```
nmap -sV 192.168.1.10
nmap -sV --version-intensity 5 192.168.1.10
nmap -sV --version-all 192.168.1.10      # максимум проб, медленнее
```

Nmap отправляет набор «фингерпринтов» (nmap-service-probes): баннеры, ответы на специфические запросы, и сравнивает с базой. Результат — служба + версия + иногда доп. данные (например, версия ОС в баннере).

### Версия ≠ уязвимость

Старая версия — это **сигнал проверить**, а не приговор. Уязвимость зависит от конфигурации, патчей, сетевой доступности и конкретного CVE. На собеседованиях любят вопрос: «Вы нашли OpenSSH 7.x — он уязвим?» Правильный ответ: нужно проверить, какая именно уязвимость, какие условия эксплуатации и подтверждается ли она.

### Отпечаток ОС (`-O`)

```
nmap -O 192.168.1.10
nmap -O --osscan-guess 192.168.1.10
```

Работает по особенностям стека TCP/IP (TTL, размеры окна, поведение на нестандартные пакеты). Требует root, не всегда точен, особенно за NAT/прокси.

| Признак                     | Linux | Windows |
| --------------------------- | ----- | ------- |
| Начальный TTL               | 64    | 128     |
| Окно TCP                    | 64240 | 65535   |
| Ответ на некорректный пакет | свой  | свой    |
### Флаг `-A`

```
nmap -A 192.168.1.10
```

`-A` = агрессивный режим: **`-sV` + `-O` + `-sC` (default-скрипты) + `--traceroute`**. Удобно для быстрого «снимка» хоста, но шумно и медленно — не стоит применять ко всей сети и к продакшену.

## 5. NSE: что с этим не так

NSE (Nmap Scripting Engine) — скрипты на Lua, которые расширяют Nmap: от получения заголовка сайта до проверки конфигурации SMB.

```
nmap -sC 192.168.1.10                       # default-набор (= --script=default)
nmap --script http-title -p 80,443 192.168.1.10
nmap --script ssl-cert,ssl-enum-ciphers -p 443 192.168.1.10
nmap --script smb2-security-mode -p 445 192.168.1.10
nmap --script-help http-title               # что делает скрипт
nmap --script "http-*" 192.168.1.10         # маска по имени
nmap --script vuln 192.168.1.10             # осторожно: шумно/агрессивно
```

**Как читать имя скрипта**: обычно `<категория/протокол>-<объект>-<действие>`, например:

- `http-title` — протокол http, получить title;
- `ssl-cert` — данные сертификата;
- `ssl-enum-ciphers` — перечислить поддерживаемые шифры и оценить их;
- `smb2-security-mode` — режим подписи SMB2 (частая находка аудита).

Категории скриптов: `default, safe, discovery, version, auth, brute, intrusive, vuln, exploit, dos, fuzzer, malware, external, broadcast`. `intrusive`/`dos`/`exploit` — только с разрешения и осторожно.

Практический смысл: `-sV` говорит «здесь nginx 1.18», а NSE говорит «вот заголовок сайта, вот истёкший сертификат, вот SMB без обязательной подписи» — то есть переводит версии в **наблюдаемые факты о конфигурации**.

> Описание скрипта можно получить с помощью флага `--script-help <name>`

Скрипты nmap расположены в директории установленного nmap:  `/usr/share/nmap/scripts`

`--script-updatedb` - перечитать индекс скриптов (в случае, если скрипт добавляется вручную)

## 6. Как записать и сравнить

### Сохранение результатов

```
nmap -oN scan.txt  192.168.1.10   # обычный текст
nmap -oX scan.xml  192.168.1.10   # XML (машиночитаемый)
nmap -oG scan.gnmap 192.168.1.10  # grepable
nmap -oA scan      192.168.1.10   # сразу все три формата
```

### Скорость и темп: `-T0…-T5`

- `-T0` paranoid, `-T1` sneaky, `-T2` polite — очень медленно, для скрытности и хрупких сетей;
- `-T3` normal (по умолчанию);
- `-T4` aggressive — обычный выбор в локальной сети/лаборатории;
- `-T5` insane — максимально быстро, высокий риск потерь и ложных `filtered`.

Тонкая настройка вместо «шаблонов»:

```
nmap --max-rate 100 --min-rate 50 192.168.1.10
nmap --host-timeout 5m --max-retries 2 192.168.1.10
```

`--max-rate` ограничивает пакеты/сек, `--host-timeout` не даёт зависнуть на одном хосте, `--max-retries` уменьшает повторы.

### Контроль изменений: Ndiff

```
ndiff scan_old.xml scan_new.xml
```

Сравнивает два XML-скана и показывает, что появилось/исчезло/изменилось (новые порты, смена версии). Это основа регулярного мониторинга своей сети.

### Отчёт в HTML

```
xsltproc -o scan.html /usr/share/nmap/nmap.xsl scan.xml
```

XML + штатная XSL-таблица → аккуратный HTML-отчёт, который можно приложить к задаче/отчёту.

## 7. Глазами защитника

### Почерк сканирования в tcpdump

```
tcpdump -nn -i eth0 'tcp[tcpflags] & tcp-syn != 0'
```

Видно характерную картину: множество SYN по разным портам с одного адреса, RST в ответ, серии по возрастанию портов, всплески UDP/ICMP. SYN-скан не завершает соединение, поэтому в логах приложения его нет — но на уровне сети он заметен.

### Где остаются следы

- фаервол/роутер (дропнутые пакеты, счётчики);
- IDS/IPS (Suricata/Snort — сигнатуры сканирования);
- логи веб-сервера/SSH — уже при `-sT` и при работе скриптов;
- NetFlow/зеркало трафика.

### Основа защиты

Сокращать поверхность атаки: закрыть лишние порты, ограничить доступ по IP/сети, включить rate limiting и блокировку после серии попыток, обновлять сервисы, не выставлять админ-интерфейсы наружу.

### Три уровня проверки

Регулярная самопроверка: (1) изнутри — что реально слушает; (2) снаружи — что видно из другой сети; (3) после изменений — сравнение сканов через Ndiff. Сканировать свою сеть нужно так же, как это сделает атакующий, и проверять, что видят защитные средства.

## 8. Полный практикум

Сквозной сценарий в том порядке, в котором его удобно повторять:

1. Зафиксировать область сканирования — убедиться, что цели правильные;

```
nmap -sL -n 192.168.1.3,5
```

2. Найти живые хосты и сохранить результаты;

```
sudo nmap -sn -n -oN hosts-$(date +%F).txt 192.168.1.3,5
```

3. Открытые TCP-порты `-sS` (или `-sT` без root);

```
sudo nmap -sS -p- -oN tcp-all.txt 192.168.1.3
```

4. Открытые UDP-порты `-sU` по ключевым портам (53, 123, 161 и т.п.);

```
sudo nmap -sU -p 53,123,161 -oN udp-all.txt 192.168.1.3
```

5. Определить версии служб по найденным портам из этапов {3,4};

```
sudo nmap -sV -p 22,8080 192.168.1.3
```

6. `-O` / `-A` — ОС и дополнительный контекст;
7. NSE — `http-title`, `ssl-cert`, `ssl-enum-ciphers`, `smb2-security-mode`;
8. `-oA` — сохранить, `xsltproc` — HTML-отчёт;
9. повторить позже → `ndiff` — что изменилось.

Итоговая таблица практикума: хост → открытые порты → служба/версия → находки NSE → оценка риска → рекомендация.

## 9. Типичные ошибки, собеседования, развитие

**Частые ошибки:**

- запуск `-sS`/`-O` без `sudo` и удивление, что «не работает»;
- сканирование чужих сетей без разрешения (юридическая и этическая ошибка);
- `-A` или `-T5` по всей сети/продакшену — шум, ложные `filtered`, риск положить сервис;
- вера в «версия старая → уязвимо» без проверки;
- игнорирование `open|filtered` и трактовка его как «открыто»;
- отсутствие сохранения результатов — сравнить потом нечего;
- забыть про `-Pn`, когда хост «не находится» из-за блокировки ping;
- сканирование `/16` «на всякий случай».

**Вопросы с собеседований:** чем `-sS` отличается от `-sT`; что означает `filtered`; почему UDP-скан медленный; что делает `-A`; чем версия отличается от уязвимости; как подтвердить находку легально.

**Как практиковаться:** свой стенд (Kali + уязвимые ВМ), `scanme.nmap.org` (разрешён для тестов), TryHackMe/HackTheBox, затем — регулярный скан собственной домашней сети.

**Портфолио:** аккуратные отчёты (XML → HTML), сравнения Ndiff, описание «что нашли → чем подтвердили → что рекомендовали».

**Куда это ведёт:** сетевой аудит, оценка уязвимостей, пентест, мониторинг и защита инфраструктуры.

## Шпаргалка по флагам

|Задача|Команда|
|---|---|
|Живые хосты|`nmap -sn 192.168.1.0/24`|
|Список целей без скана|`nmap -sL 192.168.1.0/24`|
|Без DNS|`nmap -n …`|
|Считать хост живым|`nmap -Pn …`|
|Скрытый SYN-скан (root)|`nmap -sS …`|
|Connect-скан (без root)|`nmap -sT …`|
|UDP|`nmap -sU -p 53,123,161 …`|
|Версии служб|`nmap -sV …`|
|ОС|`nmap -O …`|
|Всё сразу|`nmap -A …`|
|Default-скрипты|`nmap -sC …`|
|Конкретный скрипт|`nmap --script http-title -p 80 …`|
|Справка по скрипту|`nmap --script-help http-title`|
|Темп|`-T0…-T5`, `--max-rate`, `--host-timeout`|
|Сохранить|`-oN/-oX/-oG/-oA`|
|Сравнить|`ndiff old.xml new.xml`|
|HTML-отчёт|`xsltproc -o r.html /usr/share/nmap/nmap.xsl scan.xml`|

Nmap — это не «набор флагов», а последовательность вопросов (кто → где → что → что не так → как записать), и только последний шаг превращает скан в полезный результат.
