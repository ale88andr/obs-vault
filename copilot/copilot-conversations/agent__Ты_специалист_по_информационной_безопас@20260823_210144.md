## 1. Терминологические уточнения (важно для точности)

- Современное название по MITRE ATT&CK (T1557) — **on-path атака** (Adversary-in-the-Middle). Стоит добавить сноску, чтобы заметка не выглядела устаревшей.
- Формулировка «это называется подменой MAC-адресов» неточна: злоумышленник отправляет **свой** реальный MAC, но привязывает его к чужому IP. Корректный термин — **ARP cache poisoning (отравление кэша ARP)**. Подмена MAC — отдельная техника.
- Ключевой момент, который стоит подчеркнуть явно: уязвим не ARP как баг, а его **архитектура** (RFC 826) — протокол не имеет аутентификации ответов по дизайну. Это объясняет, почему патчем проблему не закрыть, только компенсирующими мерами.

## 2. Другие векторы MITM — главный пробел

Сейчас читатель может решить, что MITM = только ARP-спуфинг. Добавил бы раздел «Векторы» хотя бы списком:

| Вектор | Уровень | Инструмент |
| --- | --- | --- |
| ARP spoofing | L2 | arpspoof, Bettercap |
| Rogue DHCP / DHCP spoofing | L2/L3 | yersinia |
| LLMNR/NBT-NS/mDNS poisoning | Windows-сети | Responder |
| DNS spoofing / кэш-отравление | L3/app | dnsspoof |
| SSL stripping (понижение до HTTP) | App | bettercap --proxy |
| Evil Twin / rogue AP | Wi-Fi | Wi-Fi Pineapple, hostapd |
| ICMP redirect | L3 | scapy |
| STP root bridge attack | L2 | yersinia |

Особо отмечу два пункта: **Responder** — сегодня это вектор №1 во внутренних сетях компаний (перехват NTLMv2-хэшей), и **SSL stripping** — потому что он выводит тему на уровень выше канального.

## 3. Раздел «Индикаторы компрометации» (обнаружение)

В заметке есть скриншот Wireshark «жёлтым цветом», но нет практических фильтров. Добавил бы:

Плюс:
- **arpwatch** — мониторинг пар IP↔MAC с алертами на смену;
- сообщения коммутатора `%PORT_SECURITY` и **MAC flapping** (один MAC «мигает» между портами) — классический признак;
- предупреждения браузера о невалидных сертификатах у пользователей — часто единственный видимый симптом перехвата TLS.

## 4. Эшелонированная защита (за пределами трёх функций)

Три функции из заметки — это только L2. Как специалист добавил бы уровни выше:

- **DHCP Snooping** — обязательная предпосылка для DAI (заметка упоминает DAI, но не говорит, что без trust-портов и binding-таблицы она не заработает);
- **BPDU Guard + Root Guard** — против STP-атак; **DTP off** — против VLAN hopping;
- **802.1X (NAC)** — контроль доступа к порту до аутентификации;
- **RA Guard / ND Inspection** — то же самое для IPv6 (там вместо ARP — NDP, и проблема та же);
- **TLS везде + HSTS + certificate pinning** для критичных приложений — защита, которая работает даже если злоумышленник уже встал «посередине»;
- VPN для чувствительного трафика; запрет Telnet/HTTP-админок внутри сети (SSH/HTTPS).
