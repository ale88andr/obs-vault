## Почему «обычный VPN» больше не работает

С 2025 года Россия перешла от блокировки по IP/домену к анализу трафика через **ТСПУ** (технические средства противодействия угрозам) — это DPI-оборудование на сетях операторов. Отсюда три ключевых следствия:

- **Сигнатурный отпечаток.** DPI ловит не только запрещённые сайты, но и *характеристики* трафика: JA4-отпечаток TLS ClientHello, «TLS-in-TLS», падение размера пакетов на хендшейке. Именно поэтому «фейковый TLS» официального MTProto и OpenVPN/WireGuard легко детектируются.
- **Белые списки.** При «whitelist»-отключениях разрешён только госсегмент (Госуслуги, Wildberries, VK, Яндекс). Всё остальное режется по умолчанию — тут выбор SNI критичен.
- **Блочат подсети целиком.** Августовская волна 2026 била по целым подсетям хостингов — поэтому одного IP/VPS мало, нужна устойчивость.

Ориентир: по данным HRW на февраль 2026 под блокировку попало ≥469 VPN-сервисов, Apple вырезал из App Store Streisand/V2Box/v2RayTun/Happ. РКН одновременно усиливает требования к маркировке.

## Что реально работает в 2026

**1. VLESS + REALITY (+ XTLS Vision) на ядре Xray — дефолтный выбор.**
Это сейчас самый стойкий публичный протокол. Механика: VLESS не шифрует сам, а отдаёт TLS 1.3; REALITY подменяет рукопожатие хендшейком *настоящего* сайта (например `ya.ru`) — для DPI это выглядит как обычный визит. Для зондов ТСПУ сервер проксирует реальный Server Hello, а авторизованным клиентам отдаёт временный сертификат по X25519. Домена и своего сертификата не требует.
- Клиенты: v2rayNG, Hiddify, sing-box, Karing, NekoBox, Shadowrocket (iOS), Clash Verge Rev, v2RayTun.
- **Важно:** SNI выбирай из российского белого списка (`yandex.ru`, `vk.com`, `mail.ru`, `ozon.ru`, `max.ru`) — иначе при whitelist-режиме сервер будет недоступен.
- Endpoint лучше на нестандартном порту (не только 443), и с корректным **fallback** — без него ТСПУ метит узел как прокси.

**2. Свой VPS, а не публичные ключи.** Публичные подписки быстро жгутся. Схема: VPS вне РФ → установка панели (3X-UI, Marzban, Hiddify-Manager) или AmneziaVPN в self-hosted режиме → генерация ключа. Это и дешевле, и живучее.

**3. AmneziaWG.** WireGuard с обфускацией шума в хендшейке — обходит простой DPI, но детектируется на агрессивном. Как второй транспорт «на всякий случай» — норм.

**4. DPI-обход на самом клиенте.** Хорошо работает там, где режется/замедляется по-пакетно (например YouTube-троттлинг):
- **Zapret / GoodbyeDPI / ByeDPI** — фрагментация хендшейка и десинхронизация, бесплатно и локально.
- Сам Telegram подвигал **обфускацию трафика для Premium** (апрель 2026) — но это нестабильно и не для всех платформ.

**5. Tor с мостами.** `obfs4`/`Snowflake`/`meek` — резервный канал, когда всё остальное лежит. Медленно, но живёт.

**6. MTProto-прокси Telegram.** Только как дополнение, не как основной: с июня 2026 официальные MTProto-прокси (включая Fake TLS) давно и плотно режутся по JA4-отпечатку. Форки с динамической ротацией отпечатка (типа telemt/tdlib-obf) работают, но это всегда догоняющая игра.

## Как бы я выстроил стратегию (мультислой)

1. **Основной канал:** VLESS+REALITY+Vision на своём VPS, SNI из бел. списка, 443 + резервный порт.
2. **Резерв:** второй inbound с другими ключами/портом (при смене порта ключ в `vless://` меняется — держи обе ссылки).
3. **Аварийный:** AmneziaWG либо Tor с мостами.
4. **Локально:** Zapret/GoodbyeDPI для замедляемого, но не заблокированного (YouTube).
5. **Мониторинг:** скрипт пингует серверы на двух уровнях — сырой TCP (`nc -zv`) и полный хендшейк реальным клиентом (xray/sing-box + `curl` на заведомо блокируемый ресурс), репорт через приватного бота.
6. **Ротация:** держи 2–3 сервера в разных подсетях/хостерах, чтобы потеря одной подсети не убивала доступ.

Ключевой принцип 2026-го: **стойкость важнее скорости**. Выигрывает не лучший протокол, а тот, кто быстрее перестраивает конфиг после очередной волны.

## Про риски

Тут важно сказать прямо: обход блокировок в РФ теперь несёт юридический риск. С 2026-го РКН/закон ужесточают ответственность, есть **штрафы** для бизнеса и частных лиц, а реклама VPN/популяризация обхода — под запретом. ## 0. Важно про источник установки

- Версию из **Google Play скачивать нельзя** — с мая 2024 её контролирует третья сторона, она не open-source. Только **GitHub Releases** (MatsuriDayo/NekoBoxForAndroid).
- Выбор APK: `arm64-v8a.apk` для большинства устройств, `universal.apk` если не уверен.
- Установи, разрешив «неизвестные источники».

## 1. Импорт профиля

**Из ссылки (основной способ):**
1. Скопируй `vless://...` (или подписку) в буфер.
2. NekoBox → вкладка **Profiles** → «+» справа сверху.
3. **Import from clipboard** (или **Import from Link** для `http(s)://` подписки).
4. Для подписки дождись загрузки — появится группа с нодами.

NekoBox сам распарсит Reality-параметры из ссылки: UUID, `pbk`, `sni`, `sid`, `fp`, flow. Вручную лезть в конфиг обычно не нужно — правка полей руками чаще ломает.

## 2. Проверь Reality-параметры (если вводишь вручную)

Ключевое — совпадение с сервером. Поля профиля:

| Поле в NekoBox | Что там | Пример |
| --- | --- | --- |
| Address | IP/домен сервера | `203.0.113.10` |
| Port | порт inbound | `443` |
| ID / UUID | UUID клиента | `bf000d23-...` |
| Flow | управление TLS | `xtls-rprx-vision` |
| Security | тип безопасности | `reality` |
| Server Name / SNI | домен маскировки | `yandex.ru` |
| Public Key | `pbk` сервера | `XTHbm...` |
| Short ID | `sid` | `1a2b3c` |
| Fingerprint | отпечаток TLS | `chrome` |

Ошибки тут — самая частая причина «нода не подключается». Если нода из ссылки, эти поля уже заполнены.

## 3. Выбор ноды и подключение

1. Вкладка **Proxies** → тапни ноду; долгий тап → **Test latency** (проверить задержку).
2. Вернись на главный экран → кнопка **старта** (иконка питания).
3. Android спросит разрешение на VPN — **OK**.

**Режим прокси** (на главном):
- **Rule Mode** — рекомендуемый: РФ-сайты напрямую, заблокированное через прокси.
- **Global Mode** — всё через прокси (медленнее РФ-ресурсы, но проще).
- **Direct Mode** — без прокси.

## 4. Routing под Россию (важно для скорости и маскировки)

Ключевая настройка, чтобы через прокси шло только нужное, а VK/Яндекс/Госуслуги — напрямую:

**Настройки → Route (Routing) → пресеты.** Возьми базовый «bypass LAN» и добавь правила **direct**:
- `geoip:ru` → direct
- `geosite:category-ru` / `geosite:private` → direct
- `geosite:category-ads-all` → block

И правило в конце: всё остальное (`final`) → **proxy** (твоя Reality-нода). Тогда Telegram/YouTube/заблокированное идут через туннель, а российское — нет. Это заодно не подставляется под «весь трафик в туннель» при белых списках.

## 5. DNS

Настройки → DNS:
- **Remote DNS** (для проксируемого трафика): `https://1.1.1.1/dns-query` или DoH через прокси — чтобы домены не утекали открытым резолвом в РФ.
- **Direct DNS**: `77.88.8.8` (Яндекс) для прямого трафика.
- Опционально включи **Fake DNS** — ускоряет резолв и уменьшает утечки.

Резолвить DNS **через прокси** критично: иначе РКН видит, какие домены ты запрашиваешь, даже без SNI.

## 6. TUN-режим (если часть приложений не проксируется)

Настройки → **TUN Settings** → **Enable TUN** → переподключиться. TUN перехватывает весь трафик на уровне интерфейса — помогает для игр и приложений, которые игнорируют системный прокси на уровне приложения. Требует VPN-разрешения (уже выдано).

## 7. Per-app proxying

Настройки → **Per-app proxy**: включи и отметь приложения, которые должны идти через прокси (Telegram, YouTube), либо наоборот — исключи банковские/гос-приложения, которые через VPN могут не работать.

## Дектоп (NekoRay / «NekoBox for PC»)

## Если не работает

1. **Все ноды timeout** → ссылка/подписка мертва, обнови подписку; проверь интернет.
2. **Reality-нода не поднимается** → сверь SNI, `pbk`, `sid` символ-в-символ с сервером. Попробуй порт 443 + резервный (8443) — порт входит в `vless://`, бери обе ссылки.
3. **Подключается, но сайты не грузятся** → скорее DNS/Rule: проверь, что remote DNS идёт через прокси, а direct-правила не перехватывают цель.
4. **Умер после волны блокировок** → это норма гонки с ТСПУ. Обнови ядро в NekoBox (Settings → Core / Check update), смени ноду/подсеть, включи TUN.
