## 1. Фактические правки (сделал бы сразу)

| Место | Проблема | Как правильно |
|---|---|---|

| стр. 162 | «**IDT** (import directory table)» | IDT — это Interrupt Descriptor Table (таблица прерываний, её разбирает не загрузчик). Каталог импорта — элемент **Data Directory с индексом 1** (`IMAGE_DIRECTORY_ENTRY_IMPORT`), обычно в `.idata`/`.rdata` |

| стр. 42 | стек «фиксированный по размеру» | 1 МБ reserve / 4 КБ commit по умолчанию, растёт по guard-странице; у ядра фиксирован (~12 КБ x86 / ~24 КБ x64) |
| стр. 45 | «стек обнуляют, чтобы не читать мусор» | обнуляются только **свежие** страницы (свойство ОС, а не стека). Переиспользованная память стека не чистится — отсюда «мусор», `/GS`, `RtlSecureZeroMemory` |
| стр. 21 | syscall описан только как «номер сервиса» | плюс `RCX` = RIP возврата, `R11` = RFLAGS, аргументы 1–4 в `RCX/RDX/R8/R9`, 5-й и далее — на стек (+ shadow space). И возврат не всегда `sysret`: при доставке APC/смене потока — `iretq` через `KiServiceExit` |

## 2. Пробелы по самому предмету

- **WoW64 / Heaven’s Gate** — 32-битный процесс на 64-битной ОС: два PEB, `Wow64Transition`, переключение в long mode в обход 32-битных хуков.
- **Пространство имён объектов** — `\Device`, `\BaseNamedObjects`, `\Sessions\<n>\BaseNamedObjects`, `\KnownDlls`, symlinks `\??\`. Без этого непонятны ни named object squatting, ни изоляция сессий.
- **KASLR / SMEP / SMAP / KPTI** — почему эксплойт ядра не может просто прыгнуть в user-память и почему нужен ROP.
- **ALPC** — упомянут одной строкой, а это основная поверхность локального EPE (порты `lsass`, `csrss`, RPC).
- **Реестр** — у тебя есть отдельная заметка [[Компоненты ОС Microsoft Windows]], а в этой нет ни слова про `SAM`/`SECURITY`, IFEO, COM hijacking, `KnownDLLs`.
- **ETW** — без него «как это детектится» упирается в воздух.

## 3. Security-слой — главное, что я бы добавил

Предлагаю раздел `## Security implications` с картой «internals → атака → детект»:

| Тема | Что атакуют | Как выглядит | Где смотреть |
|---|---|---|---|
| SSDT / syscall | номер syscall нестабилен между билдами | direct syscalls: `Hell's Gate`, `Halo's Gate`, `FreshyCalls`, `SysWhispers` | `syscall` вне `ntdll`, return address не в `ntdll`, ETW-TI, integrity ntdll |
| IAT | указатели импорта | IAT hook, перезапись `FirstThunk` | сравнение IAT с экспортами образа на диске |
| Section objects | `SEC_IMAGE` + `NtMapViewOfSection` | инъекция/маппинг без `LoadLibrary` → нет в `PEB->Ldr` | ETW ImageLoad, VAD с `MEM_IMAGE` без файла |
| VAD / память | `MEM_PRIVATE` + `PAGE_EXECUTE_READWRITE` | shellcode, pagefile-backed секции | `!vad`, malfind, RWX-регионы |
| Хэндлы | `PROCESS_ALL_ACCESS` к чужому процессу | `DuplicateHandle`, кража токена | `ObRegisterCallbacks` (так работает EDR), Sysmon 10 |
| Токены | `SeImpersonate` / `SeDebug` | Potato-семейство, Mimikatz | 4672, аномальные привилегии у процесса |
| Драйверы | `SeLoadDriverPrivilege` | BYOVD, убийство EDR | Sysmon 6, 7045, WDAC-блоклист |
| Сессии/десктопы | `WinSta0`, UIPI | обход lock screen, `SwitchDesktop`, клипборд | кросс-сессионные открытия хэндлов |

Что конкретно стоит раскрыть в этом разделе:

**3.1 Syscall-уровень.** Ключевая мысль: `ntdll` — это не «часть ОС», а обычная DLL, которую можно переписать. Отсюда — хук EDR на стабах `Nt*`, отсюда direct/indirect syscalls, отсюда же detection: сравнение `ntdll` в памяти с диском, проверка, что инструкция `syscall` лежит в диапазоне `ntdll`, анализ call stack (спуфинг возвратных адресов — отдельная тема).

**3.2 PE и загрузчик.** Добавить «что смотреть в PE»: `DllCharacteristics` (`DYNAMIC_BASE 0x40`, `NX_COMPAT 0x100`, `GUARD_CF 0x4000`), таблица сертификатов (data directory #4, Authenticode), `.reloc`, TLS-callbacks (выполняются **до** entry point — анти-дебаг), delay-load импорты, ординалы, энтропия секций, Rich header. И атаки: DLL sideloading/search order, phantom DLL hollowing, module stomping, `AppInit_DLLs`.

**3.3 Секции и VAD.** Два практических вывода: (а) pagefile-backed секция — память без файла на диске, удобно для полезной нагрузки; (б) `MEM_PRIVATE` + executable = главный признак инжекта при форензике. Плюс PTE-манипуляции в ядре (скрытые страницы).

**3.4 Объекты и хэндлы.** В заметке есть object manager, но нет главного для защиты: `ObRegisterCallbacks` (EDR снимает `PROCESS_VM_READ`/`PROCESS_CREATE_THREAD` при открытии `lsass`), дублирование хэндлов между процессами, squatting именованных объектов, ACL на каталоги объектов.

**3.5 Дескрипторы безопасности — тут не хватает самого алгоритма.** Добавить: deny-ACE проверяются **раньше** allow; **NULL DACL** = полный доступ всем, **пустой DACL** = отказ всем; `SeAccessCheck`; privileges проверяются отдельно (`SeBackup`, `SeRestore`, `SeTakeOwnership`, `SeDebug`); уровни целостности через mandatory label в SACL (Low 0x1000 / Medium 0x2000 / High 0x3000 / System 0x4000), no-write-up; для чтения/записи SACL нужно `SeSecurityPrivilege` + включённый `auditpol`.

**3.6 Защиты ядра.** Отдельный абзац: DSE, PatchGuard (что именно проверяет), HVCI/VBS, Credential Guard, LSASS как PPL (`RunAsPPL`), Secure Boot, WDAC. И почему EDR ушёл от SSDT-хуков к `PsSetCreateProcessNotifyRoutineEx`, `PsSetLoadImageNotifyRoutine`, `ObRegisterCallbacks`, minifilters, ETW.

**3.7 Митигации процесса.** ASLR/DEP/CFG/CET (Hardware-enforced Stack Protection), ACG, CIG, `SetProcessMitigationPolicy`, `MitigationOptions` в реестре — и как их снимают/проверяют.

**3.8 Телеметрия.** Таблица «внутренности → событие»: процесс → 4688 + Sysmon 1; загрузка образа → Sysmon 7 (поле `Signed`); `CreateRemoteThread` → Sysmon 8 + 10; драйвер → Sysmon 6 + 7045; пайп → 17/18; DNS → 22; реестр → 12/13/14; доступ к объекту → 4656/4663 (нужен SACL).
