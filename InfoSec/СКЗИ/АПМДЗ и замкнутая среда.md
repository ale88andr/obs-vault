
Компоненты, обеспечивающие класс защиты **КС2** и выше. Без них невозможно обеспечить защиту от нарушителя, имеющего доступ к контролируемой зоне.

## АПМДЗ — Аппаратно-программный модуль доверенной загрузки

### Что это

АПМДЗ — это аппаратный модуль, который **контролирует целостность** загружаемого программного обеспечения СКЗИ и операционной системы. Он обеспечивает **доверенную загрузку** — процесс, при котором проверяется, что ПО не было модифицировано или заменено на вредоносное.

### Зачем нужен

Без АПМДЗ злоумышленник, имеющий физический доступ к серверу (класс КС3) или доступ к локальной сети (класс КС2), может:
- Подменить загрузчик ОС
- Установить вредоносное ПО, имитирующее легитимное СКЗИ
- Перехватить ключевую информацию на этапе загрузки
- Внедрить закладку на уровне BIOS/UEFI

АПМДЗ **исключает эти угрозы**, обеспечивая цепочку доверия от аппаратуры до прикладного ПО.

### Как работает

```
┌─────────────────────────────────────────┐
│  Включение сервера                      │
│         ↓                               │
│  АПМДЗ проверяет.signature ключ         │
│  производителя (Root of Trust)          │
│         ↓                               │
│  Проверка целостности загрузчика ОС     │
│         ↓                               │
│  Проверка целостности ядра ОС           │
│         ↓                               │
│  Проверка целостности модулей СКЗИ      │
│         ↓                               │
│  Доверенная загрузка завершена           │
│  Прикладные СКЗИ запускаются            │
└─────────────────────────────────────────┘
```

### Типы АПМДЗ

| Тип | Описание | Примеры |
| --- | --- | --- |
| **Внешний модуль** | Подключается к серверу через отдельный интерфейс (USB, TPM-слот) | С-Терра АМЗ, накопители ключей с функцией АПМДЗ |
| **Встроенный модуль** | Реализован в составе аппаратно-программного комплекса СКЗИ | ViPNet Coordinator HW (встроенный АПМДЗ) |
| **Интегрированный в ОС** | Функции АПМДЗ реализованы средствами операционной системы | Astra Linux SE (доверенная загрузка на уровне ОС) |

### Требования к АПМДЗ

- Сертифицирован ФСБ России как средство криптографической защиты информации
- Обеспечивает **хэширование** загружаемых компонентов с использованием ГОСТ Р 34.11-2012
- Поддерживает **аппаратное хранение ключей** шифрования
- Работает на уровне **до загрузки ОС** (до POST-процедур или в их рамках)

## Замкнутая программная среда

### Что это

Замкнутая (изолированная) программная среда — это **ограниченная конфигурация операционной системы**, в которой:
- Установлены **только** необходимые для работы СКЗИ компоненты
- Запрещена установка стороннего ПО
- Ограничен доступ к аппаратуре (USB, сеть, периферия)
- Все изменения фиксируются и контролируются

### Зачем нужна

Замкнутая среда нужна для класса **КС3**, когда нарушитель имеет физическое доступ к оборудованию. Она исключает:
- Установку вредоносного ПО через USB-накопители
- Подключение несанкционированных устройств
- модификацию системных файлов
- Запуск непредусмотренных процессов

### Реализация замкнутой среды

| Решение | Описание |
| --- | --- |
| **Astra Linux SE (Специальное издание)** | ОС с гарантированным уровнем доверия. Режим максимального уровня доверия блокирует все несанкционированные действия. Поддержка МКЦ (мандатного контроля доступа). |
| **Режим ограничения запуска** | В настройках ОС запрещается запуск любых приложений, кроме белого списка (СКЗИ и системные компоненты) |
| **Белый список приложений** | Список разрешённых исполняемых файлов, хэши которых контролируются АПМДЗ |
| **Ограничение аппаратных интерфейсов** | Отключение USB, Bluetooth, Wi-Fi, последовательных портов — всё кроме необходимого |

### Связь АПМДЗ и замкнутой среды

```
АПМДЗ (контроль загрузки)
    ↓
Замкнутая среда (контроль выполнения)
    ↓
СКЗИ (криптографическая защита)
```

- **АПМДЗ** обеспечивает доверие на этапе **загрузки**
- **Замкнутая среда** обеспечивает доверие на этапе **работы**
- Вместе они формируют **непрерывную цепочку доверия** от аппаратуры до прикладных сервисов

## Класс КВ и КА — eyond замкнутой среды

### Класс КВ

Применяется, когда нарушитель способен:
- Анализировать **побочные электромагнитные излучения и наводки** (ПЭМИН)
- Использовать **недокументированные возможности ПО** ОС и приложений
- Привлекать специалистов с опытом анализа СКЗИ

**Меры защиты:**
- Экранирование аппаратуры (клетка Фарадея)
- Специальные экраны от ПЭМИН
- Контроль радиоэлектронных излучений
- Регулярный аудит недокументированных возможностей

### Класс КА

Максимальный уровень. Применяется при угрозе привлечения специалистов, владеющих:
- Недокументированными возможностями **аппаратных компонентов** СКЗИ
- Методами **физического анализа** микросхем
- Техниками **side-channel attacks** на аппаратном уровне

**Меры защиты:**
- Специализированные аппаратные СКЗИ с защитой от физического анализа
- Развитые средства контроля среды функционирования
- Строгий физический контроль помещений

## Практические примеры внедрения

### КС2: Корпоративная сеть

- **СКЗИ:** ViPNet Coordinator HW (программно-аппаратный комплекс)
- **АПМДЗ:** Встроен в ViPNet Coordinator
- **ОС:** Astra Linux SE (базовый уровень доверия)
- **Помещение:** Контролируемая зона (пропускной режим, вахтёр)

### КС3: ГИС государственного органа

- **СКЗИ:** ViPNet Coordinator HW + АПМДЗ (внешний модуль)
- **ОС:** Astra Linux SE (режим максимального уровня доверия)
- **Замкнутая среда:** Белый список приложений, отключение USB
- **Помещение:** Спецпомещение с охранной сигнализацией, решётками на окнах
