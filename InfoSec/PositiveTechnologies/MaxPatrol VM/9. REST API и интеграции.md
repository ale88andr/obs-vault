## 9.1 REST API

### Обзор API

> [!note] Зачем нужен API
> REST API позволяет программно управлять MaxPatrol VM: выполнять PDQL-запросы, управлять задачами, получать данные для внешних систем, автоматизировать рутинные операции.

### Аутентификация

#### Способ 1: Токен через PT Management Console (основной)

> [!tip] Рекомендация: используйте этот способ
> Документация 2.8 описывает именно его: персональный токен формата `reference` создаётся в сервисе управления пользователями и доступом Positive Technologies Management and Configuration (PT MC) — детали на странице [[Управление токенами доступа]].

**Процесс:**
1. В главном меню MaxPatrol VM перейдите в приложение **Positive Technologies Management and Configuration**
2. В главном меню PT MC выберите значок с логином → **«Токены доступа»**
3. Нажмите **«Создать»**
4. Укажите название токена и приложение
5. Нажмите **«Создать»**

> [!warning] Ограничения из документации
> - Можно создать **не более 100 токенов**
> - Скопируйте и сохраните токен сразу: после перехода на другую страницу скопировать созданный токен будет невозможно — потребуется создавать новый
> - Токен можно изменить и удалить на странице «Токены доступа»

#### Способ 2: Токен через пароль и ClientSecret (НЕ описан в документации 2.8)

> [!note] Откуда этот способ
> Описывается в сообществе (в т.ч. в статьях А. Левонова, см. «Ресурсы»). В локальной документации 2.8 нет ни `grant_type=password`, ни `client_secret`, ни `connect/token` — единственный описанный способ получить токен доступа — интерфейс PT MC выше. Используйте на свой риск и проверяйте по актуальной документации.

**Получение токена:**

```
POST https://<MP-VM>:3334/connect/token
Content-Type: application/x-www-form-urlencoded

grant_type=password
&username=<логин>
&password=<пароль>
&client_id=mpx
&client_secret=<ClientSecret>
&scope=authorization offline_access mpx.api
```

> [!warning] Порты
> Документация 2.8 говорит про «Корневой URL API» без указания порта. Явный порт **3334** встречается в примерах действий пользователей (`https://<Корневой URL API>:3334/ptms/api/ual/...`) и это же порт веб-интерфейса PT MC. Формулировка «токен берётся по 3334, данные — по 443» в документации 2.8 не подтверждается.

**Где найти ClientSecret:**
- Файл: `/var/lib/deployer/role_instances/Core/params.yaml`
- Параметр: `ClientSecret`

**Ответ:**

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "..."
}
```

**Использование токена:**

```
Authorization: Bearer eyJhbGciOiJSUzI1NiIs...
```

### Работа с PDQL через API

**Шаг 1 — Получение токена PDQL-запроса:**

```
POST https://<Корневой URL API>/api/assets_temporal_readmodel/v1/assets_grid
Authorization: Bearer <токен доступа>
Content-Type: application/json

{
  "pdql": "Filter(Host[@Vulners.SeverityRating = 'Critical']) | Select(@Host, Host.Fqdn, Host.IpAddress, Host.@Vulners.CVEs) | Limit(100)",
  "includeNestedGroups": true
}
```

> [!important] Параметры и срок жизни токена
> Обязательные параметры тела: `pdql` и `includeNestedGroups`. Опциональные: `previousToken`, `utcOffset`, `additionalFilterParameters`, `selectedGroupIds`, `executionTime`, `groupIds`, `assetIds`. **Время действия токена — 30 минут.** Коды ошибок: 400 (синтаксическая ошибка PDQL), 500, 503. Источник: [[Получение токена PDQL-запросов]].

> [!warning] Синтаксис PDQL в API = синтаксис PDQL во вкладке «Активы»
> Через REST API передаётся **тот же PDQL**, что и в интерфейсе, — из документа «Синтаксис языка запросов PDQL». Это не диалект конструктора виджетов: операторы `==`, `qsearch()` и синтаксис вида `days(-30)` здесь не работают. Полный справочник — [[PDQL — синтаксис по документации PT]], основы — [[4. Язык PDQL]].

**Ответ:**

```json
{
  "token": "abc123...",
  "isPotentiallySlow": false,
  "hasTimepointPipe": false,
  "hasTimeseriesPipe": false,
  "fields": [
    { "name": "@Host", "localizedName": "Хост", "type": "string", "isArray": false }
  ]
}
```

**Шаг 2 — Выгрузка результатов (задокументированный способ):**

```
GET https://<Корневой URL API>/api/assets_temporal_readmodel/v1/assets_grid/export?pdqlToken=abc123...
Authorization: Bearer <токен доступа>
```

В ответ приходят данные таблицы активов в CSV (коды ошибок: 400, 403, 404, 500). Источник: [[Экспорт таблицы активов в CSV]].

> [!warning] Постраничная JSON-выборка не документирована
> Эндпоинт вида `/api/assets_grid/data?...&offset=&limit=` в локальной документации 2.8 **отсутствует** — описана только CSV-выгрузка через `/export`. Если нужен именно JSON с пагинацией, смотрите запросы веб-интерфейса в DevTools и сверяйте их с актуальной документацией. Утверждение «по умолчанию API возвращает до 50 000 записей» документацией 2.8 тоже не подтверждается; ограничение выборки задаётся операцией `Limit(<Количество записей>)` в самом PDQL.

### Советы по отладке

> [!tip] Самый простой способ
> Отлаживать PDQL-запросы удобнее в web-интерфейсе, а затем смотреть, какие запросы шлёт браузер — используется тот же API.

1. Откройте DevTools браузера (F12)
2. Перейдите во вкладку **Network**
3. Выполните PDQL-запрос в интерфейсе
4. Найдите запрос к `/api/assets_temporal_readmodel/v1/assets_grid` в сети
5. Скопируйте тело запроса и заголовки

## 9.2 Автоматизация на основе API

### CLI-утилиты

#### Positive CLI (positive_cli)

> [!note] CLI для MaxPatrol API
> Интерфейс командной строки для работы с MaxPatrol API. Позволяет выполнять PDQL-запросы, управлять задачами, получать данные из командной строки.

**Установка и подключение:**

```bash
# Подключение через сессию
mp api connect --session --host=<IP> --login=<user> --password=<pass>

# Подключение через токен
mp api connect --host=<IP> --token=<token>
```

**Примеры команд:**

```bash
# PDQL-запрос
mp pdql "Filter(Host[@Vulners]) | Select(@Host, Host.Fqdn)"

# Список задач сканирования
mp scanner tasks list

# Список групп
mp groups list
```

**Хранение данных:**
- Локальная база данных TinyDB (зашифрованный JSON)
- Расположение: `~/.pt_cli.encrypted`
- Поддержка профилей подключения

### Сценарии автоматизации

#### Сценарий 1: Автоматический экспорт уязвимостей

```python
import requests
import csv
import io

# Конфигурация
MP_HOST = "mpvm.example.com"
MP_PORT_TOKEN = 3334
MP_PORT_API = 443
LOGIN = "api_user"
PASSWORD = "secret"
CLIENT_SECRET = "your_client_secret"

# Получение токена (способ 2 — НЕ описан в документации 2.8)
def get_token():
    url = f"https://{MP_HOST}:{MP_PORT_TOKEN}/connect/token"
    data = {
        "grant_type": "password",
        "username": LOGIN,
        "password": PASSWORD,
        "client_id": "mpx",
        "client_secret": CLIENT_SECRET,
        "scope": "authorization offline_access mpx.api"
    }
    response = requests.post(url, data=data)
    return response.json()["access_token"]

# Получение токена PDQL-запроса — документированный запрос
def get_pdql_token(token, query):
    url = f"https://{MP_HOST}:{MP_PORT_API}/api/assets_temporal_readmodel/v1/assets_grid"
    headers = {"Authorization": f"Bearer {token}"}
    data = {"pdql": query, "includeNestedGroups": True}
    response = requests.post(url, headers=headers, json=data)
    return response.json()["token"]  # поле называется token, живёт 30 минут

# Выгрузка результатов в CSV — документированный запрос
def get_results(token, pdql_token):
    url = f"https://{MP_HOST}:{MP_PORT_API}/api/assets_temporal_readmodel/v1/assets_grid/export"
    headers = {"Authorization": f"Bearer {token}"}
    params = {"pdqlToken": pdql_token}
    response = requests.get(url, headers=headers, params=params)
    return response.text  # CSV

# Удобная обёртка: PDQL -> список строк
def query_rows(token, query):
    pdql_token = get_pdql_token(token, query)
    return list(csv.DictReader(io.StringIO(get_results(token, pdql_token))))

# Основной поток
token = get_token()
rows = query_rows(token,
    'Filter(Host[@Vulners.CVSS3Score >= 9]) '
    '| Select(@Host, Host.Fqdn, Host.IpAddress, Host.@Vulners.CVEs, Host.@Vulners.CVSS3Score) '
    '| Sort(Host.@Vulners.CVSS3Score DESC)'
)

# Экспорт в CSV
with open("critical_vulns.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=rows[0].keys())
    writer.writeheader()
    writer.writerows(rows)
```

#### Сценарий 3: CI/CD для контроля защищённости

```yaml
# Пример GitLab CI/CD pipeline
stages:
  - build
  - security-scan
  - deploy

security-scan:
  stage: security-scan
  script:
    - python scripts/check_vulnerabilities.py
    - |
      # Список развёртываемых хостов — либо из CI-переменной, либо из конфига
      DEPLOY_TARGETS="web01.corp.local web02.corp.local db01.corp.local"

      # Собираем список значений для оператора in: 'web01.corp.local','web02.corp.local',...
      FQDN_LIST=$(printf "'%s'," $DEPLOY_TARGETS | sed 's/,$//')

      # PDQL-запрос: критичные уязвимости на развёртываемых серверах.
      # Limit(1) — проверяем только факт наличия
      PDQL="Filter(Host[@Vulners.CVSS3Score >= 9] and Host.Fqdn in [$FQDN_LIST]) | Select(@Host, Host.Fqdn) | Limit(1)"

      # Тело запроса: обязательные параметры pdql и includeNestedGroups
      printf '{"pdql": %s, "includeNestedGroups": true}' "$(printf '%s' "$PDQL" | python -c 'import json,sys; print(json.dumps(sys.stdin.read()))')" > request.json

      # Шаг 1: получение PDQL-токена (документированный запрос, токен живёт 30 минут)
      RESP=$(curl -s -H "Authorization: Bearer $TOKEN" \
        -H "Content-Type: application/json" \
        -X POST https://mpvm/api/assets_temporal_readmodel/v1/assets_grid \
        --data @request.json)

      PDQL_TOKEN=$(printf '%s' "$RESP" | python -c 'import json,sys; print(json.load(sys.stdin).get("token",""))')

      # Шаг 2: выгрузка результата в CSV (документированный запрос)
      RESULT=$(curl -s -H "Authorization: Bearer $TOKEN" \
        "https://mpvm/api/assets_temporal_readmodel/v1/assets_grid/export?pdqlToken=$PDQL_TOKEN")

      # Больше одной строки (первая — заголовок CSV) = есть найденные уязвимости
      ROWS=$(printf '%s' "$RESULT" | grep -cv '^[[:space:]]*$')
      if [ "$ROWS" -gt 1 ]; then
        echo "CRITICAL VULNERABILITIES FOUND - DEPLOYMENT BLOCKED"
        echo "$RESULT"
        exit 1
      fi
  only:
    - main
```

> [!warning] Сборка PDQL в скриптах
> Строковые литералы PDQL заключаются в кавычки, поэтому вложить запрос прямо в `-d '{...}'` неудобно и легко сломать экранирование. Надёжнее: собрать текст запроса в переменную, сериализовать его как JSON (например, `json.dumps` в Python) и передать через `--data @file.json`.

> [!note] Проверка формата CSV
> Локальная документация 2.8 описывает запрос `/export`, но не описывает, выглядит ли пустой ответ как одна строка-заголовок или как пустая строка. Условие `ROWS > 1` нужно проверить на своём стенде.

#### Сценарий 4: Синхронизация с Active Directory

```python
import ldap3
import requests

def sync_ad_with_vm(mp_host, mp_token, ad_server, ad_user, ad_pass):
    """Синхронизация компьютеров из AD с активами MaxPatrol VM"""
    
    # Подключение к AD
    server = ldap3.Server(ad_server)
    conn = ldap3.Connection(server, ad_user, ad_pass)
    conn.bind()
    
    # Поиск компьютеров в AD
    conn.search(
        search_base='DC=example,DC=com',
        search_filter='(objectClass=computer)',
        attributes=['cn', 'dNSHostName', 'operatingSystem']
    )
    
    ad_computers = {entry['dNSHostName'].value: entry for entry in conn.entries}
    
    # Получение активов из MaxPatrol VM
    token = get_token()
    rows = query_rows(token, 'Select(@Host, Host.Fqdn, Host.OsName)')
    vm_hosts = {h['Host.Fqdn']: h for h in rows}
    
    # Выявление расхождений
    only_in_ad = set(ad_computers.keys()) - set(vm_hosts.keys())
    only_in_vm = set(vm_hosts.keys()) - set(ad_computers.keys())
    
    return {
        "only_in_ad": only_in_ad,
        "only_in_vm": only_in_vm,
        "common": set(ad_computers.keys()) & set(vm_hosts.keys())
    }
```

#### Сценарий 5: Автоматические отчёты по email

```python
import smtplib
from email.mime.multipart import MIMEMultipart
from email.mime.text import MIMEText
from email.mime.base import MIMEBase
from email import encoders

def send_weekly_report(mp_token, smtp_config):
    """Еженедельный отчёт по критичным уязвимостям"""
    
    # Получение данных
    token = get_token()
    data = query_rows(token,
        "Filter(Host.@Importance in ['H'] and Host[@Vulners.CVSS3Score >= 9]) "
        '| Select(@Host, Host.Fqdn, Host.IpAddress, Host.@Vulners.CVSS3Score as CVSS, Host.@Vulners.CVEs as CVE) '
        '| Sort(Host.@Vulners.CVSS3Score DESC)'
    )
    
    # Формирование HTML-отчёта
    html = "<h1>Еженедельный отчёт: Критичные уязвимости</h1>"
    html += "<table border='1'><tr><th>Хост</th><th>IP</th><th>CVSS</th><th>CVE</th></tr>"
    for row in data:
        html += f"<tr><td>{row['Host.Fqdn']}</td>"
        html += f"<td>{row['Host.IpAddress']}</td>"
        html += f"<td>{row['CVSS']}</td>"
        html += f"<td>{row['CVE']}</td></tr>"
    html += "</table>"
    
    # Отправка
    msg = MIMEMultipart()
    msg['Subject'] = f"VM Report: {len(data)} critical vulnerabilities"
    msg['From'] = smtp_config['from']
    msg['To'] = smtp_config['to']
    msg.attach(MIMEText(html, 'html'))
    
    with smtplib.SMTP(smtp_config['host'], smtp_config['port']) as server:
        server.starttls()
        server.login(smtp_config['login'], smtp_config['password'])
        server.send_message(msg)
```

```bash
# Синхронизация с AD и удаление устаревших — по понедельникам в 06:00
00 06 * * 1 root flock -n /var/lock/ptvm.lock docker run --rm \
  --network host -v /app/ptvm:/app ptvm run_all.py --only clean_assets

# Отчёт по аутентификации — по понедельникам в 07:00
00 07 * * 1 root flock -n /var/lock/ptvm.lock docker run --rm \
  --network host -v /app/ptvm:/app ptvm run_all.py --only export_failed_auth

# Еженедельный отчёт по критичным — по пятницам в 17:00
00 17 * * 5 root flock -n /var/lock/ptvm.lock docker run --rm \
  --network host -v /app/ptvm:/app ptvm run_all.py --only weekly_report
```
