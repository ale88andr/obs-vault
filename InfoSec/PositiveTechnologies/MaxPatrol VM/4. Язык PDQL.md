# Этап 4 — Язык PDQL

> [!todo] Приоритет: ВЫСОКИЙ (.core skill)
> PDQL — это язык запросов MaxPatrol VM. Без него невозможно эффективно работать с активами и уязвимостями.

---

## 4.1 Основы синтаксиса

### Что такое PDQL

**PDQL** (Positive Data Query Language) — собственный язык запросов MaxPatrol VM, разработанный Positive Technologies для фильтрации, группировки и анализа активов и уязвимостей.

> [!note] Аналогия
> Если SQL работает с реляционными таблицами, PDQL работает с объектной моделью активов MaxPatrol VM. Синтаксис похож на SQL, но использует концепцию алиасов и pipeline-обработки.

### Структура запроса

Базовый шаблон PDQL-запроса:

```
qsearch("текст") | select(алиасы, поля) | filter(условия) | group(алиас, агрегация) | sort(поле) | limit(N)
```

Каждая часть — это.stage pipeline. Данные проходят через каждый.stage последовательно.

### Pipeline — конвейер обработки

```mermaid

    A[qsearch<br/>Полнотекстовый поиск] --> B[select<br/>Выборка полей]
    B --> C[filter<br/>Фильтрация]

    D --> E[sort<br/>Сортировка]
    E --> F[limit<br/>Ограничение]

    style A fill:#e3f2fd,stroke:#1976d2
    style B fill:#e8f5e9,stroke:#388e3c
    style C fill:#fff3e0,stroke:#f57c00
    style D fill:#f3e5f5,stroke:#7b1fa2
    style E fill:#fce4ec,stroke:#c62828

```

| Этап | Оператор | Назначение | Обязателен? |
| --- | --- | --- | --- |
| 0 | `qsearch()` | Полнотекстовый поиск по всем полям | Нет |
| 1 | `select()` | Выбор алиасов и полей для вывода | Да |
| 2 | `filter()` | Условия фильтрации | Нет |
| 3 | `group()` | Группировка и агрегация | Нет |
| 4 | `sort()` | Сортировка результатов | Нет |
| 5 | `limit()` | Ограничение количества записей | Нет |

### Алиасы — основные сущности

> [!important] Алиасы — это типы объектов
> Алиас в PDQL — это аналог класса в ООП. Каждый актив в MaxPatrol VM принадлежит к определённому типу (классу), который представляется алиасом.

| Алиас | Описание | Пример использования |
| --- | --- | --- |
| `@Host` | Базовый класс для всех хостов | `select(@Host)` — все хосты |
| `@WindowsHost` | Windows-системы | `select(@WindowsHost)` — только Windows |
| `@UnixHost` | Linux/Unix-системы | `select(@UnixHost)` — только Linux |
| `@NetworkDeviceHost` | Сетевое оборудование | `select(@NetworkDeviceHost)` — коммутаторы, маршрутизаторы |
| `@ActiveDirectory` | Объекты Active Directory | `select(@ActiveDirectory)` — компьютеры/пользователи из AD |
| `@Vulners` | Уязвимости (все уровни) | `select(@Vulners)` — все уязвимости |
| `@NodeVulners` | Уязвимости конкретного узла (ПО/сервиса) | `select(@NodeVulners)` — уязвимости на уровне ПО |
| `@VulnerPassport` | Паспорта уязвимостей (описания CVE) | `select(@VulnerPassport)` — информация об уязвимостях |
| `@Softs` | Установленное ПО | `select(@Softs)` — все программы |

### Псевдонимы столбцов (AS)

```sql
select(@Host, Host.IpAddress as IP, Host.Fqdn as Имя)
```

Псевдонимы позволяют:
- Переименовывать столбцы для удобства
- Использовать короткие имена в `filter()` и `sort()`

## 4.2 Типичные запросы

### Поиск активов по типу

#### Windows рабочие станции

```sql
select(@WindowsHost, Host.IpAddress, Host.Fqdn, WindowsHost.HostType)
| filter(WindowsHost.HostType = 'Desktop')
```

#### Windows серверы

```sql
select(@WindowsHost, Host.IpAddress, Host.Fqdn)
| filter(WindowsHost.HostType = 'Server')
```

#### Cisco сетевое оборудование

```sql
select(@NetworkDeviceHost, Host.IpAddress, NetworkDeviceHost.Vendor, NetworkDeviceHost.Model)
| filter(NetworkDeviceHost.Vendor = 'Cisco')
```

#### Linux/Unix-системы

```sql
select(@UnixHost, Host.IpAddress, Host.Fqdn, UnixHost.OsName, UnixHost.OsVersion)
| filter(UnixHost.OsName = 'Ubuntu' or UnixHost.OsName = 'Debian')
```

### Поиск по сетевым сегментам

#### Подсеть в CIDR-нотации

```sql
select(@Host, Host.IpAddress, Host.Fqdn)
| filter(Host.IpAddress in 192.168.2.0/24)
```

#### Диапазон IP-адресов

```sql
select(@Host, Host.IpAddress, Host.Fqdn)
| filter(Host.IpAddress >= '10.0.0.1' and Host.IpAddress <= '10.0.0.254')
```

### Поиск по значимости

#### Активы без заданной значимости

```sql
select(@Host, Host.@Importance)
| filter(Host.@Importance = 'ND')
```

#### Критичные активы

```sql
select(@Host, Host.@Importance, Host.IpAddress)
| filter(Host.@Importance = 'H')
```

### Поиск ПО

#### Конкретный продукт

```sql
select(@Host, Host.Fqdn, Host.Softs.Name, Host.Softs.Version)
| filter(Host.Softs.Name = 'Adobe Reader')
```

#### ПО конкретного вендора

```sql
select(@Host, Host.Fqdn, Host.Softs.Vendor, Host.Softs.Name, Host.Softs.Version)
| filter(Host.Softs.Vendor = 'Adobe')
```

#### Версии Microsoft Office

```sql
select(@Host, Host.Fqdn, Host.Softs.Name, Host.Softs.Version)
| filter(Host.Softs.Name contains 'Microsoft Office')
```

### Поиск уязвимостей

#### Все уязвимости на активах

```sql
select(@Host, Host.@Vulners)
| filter(Host.@Vulners)
| limit(0)
```

> [!tip] `limit(0)`
> Значение `0` означает «без ограничений». По умолчанию MaxPatrol VM ограничивает вывод.

#### Уязвимости операционной системы

```sql
select(@Host, Host.OsName, Host.OsVersion, Host.@NodeVulners)
| filter(Host.@NodeVulners)
```

#### Уязвимости ПО

```sql
select(@Host, Host.Softs.Name, Host.Softs.Version, Host.Softs.@NodeVulners)
| filter(Host.Softs.@NodeVulners)
```

#### Уязвимости Linux-пакетов

```sql
select(@UnixHost, UnixHost.Packages.Name, UnixHost.Packages.Version, UnixHost.Packages.@NodeVulners)
| filter(UnixHost.Packages.@NodeVulners)
```

#### Уязвимости сетевых служб

```sql
select(@Host, Host.Endpoints.Port, Host.Endpoints.@Vulners)
| filter(Host.Endpoints.@Vulners)
```

### Поиск по паспортам уязвимостей (CVE)

#### Конкретная уязвимость

```sql
select(@VulnerPassport, VulnerPassport.CVEs, VulnerPassport.Name, VulnerPassport.Score)
| filter(VulnerPassport.CVEs = 'CVE-2021-40444')
```

#### Уязвимости с высоким CVSS

```sql
select(@VulnerPassport, VulnerPassport.CVEs, VulnerPassport.Name, VulnerPassport.Score)
| filter(VulnerPassport.Score >= 9)
```

### Поиск учётных записей (подобранных при сканировании)

```sql
select(@Host as Host, Host.Endpoints.Port as Port, Host.Endpoints.Service.Checks.Login as Login, Host.Endpoints.Service.Checks.Password as Password)
| filter(Login and Password)
| sort(Host DESC)
```

### Полнотекстовый поиск (qsearch)

#### Поиск по названию/описанию/IP/FQDN

```sql
qsearch("srv1") | select(@Host)
```

#### Поиск по IP-адресу

```sql
qsearch("192.168.1.50") | select(@Host)
```

> [!note] QSearch — до SELECT
> `qsearch()` выполняется **до** `select()` и ищет по всем текстовым полям активов. Это быстрый способ найти конкретный хост без знания точной структуры данных.

## 4.3 Продвинутые запросы

### Группировка и агрегация

#### Подсчёт активов по ОС

```sql
select(@Host, Host.OsName)
| group(Host.OsName, COUNT(*) as Count)
| sort(Count DESC)
```

#### Подсчёт уязвимостей по CVSS

```sql
select(@VulnerPassport, VulnerPassport.Score)
| group(VulnerPassport.Score, COUNT(*) as Count)
| sort(VulnerPassport.Score DESC)
```

#### Активы с 2+ сетевыми интерфейсами

```sql
select(@Host, Host.Interfaces.Name as name, Host.Interfaces.IsEnabled as enabled)
| filter(name != "lo" and name != "Npcap Loopback Adapter" and name and enabled = true)
| group(@Host, COUNT(*) as result)
| filter(result >= 2)
```

### Динамические группы на основе PDQL

> [!tip] Динамические группы
> PDQL-запрос можно использовать как основу для динамической группы. Группа автоматически обновляется при изменении данных.

**Примеры PDQL для динамических групп:**

| Группа | PDQL-запрос |
| --- | --- |
| Критичные серверы | `@WindowsHost and WindowsHost.HostType = 'Server' and Host.@Importance = 'H'` |
| Устаревшие Windows | `@WindowsHost and Host.OsVersion contains '7' or Host.OsVersion contains '2008'` |
| Серверы без аудита | `@Host and not Host.@LastAuditTime` |
| Ubuntu-серверы | `@UnixHost and UnixHost.OsName = 'Ubuntu'` |
| Сетевое оборудование Cisco | `@NetworkDeviceHost and NetworkDeviceHost.Vendor = 'Cisco'` |
| Активы с критичными уязвимостями | `@Host and Host.@Vulners[@Vulners.Severity = 'Critical']` |

### Сравнение данных во времени

#### Активы, не сканировавшиеся более 30 дней

```sql
select(@Host, Host.@LastAuditTime, Host.Fqdn)
| filter(Host.@LastAuditTime < days(-30))
```

#### Новые активы за последние 7 дней

```sql
select(@Host, Host.@CreationTime, Host.Fqdn, Host.IpAddress)
| filter(Host.@CreationTime > days(-7))
```

### Объединение условий (AND/OR/NOT)

```sql
select(@Host, Host.Fqdn, Host.IpAddress)
| filter(
    (Host.OsName = 'Windows Server 2019' or Host.OsName = 'Windows Server 2022')
    and Host.@Importance = 'H'
    and Host.@Vulners
)
```

### Комбинированные запросы (практические примеры)

#### Топ-10 активов по количеству уязвимостей

```sql
select(@Host, Host.Fqdn, Host.IpAddress, Host.@Vulners)
| filter(Host.@Vulners)
| group(@Host, COUNT(Host.@Vulners) as VulnCount)
| sort(VulnCount DESC)
| limit(10)
```

#### Уязвимости с эксплойтами

```sql
select(@VulnerPassport, VulnerPassport.CVEs, VulnerPassport.Name, VulnerPassport.Score, VulnerPassport.HasExploit)
| filter(VulnerPassport.HasExploit = true and VulnerPassport.Score >= 7)
| sort(VulnerPassport.Score DESC)
```

#### Критичные уязвимости на критичных активах

```sql
select(@Host, Host.Fqdn, Host.@Importance, Host.@Vulners)
| filter(Host.@Importance = 'H' and Host.@Vulners[@Vulners.Severity = 'Critical'])
```

#### Установленные пакеты с уязвимостями (Linux)

```sql
select(@UnixHost, Host.Fqdn, UnixHost.Packages.Name, UnixHost.Packages.Version, UnixHost.Packages.@NodeVulners)
| filter(UnixHost.Packages.@NodeVulners)
| sort(UnixHost.Packages.@NodeVulners.Score DESC)
```

### Рекурсивный поиск уязвимостей

> [!note] `@Vulners` vs `@NodeVulners`
> - `@Vulners` — **все** уязвимости, включая дочерние (ПО, сервисы, пакеты). Берёт уязвимости класса и всех подклассов.
> - `@NodeVulners` — уязвимости **только** конкретного узла (без дочерних). Берёт уязвимости уровня, указанного перед точкой.

**Пример: все уязвимости конкретного хоста**

```sql
qsearch("192.168.1.50") | select(@Host, Host.OsName, Host.@Vulners)
| filter(Host.@Vulners)
```

**Только уязвимости ОС (без ПО)**

```sql
qsearch("192.168.1.50") | select(@Host, Host.OsName, Host.OsVersion, Host.@NodeVulners)
| filter(Host.@NodeVulners)
```

## Общие ошибки и советы

| Ошибка | Проблема | Решение |
| --- | --- | --- |
| Пустой результат | Неправильный алиас | Проверьте, какой алиас использовать (`@Host` vs `@WindowsHost`) |
| `filter()` не работает | Опечатка в имени поля | Используйте подсказки веб-интерфейса |
| Много строк | Нет `limit()` | Добавьте `limit(N)` или `limit(0)` для полного вывода |
| Медленный запрос | Слишком широкий select | Укажите только нужные поля |
| Ошибка синтаксиса | Пропущен pipe `|` | Каждый этап отделяется символом `|` |
| Неправильная группировка | Группировка по всему | Укажите конкретное поле в `group()` |

### Советы по оптимизации

1. **Начинайте с qsearch** — если ищете конкретный хост
2. **Указывайте только нужные поля** — не используйте `select(@Host)` без полей
3. **Фильтруйте рано** — `filter()` до `group()` сужает набор данных
4. **Используйте `limit()`** — ограничивайте вывод в черновиках
5. **Тестируйте поэтапно** — сначала `select`, затем добавляйте `filter`, потом `group`

## Краткое резюме Этапа 4

| Аспект | Ключевая мысль |
| --- | --- |
| Pipeline | `qsearch → select → filter → group → sort → limit` |
| Алиасы | Типы объектов: `@Host`, `@WindowsHost`, `@UnixHost`, `@Vulners` |
| `@Vulners` | Все уязвимости (включая дочерние) |
| `@NodeVulners` | Только уязвимости текущего узла (без дочерних) |
| `@VulnerPassport` | Описания уязвимостей (CVE, CVSS, методы устранения) |
| `qsearch()` | Полнотекстовый поиск до SELECT |
| Группировка | `group(поле, агрегация)` — COUNT, SUM |
| Динамические группы | PDQL-запрос как основа для автоматически обновляемой группы |
