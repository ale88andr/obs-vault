В MaxPatrol VM предусмотрен механизм для автоматизации процессов устранения уязвимостей и контроля за регулярностью сканирования активов — политики. Политика состоит из совокупности правил, которые автоматически изменяют параметры объектов системы (например, сроки актуальности данных об активах или статусы экземпляров уязвимостей).

В MaxPatrol VM доступны следующие политики.

- **Значимость активов** — правила политики автоматически изменяют значимость активов. Определение значимости активов позволяет упорядочить работу с ними, выделить значимые активы, уязвимости на которых могут нанести больше всего вреда IT-инфраструктуре организации, и уделять им повышенное внимание. Необходимо стремиться к тому, чтобы для всех активов была указана значимость.

- **Сроки актуальности** — правила политики автоматически устанавливают сроки актуальности и устаревания данных об активах, полученных в результате сканирования IT-инфраструктуры методами аудита и пентеста. Опасные уязвимости на активах, данные о которых редко обновляются, могут быть выявлены слишком поздно. Вы можете оценить количество активов, данные о которых не были получены вовремя, с помощью виджета **Актуальность данных об активах**, а также найти их с помощью PDQL-запроса.
- **Статусы уязвимостей** — правила политики автоматически изменяют статус экземпляров уязвимостей, определяют срок их устранения или откладывают их обработку на определенный срок. Перечень запланированных к устранению уязвимостей можно выпускать в виде отчета по расписанию и отправлять по электронной почте системному администратору.
- **Отметка «важная»** — правила политики автоматически отмечают отдельные экземпляры уязвимостей как важные. Например, в качестве важных могут быть отмечены наиболее опасные для IT-инфраструктуры уязвимости. Вы можете найти активы с важными уязвимостями с помощью PDQL-запроса.

## Политика для значимости активов

**Задача.** Чтобы создать правило:

1. В главном меню выберите **Система** → **Политики**.
2. Выберите политику **Значимость активов**.
3. Нажмите **Создать правило**.
4. Введите название правила.
5. Выберите активы, для которых необходимо указывать значимость.
   > [!note] Примечание
   > Вы можете указать группы активов и отфильтровать активы с помощью PDQL-запроса. По ссылке **Вставить условие** доступны стандартные фильтры.
   > [!note] Примечание
   > Вы можете скопировать условие из одного из стандартных запросов в папке **Определение значимости** в панели **Запросы** на странице **Активы**. Например, выбрать активы с общими критически важными ролями можно с помощью запроса `Host.HostRoles.Role in ['DNS Server', 'Mail Server', 'DHCP Server']`.
6. Выберите значимость, которую правило будет назначать активам.
7. Нажмите **Сохранить**.
8. Нажмите **Применить изменения**.

После применения политики вы можете фильтровать активы с помощью стандартных запросов **Группировка по значимости**, **Значимость задана**, **Значимость не задана** и **Все, кроме высокой значимости**.

Вы также можете создать динамические группы на основе значимости. Значимость актива хранится в столбце `Host.@Importance`. Например, отобрать в группу только активы высокой значимости можно с помощью запроса `Host.@Importance != 'ND' AND Host.@Importance != 'L' AND Host.@Importance != 'M'`.

## Политика для сроков актуальности

**Задача.** Чтобы создать правило:

1. В главном меню выберите **Система** → **Политики**.
2. Выберите политику **Сроки актуальности** для аудита или пентеста.
3. Нажмите **Создать правило**.
4. Введите название правила.
5. Выберите активы, для которых необходимо указывать сроки актуальности данных.
   > [!note] Примечание
   > Вы можете указать группы активов и отфильтровать активы с помощью PDQL-запроса. По ссылке **Вставить условие** доступны стандартные фильтры.
6. Нажмите **Сохранить**.
7. Нажмите **Применить изменения**.

Теперь вы можете воспользоваться стандартным запросом **Время сканирования в режимах Audit и Pentest**, чтобы определить статус данных сканирования на активах в группе.

Вы также можете создать динамические группы контроля актуальности данных сканирования. Статусы данных сканирования хранятся в столбце `Host.@ScanningInfo`. Например, отобрать в группу активы с просроченными данными аудита можно с помощью запроса `Host.@ScanningInfo = "Audit: Obsolete"`.

С помощью этого запроса вы можете получить список активов, для которых данные аудита и пентеста отсутствуют или устарели:

```
filter(Host and Host.@ScanningInfo[Status in ['NeedUpdate', 'Obsolete', 'NeverHappened'] and Type in ['audit', 'pentest']]) | select(@Host, Host.@Importance) | join(select(@Host, Host.@ScanningInfo.Status, Host.@ScanningInfo.Type) | filter(Host.@ScanningInfo.Type = 'Audit') as a, a.@Host = @Host) | join(select(@Host, Host.@ScanningInfo.Status, Host.@ScanningInfo.Type) | filter(Host.@ScanningInfo.Type = 'Pentest') as p, p.@Host = @Host) | select(@Host, Host.@Importance, a.Host.@ScanningInfo.Status as Audit, p.Host.@ScanningInfo.Status as Pentest) | sort(@Host ASC)
```

## Политика для статусов уязвимостей

**Задача.** Чтобы создать правило:

1. В главном меню выберите **Система** → **Политики**.
2. Выберите политику **Статусы уязвимостей**.
3. Нажмите **Создать правило**.
4. Введите название правила.
5. В поле **Фильтр уязвимостей** введите PDQL-запрос для поиска тех экземпляров уязвимостей, статусы которых необходимо изменять.
   → Пример:
   ```
   Host.@Vulners.SeverityRating in ['Critical', 'High']
   ```
   > [!note] Примечание
   > Вы можете указать группы активов и отфильтровать активы с помощью PDQL-запроса. По ссылке **Вставить условие** доступны стандартные фильтры.
6. Выберите действие, которое необходимо выполнять с экземплярами уязвимостей.
7. Если требуется исключать из мониторинга экземпляры уязвимостей, в раскрывающемся списке **Уточнение к статусу** выберите причину исключения.
   > [!note] Примечание
   > По истечении срока исключения экземпляры уязвимостей будут по умолчанию запланированы к устранению в течение семи дней. Если требуется устранять экземпляры уязвимостей вручную, необходимо выбрать это действие в раскрывающемся списке **Устранение**.
8. Нажмите **Сохранить**.
9. Нажмите **Применить изменения**.

Доступны следующие варианты действий:

- **Плановое устранение** — экземплярам уязвимостей назначается статус **Исправляется**. Если уязвимость не исправлена в указанный срок, она переходит в статус **Требуется проверка**. Если при следующем сканировании уязвимость подтверждается, она получает статус **Просрочено**.
- **Устранение вручную** — экземплярам уязвимостей назначается статус **Новая**. Вы затем можете вручную выбрать статус **В работе**, **Исправляется** или **Исключена**.
- **Исключить** — экземплярам уязвимостей на указанный срок назначается статус **Исключена**. Необходимо также выбрать причину и срок исключения и статус, который должен быть назначен уязвимости по истечении срока.

Вы можете проверять уязвимости на значимых активах с устранением вручную и плановым на дашборде **Управление уязвимостями**.

Статусы экземпляров уязвимостей хранятся в столбце `Host.@Vulners.Status`, а назначенные действия — в столбце `Host.@Vulners.FixType`.

## Политика назначения отметки «важная»

**Задача.** Чтобы создать правило:

1. В главном меню выберите **Система** → **Политики**.
2. Выберите политику **Отметка важная**.
3. Нажмите **Создать правило**.
4. Введите название правила.
5. В поле **Фильтр уязвимостей** введите запрос на языке PDQL для поиска экземпляров уязвимостей, которые необходимо отмечать как важные.
   → Пример:
   ```
   Host.@Vulners.IsTrend = True
   ```
   > [!note] Примечание
   > Вы можете указать группы активов и отфильтровать активы с помощью PDQL-запроса. По ссылке **Вставить условие** доступны стандартные фильтры.
6. Нажмите **Сохранить**.
7. Нажмите **Применить изменения**.

Вы можете проверять важные уязвимости на значимых активах на дашборде **Управление уязвимостями**.

Отметка «важная» хранится в виде булевой переменной в столбце `Host.@Vulners.IsDanger`. Например, отфильтровать важные уязвимости можно с помощью условия `Host.@Vulners[IsDanger = True]`.

## Примеры параметров политик

Перечисленные выше политики — элемент процесса управления уязвимостями в MaxPatrol VM. Параметры политик в вашей инфраструктуре должны соответствовать стандартам, принятым в организации. Ниже приведено несколько типичных примеров групп и соответствующих политик.

Подробности см. в разделе «[Работа с уязвимостями](https://help.ptsecurity.com/ru-RU/projects/vm/2.8/help/2204533771)» Руководства оператора.

**Примеры параметров политик**

| Группа | Действие | Срок исправления или исключения |
| --- | --- | --- |
| Серверы Windows | Плановое устранение | 1 месяц |
| Linux/Unix | Плановое устранение | 1 месяц |
| Cisco | Устранение вручную | — |
| Тестовая инфраструктура | Исключить Уточнение к статусу: низкий риск | 12 месяцев |
