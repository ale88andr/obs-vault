# Устаревание актива

Сведения об активах со временем устаревают и приводят к ошибкам при выполнении задач. Чтобы не допускать таких ошибок, система выявляет и удаляет устаревшие активы. За это отвечает служба идентификации активов. Она принимает решение о том, что актив устарел и затем создает событие о его удалении. Запись об активе не удалятся безвозвратно — он будет помечен как удаленный с указанием даты. Информация об активе сохраняется в системе, чтобы можно было просмотреть его состояние на любой момент времени, предшествовавший удалению.

> [!note] Примечание
> Если необходимо, чтобы актив не удалился после устаревания (например, для активов, которые не могут сканироваться регулярно, но которые важно сохранять в системе), снимите флажок **Удалить актив из системы, если информация о нем долго не обновлялась** при редактировании паспорта актива.

Устаревшим считается актив, после последнего обновления которого прошло определенное время (по умолчанию 90 дней). Время устаревания для всех активов устанавливает администратор. Он может сделать это, [[Изменение времени устаревания активов|изменив]] значение параметра `DefaultAssetTtl` в конфигурации роли Core.

> [!note] Примечание
> Срок актуальности данных сканирования, который настраивается в [[Изменение сроков актуальности данных сканирования активов|карточке актива]] для каждого режима сканирования или в [[Создание правила для сроков актуальности данных|правилах политики]], не означает время устаревания актива.

О том, когда ожидается устаревание конкретного актива, вы можете узнать в его карточке.

Актив не устареет, если:

- данные о нем будут обновлены при сканировании;
- данные о нем будут обновлены вручную;
- данные о нем будут обновлены при импорте из файла.

Актив не будет удален в планируемую дату, если после его устаревания и до момента удаления данные о нем будут обновлены.
