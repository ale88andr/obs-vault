# Установка доверенного сертификата для RMQ Message Bus и компонентов MP 10 Core и MP 10 Collector

Для RMQ Message Bus и компонентов MP 10 Core и MP 10 Collector вы можете установить пользовательский доверенный сертификат безопасности, который должен отвечать следующим требованиям:

- использовать алгоритм подписи SHA-2 (SHA-256, SHA-384, SHA-512);
- использовать алгоритм шифрования ключей RSA;
- соответствовать формату PEM;
- использовать отдельные файлы для хранения сертификата центра сертификации (ЦС), доверенного сертификата и закрытого ключа;
- иметь заголовок `BEGIN CERTIFICATE` без дополнительных заголовков;
- содержать закрытый незашифрованный ключ в формате PEM длиной не менее 2048 бит с заголовком `BEGIN RSA PRIVATE KEY` без дополнительных заголовков;

  > [!note] Примечание
  > Чтобы расшифровать ключ, зашифрованный с помощью алгоритма RSA, необходимо выполнить команду `openssl rsa -in encrypted.key -out decrypted.key`.
- включать область применения сертификата Digital Signature или Key Encipherment;
- содержать в расширении Extended Key Usage записи аутентификации сервера `serverAuth` и аутентификации клиента `clientAuth`;
- содержать в расширении Subject Alternative Name запись типа `DNS:<FQDN узла компонента, для которого предназначен сертификат>`;
- содержать в поле `Common Name` значения `core` или `agent` для компонентов MP 10 Core и MP 10 Collector соответственно.

Во время выполнения команды импорта доверенные корневые сертификаты автоматически проверяются на соответствие требованиям безопасности. Выявленные несоответствия отображаются в терминале. Автоматизация проверки позволяет исключить риск установки потенциально небезопасных сертификатов.

Необходимо установить следующие права доступа:

- к файлам сертификата ЦС и файлу с цепочкой корневых сертификатов — 0644;
- к файлам доверенных сертификатов и ключей — 0755.

Владельцем всех файлов должен являться пользователь dockerns (UID 9009, GID 9009).

**Задача.** Чтобы установить доверенный сертификат RMQ Message Bus и компонентов MP 10 Core и MP 10 Collector на Linux:

1. Разместите файлы доверенных корневых сертификатов в рабочем каталоге пользователя на сервере c установленной ролью Deployer.
   > [!note] Примечание
   > Каждый сертификат должен находиться в отдельном файле с расширением .crt.
2. Выполните команду:
   ```bash
   deployer cacert import <Путь к корневому сертификату> <Путь к промежуточному сертификату 1> … <Путь к промежуточному сертификату N> -verbose
   ```
   > [!warning] Внимание
   > Путь к корневому сертификату необходимо указать первым. Пути к промежуточным сертификатам можно указать в любом порядке.
3. Разместите следующие файлы в каталоге `/var/lib/deployed-roles/<Идентификатор приложения>/<Идентификатор экземпляра роли>/certs` для роли RMQ Message Bus компонента MP 10 Core:
   - файл сертификата для роли RMQ Message Bus компонента MP 10 Core;
   - файл ключа сертификата роли RMQ Message Bus компонента MP 10 Core.
4. Разместите следующие файлы в каталоге `/var/lib/deployed-roles/<Идентификатор приложения>/<Идентификатор экземпляра роли>/certs` для роли Core:
   - файл клиентского сертификата для роли Core;
   - файл ключа клиентского сертификата Core.
5. Если компонент MaxPatrol 10 Collector установлен на Linux, разместите следующие файлы в каталоге `/var/lib/deployed-roles/<Идентификатор приложения>/<Идентификатор экземпляра роли>/certs` для роли Collector:
   - файл клиентского сертификата для роли Collector;
   - файл ключа клиентского сертификата для роли Collector.
6. Если компонент MaxPatrol 10 Collector установлен на Microsoft Windows, разместите следующие файлы на сервере MaxPatrol 10 Collector в постоянной папке, к которой есть доступ у пользователя Network Service:
   - файл сертификата ЦС или файл с цепочкой корневых сертификатов;
   - файл клиентского сертификата для роли Collector;
   - файл ключа клиентского сертификата для роли Collector.
7. Измените конфигурацию роли RMQ Message Bus:
   ```
   CACertFile: <Имя файла сертификата ЦС или файла с цепочкой корневых сертификатов>
   CertFile: <Имя файла доверенного сертификата>
   KeyFile: <Имя файла закрытого ключа>
   ```
8. Измените конфигурацию роли Core:
   ```
   CACertificateFileName: <Имя файла сертификата ЦС или файла с цепочкой корневых сертификатов>
   RMQSslCertificateFileName: <Имя файла доверенного сертификата>
   RMQSslKeyFileName: <Имя файла закрытого ключа>
   ```
9. Измените конфигурацию роли Collector:
   - если компонент MaxPatrol 10 Collector установлен на Linux:
   ```
   Agent_RMQ_SSL_CA_Certificate: <Полный путь к файлу сертификата ЦС или файлу с цепочкой корневых сертификатов>
   Agent_RMQ_SSL_Certificate: <Полный путь к файлу доверенного сертификата>
   Agent_RMQ_SSL_Key: <Полный путь к файлу закрытого ключа>
   ```
   - если компонент MaxPatrol 10 Collector установлен на Microsoft Windows:
   ```
   coreagentcfg set -p RMQ_SSL_CA_CERTIFICATE <Путь к файлу сертификата ЦС> RMQ_SSL_CERTIFICATE <Путь к файлу доверенного сертификата> RMQ_SSL_KEY <Путь к файлу закрытого ключа>
   ```

> [!warning] Внимание
> Если в MaxPatrol VM установлено несколько экземпляров ролей Collector, шаги инструкции необходимо выполнить для всех экземпляров.

1. На сервере с установленной ролью Deployer выполните команду:
   ```bash
   deployer cacert import <Путь к корневому сертификату> <Путь к промежуточному сертификату 1> … <Путь к промежуточному сертификату N> -verbose
   ```
   > [!warning] Внимание
   > Путь к корневому сертификату необходимо указать первым. Пути к промежуточным сертификатам можно указать в любом порядке.
2. Разместите файлы сертификата ЦС, доверенного сертификата и закрытого ключа на сервере MP 10 Core в постоянной папке, к которой есть доступ у пользователя Network Service.
3. Установите сертификат для MP 10 Collector, выполнив команду:
   ```
   coreagentcfg set -p RMQ_SSL_CA_CERTIFICATE <Путь к файлу сертификата ЦС> RMQ_SSL_CERTIFICATE <Путь к файлу доверенного сертификата> RMQ_SSL_KEY <Путь к файлу закрытого ключа>
   ```
