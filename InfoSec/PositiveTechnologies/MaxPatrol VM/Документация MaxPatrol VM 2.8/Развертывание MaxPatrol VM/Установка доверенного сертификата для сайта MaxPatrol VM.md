# Установка доверенного сертификата для сайта MaxPatrol VM

Самоподписанный сертификат, устанавливаемый автоматически при развертывании MaxPatrol VM, не является доверенным: при подключении к сайту отображается предупреждение о незащищенном соединении.

Вы можете установить собственный доверенный сертификат, который должен отвечать следующим требованиям:

- использовать алгоритм подписи SHA-2 (SHA-256, SHA-384, SHA-512);
- использовать алгоритм шифрования ключей RSA;
- соответствовать формату PEM;
- иметь заголовок `BEGIN CERTIFICATE` без дополнительных заголовков;
- содержать закрытый незашифрованный ключ в формате PEM, синтаксис PKCS #1, длиной не менее 2048 бит c заголовком `BEGIN RSA PRIVATE KEY` без дополнительных заголовков;

  > [!note] Примечание
  > Чтобы расшифровать зашифрованный с помощью алгоритма RSA ключ, необходимо выполнить команду `openssl rsa -in encrypted.key -out decrypted.key`.
- включать область применения сертификата Digital Signature или Key Encipherment;
- в расширении Extended Key Usage (EKU) содержать записи `serverAuth` и `clientAuth`;
- иметь расширение .crt;
- в расширении Subject Alternative Name (SAN) содержать запись об FQDN сервера компонента или его IP-адресе в зависимости от значения параметра `HostAddress` (оно может содержать как FQDN, так и IP-адрес).

Во время выполнения команды импорта доверенные корневые сертификаты автоматически проверяются на соответствие требованиям безопасности. Выявленные несоответствия отображаются в терминале. Автоматизация проверки позволяет исключить риск установки потенциально небезопасных сертификатов.

> [!warning] Внимание
> Если в сертификате указан URL-адрес списка отозванных сертификатов, необходимо обеспечить к нему доступ из контейнеров приложений, иначе система не сможет считать сертификат доверенным. Для проверки доступа вы можете перейти к указанному адресу в Docker-контейнере каждого приложения.

**Задача.** Чтобы установить доверенный сертификат:

1. На сервере MP 10 Core разместите файлы сертификата и закрытого ключа в каталогах `/var/lib/deployed-roles/<Идентификатор приложения>/<Название экземпляра роли>/certs` для каждой роли Core, Observability и Management and Configuration.
2. Разместите файлы доверенных корневых сертификатов в рабочем каталоге пользователя на сервере c установленной ролью Deployer.
   > [!note] Примечание
   > Каждый сертификат должен находиться в отдельном файле с расширением .crt.
3. Выполните команду:
   ```bash
   deployer cacert import <Путь к корневому сертификату> <Путь к промежуточному сертификату 1> … <Путь к промежуточному сертификату N> -verbose
   ```
   > [!warning] Внимание
   > Путь к корневому сертификату необходимо указать первым. Пути к промежуточным сертификатам можно указать в любом порядке.
4. [[Изменение конфигурации роли|Измените конфигурации]] ролей Core, Observability и Management and Configuration:
   ```
   SSLCertificatePemFileName: <Имя файла сертификата>
   SSLKeyFileName: <Имя файла закрытого ключа>
   ```
   → Например:
   ```
   SSLCertificatePemFileName: website.crt
   SSLKeyFileName: website.key
   ```

В рамках установки доверенного сертификата для роли Observability также будут установлены сертификаты для всех служб роли (Grafana, OpenTelemetry Collector, VictoriaMetrics, TelemetryTracker).

> [!warning] Внимание
> Имена файлов пользовательского сертификата и ключа не должны совпадать с именами файлов, которые уже находятся в папке сертификатов: замена содержимого стандартных файлов приведет к некорректной работе системы.
