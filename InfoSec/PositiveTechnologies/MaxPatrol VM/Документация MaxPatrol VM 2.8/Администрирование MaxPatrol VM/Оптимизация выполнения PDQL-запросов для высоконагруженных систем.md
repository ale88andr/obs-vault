# Оптимизация выполнения PDQL-запросов для высоконагруженных систем

Для оптимизации выполнения PDQL-запросов в высоконагруженных системах вы можете изменить способ фильтрации по времени для сервиса Temporal Read Model (TRM).

При первом включении нового способа фильтрации по времени сервис TRM выполняет миграцию данных. В ходе миграции создаются новые индексы, что приводит к увеличению размера БД сервиса TRM (`assets_temporal_rm`). Для таблиц с данными автоматически выполняется операция vacuum.

> [!warning] Внимание
> В процессе миграции могут возникать задержки обработки запросов на получение и вставку данных.

Существуют следующие режимы оптимизации:

- **IdAndPeriod.** Скорость обработки PDQL-запросов возрастает в несколько десятков раз. Увеличение размера БД сервиса TRM может составить до 100%.

  > [!warning] Внимание
  > Миграция данных в этом режиме может занимать более 10 часов для базы данных размером 100 ГБ.
- **PeriodOnly.** Cкорость обработки PDQL-запросов возрастает в несколько раз. Размер БД сервиса TRM увеличивается на 10—20%.

  > [!warning] Внимание
  > Миграция данных в этом режиме может занимать более одного часа для базы данных размером 100 ГБ.

> [!warning] Внимание
> Перед выполнением миграции необходимо убедиться, что свободного места на диске достаточно.

**Задача.** Чтобы определить размер базы данных сервиса TRM:

1. Откройте веб-интерфейс Grafana по адресу: `https://<IP-адрес или FQDN сервера MaxPatrol VM>:3334/grafana`.
2. Выберите дашборд **Postgresql**.
3. В поле **database** выберите `assets_temporal_rm`.

Размер базы данных показан на виджете **Database size**.

**Задача.** Чтобы включить и настроить оптимизацию выполнения PDQL-запросов,

1. [[Изменение конфигурации роли|измените конфигурацию]] роли Core, указав значения следующих параметров:
   → `AssetGridVersionRangeModeEnabled`: `True`
   → `AssetGridValidTimePeriodIndexFormat`: `<Режим оптимизации выполнения PDQL-запросов>`
