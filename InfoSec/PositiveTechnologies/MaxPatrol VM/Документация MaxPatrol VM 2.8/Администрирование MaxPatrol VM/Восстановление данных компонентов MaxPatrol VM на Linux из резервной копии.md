# Восстановление данных компонентов MaxPatrol VM на Linux из резервной копии

Для восстановления данных вам потребуются архивы с дистрибутивами ролей. Их версии должны совпадать с версиями дистрибутивов, которые были использованы при создании резервной копии.

Перед восстановлением данных необходимо разместить резервную копию на сервере роли Deployer, а также распаковать на этом сервере архивы с дистрибутивами ролей.

> [!note] Примечание
> Каталоги с резервными копиями должны иметь структуру вида `/<Имя каталога>/<Идентификатор приложения>/<Название экземпляра роли>/backup.tar`, полученную при резервном копировании, например `/backup/mc-application/sqlstorage/backup.tar`.

> [!note] Примечание
> Устанавливать роли в процессе восстановления данных необходимо в соответствии [с инструкциями по развертыванию](https://help.ptsecurity.com/ru-RU/projects/vm/2.8/help/5766586891). При установке всех ролей, кроме Deployer, необходимо выбирать идентификатор восстанавливаемого приложения и название экземпляра восстанавливаемой роли.

**Задача.** Чтобы восстановить данные компонентов на Linux:

1. Установите пакеты ролей и экземпляр роли Deployer с помощью сценария `install_all_role_packages.sh`.
2. Восстановите данные роли Deployer:
   ```
   /var/lib/deployed-roles/<Идентификатор приложения Deployer>/<Название экземпляра роли Deployer>/restore.sh <Путь к архиву c файлами резервной копии>
   ```
   → Например:
   ```
   /var/lib/deployed-roles/Deployment-Application/Deployer/restore.sh /home/deploy-app/Deployer/backup.tar
   ```
3. Если вы сохранили каталог `/var/lib/deployer/app_packages` с пакетами приложений MaxPatrol VM, скопируйте его по прежнему пути.
4. Если вы используете пользовательские сертификаты, добавьте файлы корневых и промежуточных пользовательских сертификатов центра сертификации для роли Deployer, сохраненные на этапе [[Создание резервной копии данных|резервного копирования]], в каталог `/opt/deployer/pki/trusted_ca/`.
5. Для каждой роли в каталоге `/var/lib/deployer/role_instances/<Название роли>` в файле `instance.yaml` в качестве значения параметра `HostId` укажите идентификатор Salt Minion.
6. Для каждой роли в каталоге `/var/lib/deployer/role_instances/<Название роли>` в файлах `params.yaml` и `params.default.yaml` в качестве значений параметров, содержащих FQDN, укажите FQDN серверов, на которые будут установлены соответствующие роли.
   > [!note] Примечание
   > Для быстрой замены значений параметров можно использовать команду `find /var/lib/deployer/ -name "params*.yaml" -exec sed -i 's/<FQDN сервера, на который была установлена роль>/<FQDN сервера, на который будет установлена роль>/' {} \;`.
7. Если ранее были добавлены файлы корневых и промежуточных пользовательских сертификатов, выполните команду для их обработки:
   ```bash
   deployer instance reconfigure -type Deployer
   ```
8. Создайте каталоги, в которых хранились файлы сертификатов.
   ```bash
   mkdir -p <Путь к каталогу сертификатов>
   ```
   → Например:
   ```bash
   mkdir -p /var/lib/deployed-roles/mp10-application/core-1/certs
   ```
9. Скопируйте в эти каталоги файлы сертификатов, сохраненные при создании резервной копии:
   ```bash
   cp <Путь к каталогу резервной копии сертификатов>/* <Путь к каталогу сертификатов>
   ```
   → Например:
   ```bash
   cp backup/certs/core/certs/* /var/lib/deployed-roles/mp10-application/core-1/certs
   ```
10. Установите роль SqlStorage.
    ```
    pt_sqlstorage_<Номер версии>/install.sh
    ```
    → В процессе установки система запросит реконфигурацию параметров ролей. Ее необходимо отклонить.
11. Восстановите данные роли SqlStorage:
    ```
    /var/lib/deployed-roles/<Идентификатор приложения SqlStorage>/<Название экземпляра роли SqlStorage>/restore.sh <Путь к каталогу c файлами резервной копии>
    ```
    → Например:
    ```
    /var/lib/deployed-roles/mc-application/sqlstorage/restore.sh /home
    ```
12. Установите роль LogConnector:
    ```
    pt_logconnector_<Номер версии>/install.sh
    ```
    → В процессе установки система запросит реконфигурацию параметров ролей. Ее необходимо отклонить.
13. Установите роль Observability:
    ```
    pt_observability_<Номер версии>/install.sh
    ```
    → В процессе установки система запросит реконфигурацию параметров ролей. Ее необходимо отклонить.
14. Установите роль Management and Configuration.
    ```
    pt_managementandconfiguration_<Номер версии>/install.sh
    ```
    → В процессе установки система запросит реконфигурацию параметров ролей. Ее необходимо отклонить.
15. Установите роли RMQ Message Bus и Core.
    ```
    pt_rmqmessagebus_<Номер версии>/install.sh
    pt_core_<Номер версии>/install.sh
    ```
    → В процессе установки система запросит реконфигурацию параметров ролей. Ее необходимо отклонить.
16. Восстановите данные роли Core:
    ```
    /var/lib/deployed-roles/<Идентификатор приложения Core>/<Название экземпляра роли Core>/restore.sh <Путь к каталогу c файлами резервной копии>
    ```
17. Если вы используете пользовательские сертификаты, добавьте файлы пользовательских сертификатов для остальных ролей:
    > [!warning] Внимание
    > В случае если резервная копия была создана на сервере с IP-адресом или FQDN, отличным от IP-адреса и FQDN сервера, на котором выполняется восстановление, пользовательские доверенные сертификаты, сохраненные в резервной копии, перестанут быть валидными.
    - Если резервная копия была создана на том же сервере, на котором выполняется восстановление, добавьте файлы пользовательских сертификатов, сохраненные на этапе [[Создание резервной копии данных|резервного копирования]], в каталоги `/var/lib/deployed-roles/<Идентификатор приложения>/<Название экземпляра роли>/certs`.
    - Если резервная копия была создана на одном сервере, а восстановление выполняется на другом, для доверенного сертификата в расширении Subject Alternative Name (SAN) должен быть указан IP-адрес или FQDN того сервера, на котором выполняется восстановление.
18. Выполните команду для восстановления экземпляров роли Collector:
    ```bash
    deployer instance reconfigure -type AgentLinux
    ```
19. Выполните реконфигурацию экземпляров ролей.
    ```bash
    deployer instance reconfigure -diff -silent
    ```
20. Если ключ инсталляции PT MC уже использовался для активации PT MC на другом устройстве, [[Деактивация PT MC|деактивируйте]] PT MC.
21. Если вы деактивировали PT MC, [[Активация PT MC [Обновление с помощью дистрибутивов]|активируйте]] систему повторно.
    > [!warning] Внимание
    > Количество активаций ключа инсталляции PT MC ограничено. Если лимит активаций превышен, ваш экземпляр PT MC отключится через 30 дней с момента активации. Чтобы избежать этого, обратитесь в службу технической поддержки Positive Technologies.
22. Если вы деактивировали PT MC, повторно [[Активация лицензии MaxPatrol VM|активируйте]] MaxPatrol VM.
