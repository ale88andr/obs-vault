**Задача.** Чтобы создать задачу:

1. В главном меню выберите **Сбор данных** → **Задачи**.
   → Откроется страница **Задачи по сбору данных**.
2. Нажмите кнопку **Создать задачу** и выберите пункт **Сбор данных**.
3. В поле **Название** введите название задачи.
4. В раскрывающемся списке **Расположение** выберите группу, в которую войдет новая задача.
   > [!note] Примечание
   > Если при создании задачи не была выбрана группа задач, задача будет находиться в пространстве **Задачи вне групп**.
5. В панели **Параметры сбора данных** в раскрывающемся списке **Профиль** выберите профиль.
6. Если требуется, в раскрывающемся списке **Учетная запись** выберите учетную запись для сбора данных.
   → В раскрывающемся списке **Учетная запись** отображаются учетные записи, при добавлении которых была выбрана метка используемого профилем метода сбора данных или не было выбрано никаких меток. По умолчанию выбрана учетная запись, указанная в профиле.
   → В зависимости от профиля для выбора учетной записи вам может потребоваться указать другие параметры профиля или выбрать другой пункт в иерархическом списке.
7. Если требуется, настройте другие параметры профиля.
   > [!note] Примечание
   > Профили Windows Audit, Windows Audit Vulnerabilities Discovery и Unix SSH Audit поддерживают получение обновлений экспертных данных для аудита с сервера Positive Technologies. Обновления хранятся в справочнике audit_expertise_extension. Вы можете отключить использование этого справочника в пункте **Дополнительная экспертиза для аудита** иерархического списка.
   > [!note] Примечание
   > Вы можете импортировать сохраненные ранее параметры профиля, указав по кнопке **Импорт** файл с параметрами.
8. Если требуется, в раскрывающемся списке **Коллекторы** выберите коллекторы для сбора данных.
   > [!note] Примечание
   > Для аудита высоконагруженных инфраструктур (например, каталога Active Directory) рекомендуется использовать MP 10 Collector, установленный на Linux.
9. Если в системе заведено больше одной инфраструктуры, в раскрывающемся списке **Инфраструктура** выберите инфраструктуру.
10. В панели **Цели сбора данных** → **Включить** укажите цели. Большое количество адресов рекомендуется разбить на более мелкие блоки и создать отдельные задачи на сбор данных для каждого блока:
    - Если вы хотите сканировать группу активов, укажите ее в поле **Группы активов**.
    - Если вы хотите сканировать отдельные активы, укажите их в поле **Активы**.
    - Если вы хотите сканировать конкретные сетевые узлы, укажите их IP-адреса, FQDN или маски подсетей в поле **Сетевые адреса**.
    > [!note] Примечание
    > Вы также можете изменить приоритетный способ подключения к активам — по полному доменному имени (FQDN) или по IP-адресу. По умолчанию выбран приоритет подключения по FQDN актива, так как вероятность его изменения ниже, чем у IP-адреса. Подключение по FQDN позволяет увеличить согласованность результатов сбора данных и реализовать поддержку протокола Kerberos. При невозможности подключения к активу по FQDN используется подключение по IP-адресу, и наоборот.
    > [!warning] Внимание
    > Для корректного сбора данных необходимо, чтобы подсети, используемые в вашей организации, не совпадали с подсетью Docker-контейнеров (172.17.0.0—172.31.255.255 и 192.168.0.0—192.168.255.255). Вы можете изменить подсеть Docker-контейнера [[Подсеть Docker-контейнера MaxPatrol VM совпадает с одной из подсетей предприятия|по инструкции]].
    > [!note] Примечание
    > В поле **Сетевые адреса** вы также можете указывать локальные сетевые адреса, например `localhost`, `127.0.0.1`, `::1`. Это может потребоваться для сбора данных о конфигурации MP 10 Collector, журналов MP 10 Collector или для использования модуля RemoteExecutor.
11. Если требуется, установите флажок **Выполнить обнаружение узлов до начала сбора данных**.
    → Обнаружение узлов до начала сбора данных позволяет сократить общее время сканирования.
    > [!note] Примечание
    > Если установлен флажок **Выполнить обнаружение узлов до начала сбора данных**, [[Запуск проверки подключения|при запуске проверки подключения]] модуль HostDiscovery будет запущен только на одном коллекторе из выбранных.
    > [!note] Примечание
    > Если в IT-инфраструктуре организации используется Check Point Security Gateway с включенной защитой SYN Attack protection, для каждого Check Point Security Gateway необходимо добавить в белый список SYN Attack protection IP-адрес MaxPatrol VM. Для этого требуются привилегии уровня expert.
12. Если требуется исключить отдельные цели сбора данных, укажите их на вкладке **Исключить**.
    → Для исключения целей сбора данных, заданных по IP-адресу или маске подсети, необходимо указать их IP-адреса, а для целей, заданных по FQDN, — указать их FQDN.
13. Если требуется, в панели **Расписание** включите и настройте автоматический запуск задачи.
14. Нажмите **Сохранить**.
