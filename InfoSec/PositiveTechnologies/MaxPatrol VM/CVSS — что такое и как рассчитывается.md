# Что такое CVSS

**CVSS** (Common Vulnerability Scoring System) — это открытая система оценки критичности уязвимостей, разработанная и поддерживаемая организацией [FIRST.Org](https://www.first.org/cvss/). Она позволяет перевести технические характеристики уязвимости в числовую оценку от **0,0 до 10,0**, а также представить их в виде компактной **векторной строки**.

CVSS нужен для того, чтобы разные организации и специалисты оценивали уязвимости **по единым правилам**, а не субъективно. Оценка не учитывает бизнес-риски (количество клиентов, финансовые потери и т.п.) — эти факторы оцениваются уже внутри организации отдельно.

## 1. Из чего состоит CVSS

CVSS делится на **3 группы метрик**:

| Группа | Назначение | Кто обычно заполняет |
|---|---|---|
| **Base (Базовая)** | Внутренние технические характеристики уязвимости. Не меняются со временем и не зависят от окружения. | Разработчик ПО, производитель, или аналитик, публикующий описание уязвимости (CVE). |
| **Temporal (Временная)** | Корректирует Base с учётом того, как меняется ситуация со временем (появился эксплойт, вышел патч и т.д.). | Аналитик уязвимостей. |
| **Environmental (Средовая)** | Корректирует оценку под конкретную IT-инфраструктуру организации (наличие защитных мер, важность активов). | Специалисты ИБ в организации (потребители). |

Чаще всего публикуется только **Base Score**. Temporal и Environmental можно рассчитать дополнительно, чтобы получить более точную оценку для своей среды.

## 2. Base-метрики (основные)

Base-оценка складывается из трёх блоков: **Exploitability** (возможность эксплуатации), **Scope** (границы воздействия) и **Impact** (последствия).

### 2.1 Exploitability (возможность эксплуатации)

Показывает, **насколько легко** можно эксплуатировать уязвимость. Оценивается относительно *уязвимого компонента* (того, в чём именно есть уязвимость).

| Метрика | Коротко | Возможные значения | Что означает |
|---|---|---|---|
| **AV (Attack Vector)** | Способ атаки | `N` (Network) — 0,85 | Уязвимость эксплуатируется по сети (включая Интернет). Чем дальше может находиться атакующий — тем выше оценка. |
| | | `A` (Adjacent) — 0,62 | Требуется нахождение в той же логической/физической сети (Wi-Fi, локальный сегмент). |
| | | `L` (Local) — 0,55 | Атакующий должен иметь локальный доступ к системе (консоль, SSH) либо требуется действие пользователя. |
| | | `P` (Physical) — 0,2 | Требуется физический доступ к устройству. |
| **AC (Attack Complexity)** | Сложность атаки | `L` (Low) — 0,77 | Атаку можно провести стабильно, без особых предварительных условий. |
| | | `H` (High) — 0,44 | Требуются дополнительные условия (знание конфигурации, race condition, man-in-the-middle и др.), успешная атака не гарантирована. |
| **PR (Privileges Required)** | Требуемые привилегии | `N` (None) — 0,85 | Привилегии не требуются (атакующий неавторизован). |
| | | `L` (Low) — 0,62 (0,68 при Scope=Changed) | Достаточно привилегий обычного пользователя. |
| | | `H` (High) — 0,27 (0,5 при Scope=Changed) | Требуются привилегии администратора/высокого уровня. |
| **UI (User Interaction)** | Взаимодействие с пользователем | `N` (None) — 0,85 | Уязвимость можно эксплуатировать без участия человека. |
| | | `R` (Required) — 0,62 | Обязательно требуется, чтобы пользователь выполнил какое-то действие (открыл документ, перешёл по ссылке и т.д.). |

### 2.2 Scope (S) — границы воздействия

**Scope** показывает, может ли эксплуатация уязвимости в одном компоненте повлиять на компоненты, находящиеся **за пределами его зоны безопасности** (security scope).

| Значение | Обозначение | Пояснение |
|---|---|---|
| **Unchanged (U)** | Без изменения границ | Уязвимый компонент и пострадавший компонент управляются **одной** системой безопасности. Воздействие ограничено тем же компонентом. |
| **Changed (C)** | С изменением границ | Атака затрагивает компоненты, управляемые **другой** системой безопасности (например, уязвимость в веб-приложении даёт доступ к ОС или БД). Это серьёзнее, поэтому даёт больший вклад в итоговую оценку. |

### 2.3 Impact (последствия)

Оценивают ущерб для **пострадавшего компонента** (impacted component) — того, на чём реально проявились последствия атаки.

| Метрика | Что измеряет | `H` (High) | `L` (Low) | `N` (None) |
|---|---|---|---|---|
| **C (Confidentiality)** | Конфиденциальность | Полная утрата: доступ ко **всей** конфиденциальной информации. | Частичная утрата: доступ к некоторой информации, без полного контроля атакующего. | Нет потери конфиденциальности. |
| **I (Integrity)** | Целостность | Полная утрата: атакующий может **любым образом** изменять данные/файлы. | Частичное изменение данных, без возможности контролировать все последствия. | Нет потери целостности. |
| **A (Availability)** | Доступность | Полная утрата доступности (услуга недоступна полностью, устойчиво). | Частичное снижение производительности/доступности, сервис не блокируется полностью. | Нет влияния на доступность. |

## 3. Temporal-метрики (временные)

Учитывают текущее состояние уязвимости.

| Метрика | Обозначение | Значения (важность снижается по мере исправления) |
|---|---|---|
| **E (Exploit Code Maturity)** | Зрелость эксплойта | `H` (High) — есть рабочий автоматизированный эксплойт (worm/утилита). `F` (Functional) — есть рабочий эксплойт. `P` (Proof-of-Concept) — есть PoC, требует доработки. `U` (Unproven) — эксплойта нет. `X` (Not Defined) — не влияет. |
| **RL (Remediation Level)** | Уровень исправления | `U` (Unavailable) — решения нет. `W` (Workaround) — есть неофициальное обходное решение. `T` (Temporary Fix) — временный фикс от вендора. `O` (Official Fix) — есть официальный патч/обновление. `X` — не влияет. |
| **RC (Report Confidence)** | Достоверность отчёта | `C` (Confirmed) — уязвимость подтверждена (исходники, PoC рабочий, вендор подтвердил). `R` (Reasonable) — есть существенные детали, но не полная уверенность. `U` (Unknown) — отчёты неполные/противоречивые. `X` — не влияет. |

## 4. Environmental-метрики (окружение)

Позволяют скорректировать оценку под приоритеты организации:

- **Security Requirements** (`CR`, `IR`, `AR`) — насколько критичны для организации конфиденциальность/целостность/доступность для данного актива (`L`, `M`, `H`, `X`). По умолчанию `M` (Medium).
- **Modified Base Metrics** — можно скорректировать базовые метрики, если в окружении есть компенсирующие контроли (например, сегментация сети снижает AV/AC).

## 5. Как рассчитывается CVSS (принцип)

CVSS использует математические формулы (v3.1), но суть простая:

1. **Считается Impact Sub-Score (ISS)** — на основе потерь C,I,A.
2. **Считается Impact** — в зависимости от `Scope` (если границы изменяются — воздействие усиливается).
3. **Считается Exploitability** — произведение AV×AC×PR×UI с коэффициентами.
4. **Base Score** = округление до 1 знака после запятой по специальному правилу (`round up`):  
   - Если `Impact <= 0` → **0,0**
   - Если `Scope = Unchanged (U)` → `min(Impact + Exploitability, 10)`
   - Если `Scope = Changed (C)` → `min(1.08 × (Impact + Exploitability), 10)`
5. **Temporal** = `round_up(Base × E × RL × RC)`
6. **Environmental** — считается по тем же формулам, но с модификаторами (Modified + Requirements). Даёт наиболее точную оценку для конкретной среды.

Полные формулы приведены в [спецификации CVSS v3.1](https://www.first.org/cvss/v3.1/specification-document).

## 6. Векторная строка CVSS

Оценка всегда сопровождается **вектором** — он показывает, какие значения были выбраны, и позволяет воспроизвести расчёт.

**Пример:** `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`

Расшифровка:
- `CVSS:3.1` — версия
- `AV:N` — Network, `AC:L` — Low, `PR:N` — None, `UI:N` — None
- `S:U` — Scope Unchanged
- `C:H/I:H/A:H` — High по всем трём Impact

Эта векторная строка даёт **Base Score 9,8** (уровень **Critical**).

## 7. Уровни критичности (Severity Rating)

FIRST задаёт диапазоны для **Base Score**:

| Диапазон | Уровень | Описание |
|---|---|---|
| **0,0** | None | Нет уязвимости / не влияет |
| **0,1 – 3,9** | Low (Низкий) | Низкая критичность |
| **4,0 – 6,9** | Medium (Средний) | Средняя критичность |
| **7,0 – 8,9** | High (Высокий) | Высокая критичность |
| **9,0 – 10,0** | Critical (Критический) | Критическая критичность |

## 8. Краткий вывод

- **CVSS** — это не оценка бизнеса, а **техническая оценка тяжести уязвимости**.
- **Base** — «как опасна уязвимость сама по себе».
- **Temporal** — «насколько опасна прямо сейчас».
- **Environmental** — «насколько опасна именно для нас».

Для практической работы в MaxPatrol VM чаще всего опираются именно на **Base Score** и **вектор CVSS**, сверяя их с официальными данными (NVD/FIRST/CVE).
