## 5.1 Правила для атак (сигнатурный детект)

- Правило — совокупность признаков, по которым модуль `ptdpi` находит атаку или её фазу; задаёт название, класс, уровень опасности, может содержать описание уязвимости и рекомендации (раздел 2.2)
- Управление: раздел **«Правила для атак и группы»** в администрировании (20.2): просмотр, поиск, создание, копирование, импорт, синхронизация
- Источники: правила PT (база знаний экспертного центра), Proofpoint ET Open/ET Pro — загружаются автоматически; пользовательские — свои
- Вендорские правила удалять нельзя; состояние «Пользовательские изменения» показывает, что правило правил оператором

### Синтаксис (приложение Ж)

- Поддержка ключевых слов **Suricata 5**
- Ключевые слова для записи протоколов и приложений
- Расширение **`ptrule`** — обращение к полям в транзакциях протоколов: допустимые структуры, операторы, типы данных, поля протоколов
- Практика этапа: прочитать приложение Ж и разобрать 2–3 вендорских правила построчно

> [!important] Обязательная настройка
> Для корректной работы правил нужно настроить **группы узлов и группы портов** (раздел 20.7) — иначе правила, рассчитанные на «сервер БД», «рабочая станция» и т.п., будут работать некорректно.

## 5.2 Карточка атаки (раздел 10.1)

- **Описание и рекомендации** — то, что дал вендор: уязвимость, ПО злоумышленника, последовательность действий, что делать оператору, ссылки на CVE/Securelist
- **Тактики и техники ATT&CK** — блок в общих сведениях
- **Сработавшее правило** — текущая версия правила (может отличаться от версии на момент срабатывания) и **Payload** — сегмент трафика, на котором сработало правило
- **Причина срабатывания** — вместо правила, если атака найдена правилом обнаружения аномалий: та часть метаданных сессии, которая привела к записи
- Из карточки атаки возможен переход к карточке правила для активности (кроме флудов, сканирований, ICMP-туннелей)

## 5.3 Работа с ложными срабатываниями (раздел 10.10)

- Отметки о ложных срабатываниях ставятся в свойствах атаки; такие строки в таблице — более светлые
- Фильтры: `alert.false_positive`, `alert.false_positive.author`, `alert.false_positive.date`, полнотекстовый `alert.false_positive.comment`
- В 12.3 отметки можно ставить и из центральной консоли для данных дочерних систем
- **Правило подавления:** комментарий обязан описывать причину; не отключайте правило целиком — сузьте область (узел/группа/период)

### Справочник исключений (раздел 20.4)

- Исключения из правил для атак добавляются из четырёх мест: карточка атаки, карточка правила, карточка сессии, таблица всех исключений
- Исключения из правил для активностей — из ленты активностей или таблицы всех исключений
- Есть экспорт справочника и импорт записей — используйте это для переноса «белых списков» между системами

## 5.4 Правила для активностей (несигнатурный детект)

- Ищут опасную/потенциально опасную активность **по совокупности признаков в цепочке сессий**, с функцией самообучения (раздел 2.2)
- Набор обновляется из базы знаний экспертного центра PT; свои правила тоже можно создавать (20.3.7) и даже создавать их из сохранённых фильтров (20.3.8)
- Управление (20.3): включение/выключение, изменение уровня опасности, массовые операции, удаление
- **Обучение правила** (20.3.10–20.3.11): ручной и автоматический перезапуск (по умолчанию раз в сутки); перезапуск нужен, если правило часто срабатывает на легитимное
- **Что нового в 12.3:** улучшены правила «DNS-туннелирование», «Активность сканера сети», «Медленное сканирование», «Сканирование сети» — меньше ложных срабатываний, информативнее карточки

## 5.5 Лента активностей — рабочий цикл (раздел 14)

1. **Просмотр списка** → карточка активности (комментарии, вкладчики)
2. **Перейти к дашбордам** — трафик, отфильтрованный по активности (если активность дольше 24 часов, показываются последние 24 часа — период расширяется вручную)
3. **Выбор решения** — например, «проблема решена» после смены словарного пароля; можно применить решение сразу к аналогичным активностям на том же узле
4. **Отслеживание** — возможность отключить/возобновить отслеживание активности на период
5. **Ретроспективные результаты** — флажок «Показывать в ленте активностей» в параметрах уведомлений (14.13)

## 5.6 Репутационные списки и исключения DGA

- **Репутационные списки** (20.5): IP-адреса, домены, URL, файлы; цвет элемента = цвет списка (0–7), для DGA — 8
- Фильтры: `rpt`, `rpt.cat`, `rpt.color`, `rpt.type` (ip/dga/host/url/md5/ms), `rpt.where` (flow.src/flow.dst/files/dns/http/tls.sni/quic.sni)
- **Исключения DGA** (20.6) — для легитимных доменов, похожих на сгенерированные

## 5.7 Плейбуки (новое в 12.3)

- Документы с порядком реагирования, доступны по ссылке из карточек атаки, активности, сессии, правила атаки и правила активности
- Добавлены плейбуки: Coerce-атака, DNS-туннелирование, активность вредоносного ПО по DNS, ПО удалённого управления, DCSync, детектирование вредоносного ПО, попытки эксплуатации уязвимостей (T1190), энумерация (ATTACK AD), SHELL, TOOLS, успешная эксплуатация уязвимости
- Список будет расширяться — проверяйте при обновлениях

## Практика этапа

- Разобрать 3 вендорских правила: что срабатывает, какие поля заданы, какой MITRE соответствует
- Написать и проверить простое пользовательское правило для атаки (по приложению Ж)
- Создать правило для активности из сохранённого фильтра (20.3.8)
- Провести учебный FP: поставить отметку о ложном срабатывании, добавить исключение, проверить фильтром `alert.false_positive`
- Настроить обучение пользовательского правила профилирования и перезапустить обучение после ложного срабатывания
