## 6.1 Фильтры — главный инструмент

### Операторы (приложение Б.1)

| Группа | Операторы | Пример |
| --- | --- | --- |
| Сравнения | `>` `<` `>=` `<=` `==` `<>` `!=` `~` (шаблон) `=` (полнотекстовый) | `src.ip == 10.0.0.24`, `files.filename ~ '*.exe'` |
| Логические | `&&` / `and`, `\|\|` / `or`, `!` / `not` | `src.port == 23518 && dst.port == 445` |
| Множества | `in [x,y,z]`, `in [n..m]` | `app_proto in [tls,ssh,dns]`, `bytes.total in [150000..250000]` |

### Ключевые параметры (приложение Б.2)

- **Атаки:** `alert` (сессии с атаками), `alert.pr` (уровень опасности; `alert.pr <= 2` — средний+высокий), `alert.msg`, `alert.cls`, `alert.att_ck`, `alert.success` (успешная атака — сработало при наличии применимой уязвимости по данным MaxPatrol 10), `alert.attacker.*` / `alert.victim.*`
- **Транспорт и объёмы:** `proto`, `src.ip`, `dst.ip`, `src.port`, `dst.port`, `bytes.*`, `pkts.*`, `state` (ESTABLISHED / FINISHED)
- **Прикладной уровень:** `app_proto`, `app_protos`, `app_service`, `http.*`, `dns.*`, `tls`, `ssh`, `ftp`, `smtp`…
- **Файлы:** `files`, `files.filename`, `files.md5`, `files.mime`, `files.size`, `files.rpt.verdict` (семейство вредоносного ПО от MultiScanner), `files.rpt.sandbox`
- **Учётные данные:** `credentials.login`, `credentials.password`, `credentials.valid`
- **IOC:** `rpt`, `rpt.cat`, `rpt.color`, `rpt.type`, `rpt.where`
- **Качество данных:** `errors` (проблемы сборки сессии), `flags` — смотрите в карточке сессии
- **Узлы и группы:** `host.*`, `host.groups`, `dst.groups`, `src.groups` (группы активов приходят и от MaxPatrol 10)

### Полнотекстовый поиск (приложение Б.3)

Поля вида `any`, `alert.any`, `http.any`, `dns.any`, `files.any`, `mail.subject`, `telnet.rqs`, `smtp.any` и др. — поиск по содержимому там, где оно индексируется. В 12.3 дополнительно индексируются **нестандартные поля HTTP-заголовков**.

### Примеры (приложение Б.4)

```
!files                                    — сессии без файлов
dst.ip == 213.180.204.3                   — конкретный получатель
alert.pr <= 2                             — средние и высокие атаки
dst.dns ~ "ptsec*"                        — домены по шаблону
http(rqs.method == POST and rsp.status == OK)
src.ip == 198.51.100.31 and not http.rqs.user-agent ~ "*Windows NT*"
!errors && !flags                         — сессии без ошибок и фильтров
```

### Сохранённые фильтры (раздел 13)

- **личные** и **общие** фильтры; копирование между наборами, изменение, удаление
- по личному фильтру можно настроить **автоматическую генерацию отчётов** (16.2)
- фильтр сохраняется в аккаунте и доступен при переходе между страницами

## 6.2 Сессии — от списка к доказательствам (раздел 9)

Рабочий маршрут:
1. **Список сессий** → фильтр по периоду и метаданным
2. **Карточка сессии** — расширенные данные, флаги и ошибки (экспертный режим), DGA-домены
3. **Экспорт PCAP** сессий (9.9) — дамп для Wireshark/эксперта
4. **Копирование трафика в хранилище** (9.10) — зафиксировать «срез доказательств» для ретроспективного анализа
5. **Экспорт метаданных** в JSON/CSV (9.11) — для своего анализа или передачи
6. **Скачивание файлов**, переданных в сессии (9.12) — на проверку в MultiScanner/Sandbox
7. **Ссылка на карточку сессии** (9.13) — приложить к отчёту/заявке

## 6.3 Атаки — эскалация от срабатывания (раздел 10)

- Фильтрация атак по периоду и метаданным, диаграмма распределения по времени (выявление закономерностей)
- Экспорт PCAP по атакам (10.6), копирование в хранилище (10.7), экспорт метаданных (10.8), скачивание файлов (10.9)
- Отметки о ложных срабатываниях (10.10) и ссылка на карточку атаки (10.11)

## 6.4 Сетевые связи и узлы

- **Сетевые связи** (раздел 12): просмотр связей узла, фильтры по периоду и метаданным — ответ на вопрос «с кем вообще общался затронутый хост»
- **Узлы** (раздел 15): сводная и подробная информация, трафик по узлу, переименование, комментарии, типы и роли (ручные и автоопределение) — обогащение контекста для отчёта

## 6.5 Внешняя проверка индикаторов

- **IP/домены** (раздел 17): статистика на дашбордах + WHOIS и проверка на внешних ресурсах — для неизвестных узлов
- **Файлы** (раздел 18): статистика по файлу, информация о вредоносном ПО во внешней аналитической системе, проверка на внешних ресурсах

## 6.6 Итог расследования

- **Отчёт о сетевом взаимодействии** (16.1): со страниц Дашборды / Сессии / Атаки / Сетевые связи → «Выпустить отчёт», формат PDF/DOCX; автоматизация — по личному фильтру (16.2) или по всему трафику (16.3), отправка на e-mail
- **Регистрация инцидента в MaxPatrol 10** (раздел 19): из таблицы сессий/атак или из карточки → «Зарегистрировать инцидент» → информация об инциденте → ссылка в уведомлении на карточку

### Шаблон расследования

1. Фильтр и период → какие сессии/атаки вошли в картину
2. Затронутые узлы: тип, роль, значимость, соседи по сетевым связям
3. Стадия kill chain / техники ATT&CK из карточек атак
4. Артефакты: PCAP, файлы (MD5), домены, URL, логины `credentials.*`
5. Распространение: были ли аналогичные активности на других узлах (`host.groups`, `alert.attacker.ip`)
6. Вывод и рекомендация → отчёт + регистрация инцидента

## Практика этапа

- Найти все сессии узла за сутки, экспортировать PCAP, открыть в Wireshark
- Найти сессии с файлами `.exe`, у которых `files.rpt.verdict` задан — скачать файл
- Найти учётные данные: `credentials.valid == false` — отработать как активность «словарный пароль»
- Составить сложный фильтр из 3+ условий с `not` и `in [..]`, сохранить как личный, сделать общий
- Выпустить отчёт по личному фильтру и настроить его еженедельную рассылку
- Провести полное расследование по шаблону выше и зарегистрировать инцидент в MaxPatrol 10
