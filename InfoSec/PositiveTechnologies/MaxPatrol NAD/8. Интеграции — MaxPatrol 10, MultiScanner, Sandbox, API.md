## 8.1 MaxPatrol 10 (SIEM)

Что даёт интеграция (раздел 2):
- **передача сведений об угрозах** в MaxPatrol 10 для инвентаризации активов и проверки результативности атак
- обмен данными работает через API MaxPatrol 10 и специального агента
- события NAD могут уходить и в другие SIEM по **syslog** или через **webhook**

Как используется в операторской работе:
- **регистрация инцидента** (раздел 19): из таблицы сессий/атак или из карточки → заполнить информацию → перейти по ссылке в уведомлении к карточке инцидента
- **`alert.success`** — атака считается успешной, если для узла найдена применимая уязвимость *по информации из MaxPatrol 10*; то есть «успешность» — это пересечение трафика и данных VM/SIEM
- **группы активов** из MaxPatrol 10 участвуют в фильтрации (`host.groups`, `src.groups`, `dst.groups`, `alert.attacker.groups`, `alert.victim.groups`)
- в версии **PT NAD Sensor** интеграция упрощена (см. [[2. Архитектура и захват трафика]])

> [!tip] Цепочка контекста
> NAD видит сетевую попытку → MaxPatrol 10/VM сообщает, что это был хост с критичной уязвимостью и известной учётной записью → инцидент получает приоритет и доказательность.

## 8.2 Внешние аналитические системы: файлы

- **PT MultiScanner** — антивирусное сканирование и репутационный анализ извлечённых из трафика файлов
- **PT Sandbox** — антивирусное сканирование, экспертная оценка и поведенческий анализ
- Отображение в данных:
  - `files.rpt.verdict` — семейство вредоносного ПО (MultiScanner)
  - `files.rpt.sandbox == true` — опасное поведение выявлено (MultiScanner < 3.0 или PT Sandbox)
  - `rpt.cat` / `rpt.type == "ms"` — файл определён как опасный
- Раздел 18: статистика по файлу на дашбордах, информация о вредоносном ПО во внешней аналитической системе, проверка файла на внешних ресурсах

## 8.3 Репутации и внешние проверки

- **База знаний PT** — экспертиза об атаках на удалённую эксплуатацию уязвимостей и о безопасности IP/доменов/ссылок/файлов поставляется в продукт (раздел 2)
- **Репутационные списки** (20.5) — свои и вендоровские, работают при обогащении метаданных
- **Раздел 17** — WHOIS и проверка IP/доменов на внешних ресурсах для неизвестных узлов

## 8.4 Открытые интерфейсы

- **Открытый HTTP API** — разработка сторонних приложений для работы с проанализированным трафиком (раздел 2)
- **Справочное руководство по REST API** — отдельный документ комплекта (см. раздел 1 руководства оператора): доступные функции сервиса REST API
- Типовые сценарии автоматизации:
  - выгрузка событий/атак за период для внешнего анализа
  - автоматизация отчётов и уведомлений
  - связка с SOAR/скриптами реагирования

## 8.5 Уведомления как канал интеграции

- e-mail, системный журнал (syslog), отображение в интерфейсе (раздел 14.13)
- два типа: результаты ретроспективного анализа и факт поступления/непоступления определённого трафика
