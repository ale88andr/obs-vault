# Шифрование через KSC

KES умеет шифровать файлы и диски (заявлено в архитектуре — [[0. Архитектура]]), KSC централизованно управляет ключами и восстановлением. Для контура с НСД это альтернатива/дополнение ручным мерам из [[Требования по защите от НСД]].

## Режимы шифрования KES

| Режим | Что делает | Когда выбирать |
| --- | --- | --- |
| **FLE (File Level Encryption)** | Шифрует файлы и папки по правилам политики (по расширению, пути, маске) | Нужна защита конкретных данных, диск общий с ОС |
| **FDD (Full Disk Encryption)** | Шифрует весь диск/том, включая загрузочный | Требование защиты устройства целиком (ноутбуки, выносные машины) |
| **Управление BitLocker** | KES управляет штатным BitLocker: включает, эскроуит ключи восстановления | Windows-парк со встроенным BitLocker; не хочется двойного шифрования |

Шифрование AES-256; расшифровка выполняется в фоне после снятия политики (данные не ломаются).

## Управление через политику

1. В политике KES раздел «Настройки → Шифрование данных»: выбрать режим и правила.
2. Обязательно закрыть настройки замком — иначе пользователь выключит ([[2. Настройка политик]]).
3. Ключи шифрования хранятся на Сервере администрирования; агент передаёт их защищённо.
4. **Эскроу ключей восстановления**: ключи восстановления BitLocker/FDD автоматически сохраняются в свойствах компьютера в консоли — это главный аргумент против локального включения шифрования пользователями.

## Восстановление

- Пользователь без прав администратора забыл пароль → администратор смотрит ключ восстановления в свойствах компьютера в Web Console.
- Потерян контакт с сервером → заранее настроенный механизм восстановления через агента/файл.
- Утилита расшифровки KES для аварийных случаев — держать дистрибутив под рукой.

## Типовые грабли

- FDD + сторонние дисковые утилиты/клонирование образов = риск потери данных; клонировать до шифрования или средствами, понимающими BitLocker.
- Двойное шифрование (BitLocker поверх FDD) не настраивать.
- На виртуальных машинах шифрование гостевых дисков усложняет снапшоты/бэкапы — свериться с [[Защита виртуализации]].
- Требования лицензии: функциональность шифрования доступна не во всех лицензиях — проверить до внедрения.

## Чеклист внедрения

- [ ] Выбрать режим (FLE / FDD / BitLocker) под тип устройств
- [ ] Тестовая группа из 5–10 машин, включая ноутбуки вне офиса (автономные политики — [[KSC Защита]], раздел 7)
- [ ] Проверен сценарий восстановления ключа из консоли
- [ ] Политика закрыта замком, самозащита включена
- [ ] Регламент: что делать при увольнении сотрудника / утилизации ноутбука
