# Автоматизация KSC (OpenAPI)

Web Console KSC предоставляет REST API по спецификации OpenAPI — база для скриптов массовых операций, которые неудобно делать руками.

## Начало работы

1. Спецификация OpenAPI скачивается с сервера Web Console (в консоли есть ссылка на описание API своей версии).
2. Базовый URL: `https://<адрес-сервера>:13299/api/v1.0/` — тот же порт, что и у Web Console ([[0. Архитектура]]).
3. Аутентификация: создать API-пользователя в консоли (отдельная учётка с минимальными правами), получить токен и передавать его в заголовке `Authorization`.

## Типовые сценарии

| Сценарий | Что даёт |
| --- | --- |
| Ежедневная выгрузка статусов защиты во внешний дашборд | Не открывать консоль ради «зелёных/красных» |
| Массовое создание групп/перемещение машин по списку из CMDB | Синхронизация структуры KSC с реальной инфраструктурой |
| Автоматическое создание задач для новых выборок | Стандартизация при онбординге новых сегментов |
| Экспорт отчётов в файлы/почту вне расписаний KSC | Гибкая рассылка руководству |

## Пример (паттерн)

```shell
# Получить список компьютеров (структура запроса зависит от версии API)
curl -sk "https://10.92.192.7:13299/api/v1.0/computers" \
  -H "Authorization: Bearer <TOKEN>"
```

```powershell
# PowerShell-вариант: обойти самоподписанный сертификат и забрать выборку
$response = Invoke-RestMethod -Uri "https://ksc.corp.local:13299/api/v1.0/computers" `
  -Headers @{ Authorization = "Bearer $token" } -SkipCertificateCheck
```

> [!warning] Точные пути эндпоинтов и поля зависят от версии KSC
> Всегда сверяться со скачанной спецификацией своей версии; структура ответов между мажорными версиями менялась. Токен хранить в секретах, не в скрипте.

## Правила безопасности

- Отдельная учётная запись для API, права только на нужные операции.
- Ограничить источники: порт 13299 наружу из сети администрирования не торчать ([[Цифровая зона]] — пример сегментации).
- Логировать вызовы; изменения через API попадают в журнал сервера так же, как интерактивные.
