# Интеграция KSC с SIEM

Как выгружать события Kaspersky Security Center во внешнюю систему мониторинга (KUMA, сторонний SIEM, syslog-коллектор).

## Что выгружать

Не всё подряд — сначала события с критичным уровнем важности. Минимальный набор (пересекается со списком из [[Рекомендации по ежедневному администрированию Kaspersky Security Center]]):

- Обнаружена активная угроза / требуется лечение активного заражения
- Обнаружен вредоносный объект (по KSN)
- Процесс завершён / обнаружена ранее открытая опасная ссылка
- Обнаружена сетевая атака
- Сработало правило Предотвращения вторжений
- Лицензионное ограничение превышено
- Изменение статуса защиты: программа не запущена / защита выключена
- Агент давно не подключался

## Форматы и транспорт

| Формат | Кому подходит |
| --- | --- |
| **CEF** | Дефолт для большинства SIEM (ArcSight-совместимые), KUMA умеет нативно |
| **LEEF** | IBM QRadar |

Транспорт — syslog: UDP/TCP/TCP+TLS на адрес коллектора, порт настраивается (классика — 514/6514). При TLS у KSC должен быть доверенный сертификат коллектора.

## Настройка в Web Console (порядок действий)

1. **Мониторинг и отчеты → Интеграция SIEM → Добавить SIEM** (в разных версиях путь может отличаться — искать «Интеграция SIEM»).
2. Указать формат CEF/LEEF, адрес, порт, транспорт.
3. Настроить **критерии отбора событий**: тип события + уровень важности (Critical обязательно; Warning по необходимости).
4. Ограничить частоту повторяющихся событий (rate limit), чтобы не залить коллектор при эпидемии.
5. Проверить приём на стороне SIEM тестовым событием.

## Со стороны KES

KES дополнительно пишет события в журнал Windows («Приложения», источник `Kaspersky Event Log`) — их можно собирать штатным Windows Event Forwarding параллельно с экспортом KSC. Это даёт события даже когда связь хоста с сервером потеряна.

## Проверка контура

1. Сгенерировать тестовое событие: запустить заведомо детектируемый тестовый файл (EICAR) на тестовой ВМ.
2. Убедиться, что событие дошло до SIEM за ожидаемое время и распарсилось в поля (host, threat name, verdict, user).
3. Проверить поведение при недоступности SIEM: буферизация на стороне KSC и последующая досылка.
