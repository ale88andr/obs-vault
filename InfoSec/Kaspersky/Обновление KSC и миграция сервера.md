# Обновление KSC и миграция сервера

Два пути смены версии/сервера администрирования и когда какой выбирать. База по резервному копированию — [[KSC Обслуживание]] (задача «Резервное копирование данных Сервера администрирования», утилита `klbackup.exe`).

## Путь 1: обновление поверх (in-place)

Стандартный сценарий: инсталлятор новой версии обнаруживает старую, обновляет компоненты, конвертирует настройки.

Порядок:
1. Прочитать release notes целевой версии: поддерживаемые пути обновления (обычно только с предыдущих N-версий), требования к ОС и СУБД.
2. **Полная резервная копия** сервера (задача klbackup) + дамп БД средствами СУБД.
3. Проверить восстановление из копии на тестовом стенде — до, а не после апгрейда.
4. Обновить сервер администрирования → затем Web Console.
5. Проверить службы (`systemctl status` для KSCLinux / `services.msc` для Windows), вход в консоль, синхронизацию тестового агента.
6. Агенты администрирования и KES обновляются отдельно, своими пакетами; сервер совместим с клиентами в диапазоне версий из release notes.

Для KSCLinux дополнительно: версии СУБД критичны ([[Развертывание Kaspersky Security Center]]: KSC 15 требует PostgreSQL 14 без МРД); журналы смотреть через `journalctl -u kladminserver_srv`.

## Путь 2: миграция через резервную копию

Когда нужен новый сервер (железо, ОС, переезд в другой сегмент):

1. Создать резервную копию старого сервера (klbackup).
2. Деинсталлировать старый сервер (или вывести из эксплуатации параллельно).
3. Установить новую версию на новом месте.
4. Восстановить конфигурацию из копии.

Ограничения и нюансы:
- Старый и новый серверы должны использовать **однотипный SQL-сервер** (оба Microsoft SQL или оба MySQL).
- Копия включает базу, структуру групп, задачи, политики, сертификат сервера, хранилище ключей шифрования; **не включает** обновления в хранилище (успеют устареть — не страшно).
- Сертификат сервера переносится вместе с копией — агенты не заметят подмены.
- Этот же путь позволяет заодно сменить аппаратную платформу и версию продукта.

## После любого пути

- Убедиться, что компьютеры синхронизировались (виджет «Состояние защиты»).
- Пересоздать/проверить задачу загрузки обновлений в хранилище (типовая проблема после миграций — [[Ошибка - Содержимое не готово]]).
- Обновить инсталляционные пакеты до актуальной версии.
- Зафиксировать новую версию и дату в регламенте ([[KSC Обслуживание]], раздел «раз в год»).

> [!tip] Чеклист перед началом работ
> - [ ] Резервная копия + проверенное восстановление
> - [ ] Окно обслуживания согласовано (агенты не смогут синхронизироваться)
> - [ ] Известен план отката (старая ВМ не удаляется до стабилизации)
> - [ ] Пароли сервисных учётных записей под рукой
