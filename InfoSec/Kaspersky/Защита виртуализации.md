# Защита виртуализации

Как защищать виртуальные и облачные среды средствами Kaspersky: три подхода, их границы и что из этого применимо к нашему стеку.

## Три подхода

| Подход | Как работает | Плюсы | Минусы |
| --- | --- | --- | --- |
| **Полный агент в каждой ВМ** | Обычный KES/KESL внутри гостевой ОС | Полный функционал KES; работает на любом гипервизоре | Расход ресурсов ВМ; AV-шторма при одновременных сканированиях |
| **Light Agent** | Лёгкий агент в ВМ, вся проверка выполняется на выделенной SVM (Security Virtual Machine) на хосте | Минимум нагрузки на гостевые ОС, централизованные SVM | Только поддерживаемые гипервизоры |
| **Agentless** | Сканирование дисков ВМ с хоста без агента вообще | Ноль агентов в ВМ | Нет защиты «на лету» — только по расписанию/по требованию |

## Kaspersky Security for Virtualization

- **Protection Server (SVM)** — виртуальный модуль с движком защиты; один обслуживает несколько десятков ВМ на хосте.
- **Integration Server** — связка с платформой виртуализации (vCenter, NSX) для автоматического размещения SVM и политик.
- Light Agent официально поддерживает VMware vSphere (в т.ч. через NSX) и Microsoft Hyper-V.

> [!warning] OpenStack и Kubernetes не входят в список поддерживаемых платформ KSV
> Для нашего стека ([[KESL Настройка Kaspersky Endpoint Security]] — nova, neutron, glance, cinder, qemu, containerd) единственный рабочий вариант — **полный агент KESL в каждой ноде** с правильно настроенными исключениями.

## Практика для нашего контура

1. KESL ставится на все ноды (управление через KSC, см. [[Установка klnagent]], [[Команды KESL]]).
2. Исключения для служб виртуализации и образов (`*.qcow2`, `*.raw`, `*.iso`, процессы `qemu*`, `containerd*`) — полный список в [[KESL Настройка Kaspersky Endpoint Security]]. Без них возможны деградация производительности гипервизорных операций и ложные срабатывания на образы дисков.
3. Задачи полного поиска вирусов на нодах выносить за пределы пиковых часов (см. регламент в [[KSC Обслуживание]]).
4. Следить за обновлением KESL: новые версии лучше дружат с новыми ядрами и container runtime.

## Анти-AV-шторм

Классическая проблема виртуальных сред — синхронные сканирования десятков ВМ одновременно:

- Разносить расписания задач проверки (случайное смещение старта).
- Не проверять неизменённые файлы (поведение по умолчанию KES).
- Использовать iSCSI/NAS-исключения только при уверенности в локальной защите хранилища.
