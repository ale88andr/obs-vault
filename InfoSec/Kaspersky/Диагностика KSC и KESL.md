# Диагностика KSC и KESL

Сводная шпаргалка: что запускать, когда что-то сломалось. Крупицы разбросаны по базе — здесь всё в одном месте.

## Агент администрирования (Windows)

Утилиты лежат в `%ProgramFiles(x86)%\Kaspersky Lab\NetworkAgent`:

| Утилита | Назначение |
| --- | --- |
| `klnagchk.exe` | Выводит настройки агента, тестирует связь с сервером, публикует результат и статистику подключений. Принудительная синхронизация: `klnagchk.exe -sendhb` |
| `klmover.exe` | Смена адреса сервера у агента: `klmover.exe -address 10.28.0.20` |

Диагностика «компьютер виден, но агент не выходит на связь» — пошагово в [[Рекомендации по ежедневному администрированию Kaspersky Security Center]].

## KES Windows

- Сбор данных для анализа: утилита **GetSystemInfo** (собирает конфигурацию, журналы, состояние служб).
- Трассировка включается в настройках самозащиты/поддержки; уровень детализации поднимать только по запросу техподдержки.
- Полное удаление нерабочей установки — **kavremover** (официальная утилита удаления).

## KESL (Linux)

```shell
# Статус приложения
kesl-control --app-info
# Статус службы
systemctl status kesl
```

- Уровень трассировки:

```shell
sudo /opt/kaspersky/kesl/bin/kesl-control --set-app-settings TraceLevel=Detailed
# вернуть обратно:
sudo /opt/kaspersky/kesl/bin/kesl-control --set-app-settings TraceLevel=NotDetailed
```

- Журналы и данные: `/var/opt/kaspersky/kesl/`; обновления: `/var/opt/kaspersky/kesl/common/updates` ([[Команды KESL]]).
- Проверка связи агента с сервером: `/opt/kaspersky/klnagent64/bin/klnagchk`.

## Сервер администрирования KSCLinux

```shell
# Журналы сервера
journalctl -u kladminserver_srv
# Статусы всех служб KSC
systemctl status klnagent_srv kladminserver_srv klactprx_srv klwebsrv_srv
```

Типовые проблемы после миграций/обновлений — [[Обновление KSC и миграция сервера]]; ошибка хранилища обновлений — [[Ошибка - Содержимое не готово]].

## Алгоритм первичной диагностики

1. Определить слой: нет связи с сервером → агент; защита не работает → KES; консоль/задачи → сервер.
2. Связь: `klnagchk` на клиенте; на сервере — порты ([[0. Архитектура]]) и firewall между сегментами ([[Цифровая зона]] как пример правил UFW/Континент).
3. Защита: статус в консоли → локальный интерфейс/`kesl-control --app-info`.
4. Собрать логи **до** перезапусков — половина улик теряется после рестарта службы.

> [!tip] Перед обращением в техподдержку
> Подготовить: версию продукта и сборку (`--app-info`), трассировку с момента воспроизведения, GetSystemInfo/sysdiagnose-аналог, описание сети (есть ли NAT, прокси, MTU нестандартный).
