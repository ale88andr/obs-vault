- **Вредоносное ПО (malware)** — программное обеспечение, намеренно разработанное для нарушения нормальной работы компьютеров, получения несанкционированного доступа, сбора конфиденциальной информации или нанесения другого ущерба.
- Основные признаки: **скрытность**, **автоматическое распространение**, **выполнение нежелательных операций**.

## Основные классы вредоносного ПО

| Тип | Характеристика | Примеры |
| --- | --- | --- |
| **Вирус** | Самореплицируется, внедряется в другие программы или файлы. Активируется при запуске заражённого ПО. | Brain, Melissa |
| **Червь** | Самостоятельно распространяется по сети, используя уязвимости ОС. Не требует действий пользователя. | Morris Worm (1988), Stuxnet |
| **Троян** | Маскируется под легитимное ПО, активируется пользователем. Даёт злоумышленнику доступ к системе. | Zeus Trojan |
| **RAT / бэкдор** | Троян удалённого администрирования: скрытый полный контроль над системой; стандартный инструмент APT-группировок. | Cobalt Strike, DarkComet |
| **Дроппер / загрузчик** | Сам не несёт полезной нагрузки — доставляет и запускает основной вредонос (первая стадия атаки). | Emotet, QakBot |
| **Шифровальщик (ransomware)** | Блокирует или шифрует данные, требует выкуп. Современные группы совмещают шифрование с утечкой данных (double extortion). | WannaCry (2017), LockBit, ALPHV/BlackCat |
| **Wiper** | Безвозвратно уничтожает данные и загрузчики; иногда маскируется под шифровальщик. | Shamoon, HermeticWiper |
| **Spyware** | Скрытно собирает данные о пользователе (пароли, сайты, клавиши). | CoolWebSearch, Pegasus |
| **Кейлогер** | Записывает нажатия клавиш и движения мыши. | Keylogger.Win32 |
| **Руткит** | Скрывает присутствие других вредоносных программ, обеспечивает скрытый доступ. | Sony Rootkit (2005) |
| **Bootkit** | Подкласс руткитов: заражает загрузочный уровень (MBR/UEFI), переживает переустановку ОС. | LoJax (UEFI), MoonBounce |
| **Fileless malware** | Работает напрямую в памяти или злоупотребляет легитимными системными инструментами; не оставляет файлов на диске. | Mimikatz, PowerShell Empire |
| **Криптомайнер** | Несанкционированно использует ресурсы ЦП/GPU для майнинга; один из самых частых инцидентов на корпоративных серверах. | XMRig, CoinMiner |
| **Bots (ботнет)** | Заражённые машины подчиняются C2-инфраструктуре злоумышленника и выполняют команды: DDoS, спам, проксирование трафика, кража данных. | Mirai, ZeuS P2P |
| **Adware / PUP** | Потенциально нежелательное ПО: навязчивая реклама, перехват браузера. Граничит с легитимным — частый источник споров «вирус это или нет». | Fireball, browser hijackers |

> [!note] Фишинг и spear phishing — не классы ВПО, а **векторы доставки**: см. [[#Векторы доставки и социальная инженерия]].

## Векторы доставки и социальная инженерия

| Вектор | Суть | Пример |
| --- | --- | --- |
| **Массовый фишинг** | Приманка рассылается широкой аудитории в расчёте на случайную жертву. | Поддельные письма «от банка» |
| **Spear phishing** | Целевая разновидность фишинга: персонализированные сообщения конкретным людям или организациям на основе собранной о жертве информации. Тщательно готовится, вероятность успеха выше массового. | BEC-атаки, первичный этап операций APT |
| **Watering hole** | Компрометация сайта, который регулярно посещают сотрудники целевой организации. | Атаки через отраслевые порталы |
| **Supply chain compromise** | Внедрение вредоноса на этапе сборки или доставки легитимного ПО. | SolarWinds SUNBURST |
| **Drive-by download** | Заражение при простом посещении скомпрометированного сайта через уязвимый браузер или плагин. | Эксплойт-киты (Angler) |
| **Съёмные носители** | Классика для изолированных (air-gapped) сетей, куда сеть не дотянется. | USB-инфекция Stuxnet |

## Основные методы выявления ВПО

| Метод | Принцип работы | Преимущества | Ограничения |
| --- | --- | --- | --- |
| **Сигнатурный анализ** | Сравнение файлов и процессов с базой известных сигнатур (хеши, шаблоны кода). | Высокая точность против известных угроз, быстрый и лёгкий. | Не выявляет новые угрозы (zero-day), уязвим к полиморфным вирусам и fileless malware. |
| **Эвристический анализ** | Поиск подозрительных свойств и поведения программ (статически и динамически). | Обнаружение новых и модифицированных угроз, эффективен против полиморфных вирусов. | Возможны ложные срабатывания, высокая нагрузка на систему, нет гарантии лечения. |
| **Статический анализ** | Изучение кода без запуска: структура файла, строки, импортируемые функции. | Безопасность (не запускается вредоносный код), быстрый обзор. | Не выявляет поведение, может быть обманут обфускацией или упаковкой. |
| **Динамический анализ** | Запуск ПО в песочнице и наблюдение за его действиями. | Позволяет увидеть реальное поведение, выявляет скрытые функции. | Требует изолированной среды, ресурсоёмкий, может быть обманут анти-анализными техниками. |
| **Гибридный анализ** | Комбинация статического и динамического подходов. | Более полная картина, высокая эффективность. | Сложность реализации, требует больше ресурсов. |
| **Поведенческий анализ** | Мониторинг действий программы в реальном времени (сетевые запросы, шифрование файлов). | Обнаружение аномалий, эффективен против неизвестных угроз. | Возможны ложные срабатывания, требует постоянного мониторинга. |
| **IoC-анализ** | Поиск индикаторов компрометации: хеши, IP, домены, ключи реестра. | Быстрое выявление заражений, интеграция с SIEM. | Эффективен только при наличии актуальных IoC, не выявляет новые угрозы. |
| **Облачная репутация** | Проверка файла, URL, издателя по облачной базе репутаций, агрегирующей данные с миллионов конечных точек. | Мгновенный вердикт без ожидания сигнатуры; новые угрозы «видны» сразу после первого появления у любого участника сети. | Зависимость от подключения к облаку, вопросы приватности передаваемых данных. |
| **Машинное обучение** | Классификация объектов моделями, обученными на больших выборках чистых и вредоносных файлов. | Выявление новых семейств без сигнатур, работа со статикой до запуска. | Ложные срабатывания, непрозрачность решения («чёрный ящик»), необходимость переобучения. |

## Технологии выявления в решениях Kaspersky

Теория выше реализована в продуктах линии конкретными компонентами — эти термины всплывут при настройке политик ([[KSC Защита]]):

- **KSN (Kaspersky Security Network)** — облачная репутация файлов, URL и издателей; мгновенный вердикт без ожидания локальной сигнатуры.
- **System Watcher** — поведенческий анализ на конечной точке + откат действий вредоноса (в том числе последствий шифровальщика).
- **Automatic Exploit Prevention (AEP)** — перехват эксплойтов на этапе использования уязвимостей приложений.
- **ML-классификаторы** — статические модели, дополняющие сигнатурный движок.
- **Контроль программ (Application Control)** — разрешающая модель запуска: всё неизвестное = заблокировано.
- **Веб-контроль и антифишинг** — репутационная фильтрация web-ресурсов.

Как KES проверяет файлы на практике — подробно в [[Как Kaspersky Endpoint Security проверяет файлы]].

## Техники уклонения от обнаружения

Почему «может быть обманут» встречается почти в каждой строке таблицы выше:

- **Полиморфизм** — при каждом заражении тело шифруется новым ключом, сигнатура меняется.
- **Метаморфизм** — вирус полностью переписывает собственный код, сохраняя функциональность.
- **Упаковщики и крипторы** — нагрузка сжимается/шифруется и раскручивается только в памяти; статический анализ видит «мусор».
- **Sandbox evasion** — детект виртуальной машины/песочницы, задержка активации по времени или числу запусков, проверка реальной активности пользователя, гео-привязка.
- **LOTL (Living Off The Land)** — использование легитимных инструментов (PowerShell, WMI, certutil) вместо собственных бинарников; нечего искать сигнатурой.
- **Tampering** — отключение защитных решений: остановка служб AV, удаление агентов, изменение настроек.

## IoC, IoA и TTP

Практическое правило — «пирамида боли» (Pyramid of Pain): чем выше уровень индикатора, тем дороже он обходится злоумышленнику и тем дольше живёт детект.

| Уровень | Что это | Живучесть |
| --- | --- | --- |
| **IoC** (Indicators of Compromise) | Хеши файлов, IP, домены, пути и ключи реестра. Хеш одного билда бесполезен после пересборки malware. | Часы–дни |
| **IoA** (Indicators of Attack) | Последовательности действий, указывающие на идущую атаку ещё до завершения компрометации. | Недели–месяцы |
| **TTP** (Tactics, Techniques, Procedures) | Тактики, техники и процедуры противника. Отраслевой стандарт описания — матрица **MITRE ATT&CK**: тактика = «зачем», техника = «как». | Годы |

Именно переход от погони за IoC к работе с TTP отличает мышление SOC от классического антивирусного подхода.

## EDR vs Антивирус

|Характеристика|**Антивирус**|**EDR**|
|---|---|---|
|**Принцип работы**|Сигнатурное и эвристическое выявление известных угроз.|Поведенческий анализ, мониторинг активности, реагирование на инциденты.|
|**Цель**|Предотвращение заражения и удаление вредоносного ПО.|Обнаружение сложных атак, расследование и реагирование.|
|**Уровень защиты**|Базовый — против вирусов, троянов, червей.|Продвинутый — против APT, fileless malware, zero-day атак.|
|**Методы**|Сканирование файлов, проверка хешей, сигнатур.|Логирование событий, анализ процессов, сетевой активности, IoC.|
|**Реакция на угрозы**|Автоматическое удаление или карантин.|Аналитика, расследование, автоматизированное или ручное реагирование.|
|**Подходит для**|Домашних пользователей и базовой корпоративной защиты.|Средних и крупных организаций, SOC, критической инфраструктуры.|
|**Примеры решений**|Kaspersky, ESET, Avast.|CrowdStrike Falcon, SentinelOne, Microsoft Defender for Endpoint.|

## Эволюция решений: AV → NGAV → EDR → XDR → MDR

Таблица выше фиксирует два полюса, но рынок давно движется между ними и дальше:

| Решение | Суть | Примеры |
| --- | --- | --- |
| **Классический AV** | Сигнатуры + базовая эвристика, реактивная модель обновлений. | — |
| **NGAV** | AV нового поколения: облако, ML, поведение, exploit prevention; ставка на предотвращение. | KES, CrowdStrike Falcon Prevent |
| **EDR** | Телеметрия конечных точек, расследование инцидентов, реагирование. | Kaspersky EDR, SentinelOne |
| **XDR** | EDR + корреляция данных из сети, почты, identity в единой платформе. | Kaspersky XDR |
| **MDR** | Управляемый сервис: внешний SOC мониторит и реагирует на базе EDR/XDR клиента. | Kaspersky MDR |

Соответствие в экосистеме Kaspersky: **KES** (endpoint) → **KEDR** → **KXDR**; сетевой уровень и песочница — **KATA** (Anti Targeted Attack); централизованный сбор и корреляция событий — SIEM **KUMA**.

## Ключевые отличия

- Антивирус работает **превентивно**, блокируя известные угрозы.
- EDR работает **реактивно и проактивно**: выявляет аномалии, расследует инциденты, помогает реагировать на сложные атаки.
- Антивирус — это «щит», а EDR — «щит + система видеонаблюдения + команда реагирования».

## Карантин и лечение

- **Карантин** — изоляция объекта в защищённом контейнере с возможностью восстановления: объект может оказаться ложным срабатыванием.
- **Дезинфекция** — попытка вылечить заражённый файл, удалив вредоносную вставку; применима не ко всем типам ВПО.
- Для троянов и шифровальщиков лечение обычно невозможно — только удаление объекта и восстановление данных из резервных копий.
- **Откат изменений** — System Watcher умеет отменять действия вредоноса в системе после факта заражения.
- Корпоративная практика: хост с подтверждённой компрометией — недоверенный хост. Переустановка ОС надёжнее «лечения».

## Место антивируса в защите

Антивирус — один слой эшелонированной обороны [[Defense in Depth]]. Сетевые средства ([[IPS, IDS, UTM]]), патч-менеджмент, контроль доступа и процессы обработки [[Инциденты ИБ]] работают только в связке с ним.
