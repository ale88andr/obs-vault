# Компоненты ОС Microsoft Windows

Если вы специалист по безопасности, то вам потребуется часто анализировать хосты, если будет замечена подозрительная активность. Чтобы дольше оставаться незамеченными, злоумышленники зачастую используют совершенно легитимные инструменты и процессы, которые можно найти в любой ОС **Microsoft Windows**.

Поэтому важно понимать, как Windows обрабатывает процессы и какие встроенные инструменты может использовать специалист по безопасности для анализа активностей на хосте.

---

## Процессы, потоки и службы

В Windows, когда приложение запущено, оно создает процесс. Обычно приложение может иметь один или несколько выделенных ему процессов. **Процесс** — это все ресурсы, необходимые для обеспечения возможности выполнения/запуска приложения в операционной системе хоста. Представьте, что вы открываете диспетчер задач, чтобы проверить производительность вашего компьютера. Операционная система создаст процесс со всеми необходимыми ресурсами для этого приложения.

![[Pasted image 20240122102938.png]]

Как показано на предыдущем рисунке, диспетчер задач — это служебная программа, которая предоставляет информацию о процессах, службах и производительности устройства. На вкладке «Процессы» вы увидите список всех запущенных в данный момент приложений в операционной системе хоста, список фоновых процессов и ресурсы, которые выделяются каждому приложению (ЦП, память).

### Фоновые процессы и службы

Фоновые процессы в Windows выполняются как службы. **Служба** — это программа, которая выполняется в фоновом режиме операционной системы, обеспечивая поддержку приложения и/или операционной системы. Эти службы можно настроить на автоматический запуск при загрузке Windows. Вы можете запускать, останавливать и перезапускать службу вручную.

![[Pasted image 20240122102954.png]]

На предыдущем рисунке показан список служб в операционной системе хоста. Здесь вы можете настроить свойства службы в Windows. Дважды щелкнув на службу, откроется окно свойств.

![[Pasted image 20240122103008.png]]

Как показано на предыдущем рисунке, вы можете настроить тип запуска службы:

| Тип запуска | Описание |
| --- | --- |
| **Автоматически** | Служба запускается при старте Windows |
| **Вручную** | Служба запускается только по запросу |
| **Отключена** | Служба не может быть запущена |
| **Автоматически (отложенный запуск)** | Служба запускается через небольшое время после загрузки Windows |

### Процессы и потоки

Каждое приложение создает родительский процесс с одним или несколькими дочерними процессами, иногда называемыми потоками. Каждый дочерний процесс или поток отвечает за функцию, обеспечивающую выполнение приложения. Когда приложение выполняется в операционной системе Microsoft Windows, родительский процесс использует API-вызов **`CreateProcess()`**, который позволяет родительскому процессу для запущенного приложения создать один или несколько дочерних процессов.

> [!important] Примечание
> В отличие от Unix/Linux, где используется системный вызов `fork()`, в Windows для создания процессов применяется `CreateProcess()` — это принципиальное различие архитектур двух семейств ОС.

Однако имейте в виду, что у дочернего процесса может быть только один родительский процесс, а у родительского процесса может быть несколько дочерних процессов.

Когда приложение выполняется операционной системой или пользователем, операционная система задействует физическую память из оперативной памяти и создает виртуальную память для выделения запущенному процессу или дочернему процессу. Таким образом, процессы выполняются в виртуальном адресном пространстве операционной системы.

> [!important] Важное примечание
> Операционная система Windows управляет выделением виртуальной памяти процессу.

Иногда, когда приложение закрывается, родительский процесс и все дочерние процессы завершаются, тем самым высвобождая ресурсы обратно операционной системе. Однако родительский процесс может завершиться, пока дочерние процессы остаются активными. В этой ситуации виртуальная память и любые другие ресурсы по-прежнему выделяются каждому дочернему процессу. Дочерний процесс, у которого нет родительского процесса, называется сиротским процессом (**orphan process**). Пользователь может вручную завершить дочерний процесс в диспетчере задач или выполнить перезагрузку системы. Перезагрузка системы завершит все процессы и перезагрузит операционную систему.

## Файл подкачки Windows

По мере того, как в память загружается больше приложений, операционная система выделяет части физической памяти (ОЗУ) каждому процессу, используя виртуальную память. Каждый родительский процесс и его дочерние процессы выполняются в одном виртуальном адресном пространстве в операционной системе хоста. Как уже упоминалось, за выделение памяти отвечает операционная система, однако есть некоторые приложения, которым для бесперебойной работы требуется намного больше памяти, чем другим, и это может создать нехватку доступной памяти для других приложений.

Операционная система Windows использует часть памяти из другой области, с жесткого диска или SSD. Windows берет небольшую часть памяти с локального диска и преобразует ее в виртуальную память. Это называется **файлом подкачки**.

Файл подкачки позволяет операционной системе хоста использовать эту часть памяти для загрузки приложений и, следовательно, снижает нагрузку на физическую память (ОЗУ) в системе.

### Настройка файла подкачки

Чтобы получить доступ к настройкам файлов подкачки:

1. Щёлкните значок Windows в нижнем левом углу экрана и выберите *Система*. Откроется окно «Система». Слева выберите пункт «Дополнительные параметры системы».
2. Откроется окно «Свойства системы». Выберите пункт «Дополнительно» и нажмите «Параметры» в разделе «Быстродействие»:

![[Pasted image 20240122103250.png]]

3. Откроется окно параметров быстродействия. Чтобы изменить размер файла подкачки, нажмите «Изменить…»:

![[Pasted image 20240122103315.png]]

Вам будет предоставлена возможность настроить размер файла подкачки для всех дисков в локальной системе. Размер файла подкачки по умолчанию зависит от объема оперативной памяти хост-системы. Операционная система Windows 10 автоматически управляет размером файла подкачки в зависимости от конфигурации хоста и объема оперативной памяти в системе.

> [!tip] Связь с безопасностью
> Файл подкачки (`pagefile.sys`) может содержать остатки данных из оперативной памяти, включая пароли, ключи шифрования и другой конфиденциальный контент. При расследованиях анализ swap-файла может дать ценную информацию. Для полного удаления данных рекомендуется настроить автоматическую очистку при завершении работы или использовать шифрование (BitLocker).

## Реестр Windows

Вся информация о конфигурациях и настройках операционной системы Windows и ее пользователей хранится в базе данных, известной как **реестр** (**registry**). Самый высокий уровень реестра известен как куст. В реестре Windows есть пять кустов, и каждое значение данных хранится в разделе или подразделе куста. Древо (куст) реестра — это подмножество разделов, подразделов и параметров реестра, которому сопоставлен набор вспомогательных файлов, содержащих резервные копии этих данных.

### Пять кустов реестра

| Куст | Описание |
| --- | --- |
| `HKEY_CLASSES_ROOT` (HKCR) | Отвечает за правильное выполнение всех текущих приложений в проводнике Windows. Содержит сведения о ярлыках и правилах перетаскивания |
| `HKEY_CURRENT_USER` (HKCU) | Хранит информацию о текущей учетной записи пользователя: настройки панели управления, папок и персонализации |
| `HKEY_LOCAL_MACHINE` (HKLM) | Хранит специфичные для оборудования детали: конфигурация системы, подключенные диски, программное обеспечение |
| `HKEY_USERS` (HKU) | Содержит данные конфигурации профилей всех пользователей в локальной системе |
| `HKEY_CURRENT_CONFIG` (HKCC) | Содержит подробную информацию о текущих конфигурациях системы |

Для доступа к реестру используйте **Registry Editor** (`regedit`) в строке поиска Windows.

![[Pasted image 20240122103340.png]]

Как показано на предыдущем рисунке, каждый куст находится на верхнем уровне. Если вы развернете куст, вы увидите папки, а в каждой папке есть ключи, которые содержат сведения о конкретной функции или конфигурации в операционной системе.

### LastWrite — метка времени

В каждом ключе реестра есть значение, известное как **LastWrite**, которое указывает время последнего изменения объекта или файла. Эта информация может использоваться для определения времени инцидента или события, связанного с безопасностью.

### Точки автозагрузки в реестре (Persistence)

В реестре также содержатся сведения о приложениях, которые запускаются автоматически со стартом системы — **AutoRun**. Для закрепления в системе злоумышленники часто модифицируют ветки реестра, которые отвечают за автоматический запуск процессов и сервисов, и добавляют в них ссылки на вредоносные программы, чтобы они каждый раз запускались со стартом системы и могли пережить перезагрузку.

> [!warning] Точки Persistence
> Злоумышленники часто используют реестр для постоянного доступа к системе. Ниже перечислены основные ветки, отвечающие за автоматический старт приложений и сервисов:

**HKLM (для всех пользователей):**
- `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`
- `HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce`
- `HKLM\Software\Microsoft\Windows\CurrentVersion\RunServices`
- `HKLM\Software\Microsoft\Windows\CurrentVersion\RunServicesOnce`

**HKCU (для текущего пользователя):**
- `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
- `HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce`
- `HKCU\Software\Microsoft\Windows\CurrentVersion\RunServices`
- `HKCU\Software\Microsoft\Windows\CurrentVersion\RunServicesOnce`

**Дополнительные точки автозагрузки:**
- `HKLM\Software\Microsoft\Windows NT\CurrentVersion\Winlogon\Userinit` — программы, запускаемые при входе пользователя
- `HKCU\Software\Microsoft\Windows NT\CurrentVersion\Windows` — программа, запускаемая при входе
- `HKLM\Software\Microsoft\Windows NT\CurrentVersion\Winlogon\Shell` — оболочка Windows (по умолчанию `explorer.exe`)
- `HKLM\System\CurrentControlSet\Services` — все установленные службы
- `HKLM\Software\Microsoft\Windows\CurrentVersion\Explorer\Shell Folders` — папки автозагрузки

**Пример:** чтобы при каждом старте Windows запускался блокнот, в ветку `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` можно добавить новое значение:

```
"Notepad"="C:\Windows\notepad.exe"
```

### Ключи реестра, важные для расследований

- `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` — список установленных программ
- `HKLM\SYSTEM\CurrentControlSet\Control\ComputerName` — имя компьютера
- `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProfileList` — профили пользователей и SID
- `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\AutoplayHandlers` — обработчики автозапуска
- `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\AppCompatCache` — кэш совместимости приложений (сользуйся для обхода AppLocker)
- `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options` —可用于 перехвата запуска процессов (Image File Execution Options debugging)

## Windows Management Instrumentation (WMI)

Управлять несколькими компьютерами с ОС Windows в небольшой сети очень просто. Однако по мере роста сети и подключения все большего числа устройств на базе Windows управление политиками и службами на уровне приложений может стать сложной задачей. **Windows Management Instrumentation** (WMI) — это инструмент, встроенный в операционную систему Windows, который позволяет системному администратору или специалисту по безопасности управлять многими системами на базе Windows в корпоративной сети.

WMI — это функция администрирования Windows, которая обеспечивает единую среду для локального и удаленного доступа к системным компонентам Windows, а также позволяет собирать статистическую информацию об удаленных компьютерах в вашей сети. Вы сможете собирать статистику как по оборудованию, так и по программному обеспечению и даже отслеживать состояние каждого устройства.

### Открытие WMI

1. Откройте приложение *Computer Management* (Управление компьютером) в Windows 10/Server 2019.
2. Слева разверните «Службы и приложения».
3. Щёлкните правой кнопкой мыши элемент управления WMI и выберите «Свойства».

![[Pasted image 20240122103427.png]]

### WMI и безопасность

Злоумышленники могут использовать инструментарий управления Windows (WMI) для удаленного управления. WMI работает через протоколы **SMB** и службу удаленного вызова процедур (**RPC**) для удаленного доступа. RPC работает через порт **135** (Endpoint Mapper).

> [!warning] WMIC deprecated
> Утилита командной строки **WMIC** (`wmic process call create`) deprecated начиная с Windows 10 21H1. Вместо неё рекомендуется использовать PowerShell cmdlets:
> - `Get-CimInstance` — получение информации через WMI
> - `Get-WmiObject` — устаревший, но всё ещё работающий вариант
> - `Invoke-CimMethod` — вызов методов WMI

**Примеры PowerShell-команд для работы с WMI:**

```powershell
# Получение списка процессов
Get-CimInstance -ClassName Win32_Process | Select-Object Name, ProcessId, ParentProcessId

# Получение информации об операционной системе
Get-CimInstance -ClassName Win32_OperatingSystem | Select-Object Caption, Version, BuildNumber

# Создание процесса (аналог wmic process call create)
Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{CommandLine="notepad.exe"}

# Получение списка установленного ПО
Get-CimInstance -ClassName Win32_Product | Select-Object Name, Version
```

### WMI-Persistence

> [!danger] WMI-Persistence
> Злоумышленники могут создавать WMI-провайдеры и подписки (-event subscriptions) для постоянного доступа. WMI-Persistence работает через три компонента:
> - **Event Filter** — условие срабатывания (например, при запуске системы)
> - **Event Consumer** — действие при срабатывании (запуск вредоносного кода)
> - **FilterToConsumerBinding** — привязка фильтра к обработчику

Этот метод persistence особенно опасен, так как:
- Не создаёт новых ключей в Run/RunOnce
- Может быть обнаружен только через специализированные инструменты
- Переживает перезагрузку системы

Для поиска WMI-persistence можно использовать:

```powershell
# Поиск подписок WMI
Get-WMIObject -Namespace root\Subscription -Class __EventFilter
Get-WMIObject -Namespace root\Subscription -Class __EventConsumer
Get-WMIObject -Namespace root\Subscription -Class __FilterToConsumerBinding
```

Использование WMI должно быть ограничено и ограничиваться только авторизованными пользователями, внимательно следя за его использованием.

## Инструменты мониторинга

### Resource Monitor и Performance Monitor

В операционной системе Windows существует множество инструментов мониторинга, которые специалист по безопасности может использовать для мониторинга различных ресурсов и действий на устройстве.

**Performance Monitor** (Монитор производительности) позволяет пользователю собирать более подробные данные, чем Resource Monitor. Монитор производительности — это основной инструмент, используемый как в Windows 10, так и в Windows Server. Специалист по безопасности может использовать этот инструмент для сбора статистики о системе за различные периоды времени, например, часы или дни. Затем собранные данные можно проанализировать на предмет любых аномалий.

![[Pasted image 20240122103452.png]]

**Монитор стабильности системы** позволяет специалисту по безопасности просматривать историю проблем, возникших в основной системе в течение нескольких дней или недель. Пользователь может нажать на событие в инструменте, чтобы получить подробную информацию о проблеме, и существует система оценок от 1 до 10, отражающая серьёзность проблемы.

![[Pasted image 20240122103506.png]]

Как показано на предыдущем рисунке, в системе произошел ряд критических событий за определенный период времени. Выбрав событие, монитор покажет подробную информацию о службе или приложении, вызвавшем событие, сводку и время его возникновения. Специалист по безопасности может использовать статистику и информацию, найденные здесь, чтобы лучше понять, вызвало ли вредоносное ПО или неавторизованные приложения нарушение безопасности в хост-системе.

## Журналирование событий (Event Viewer)

Когда в системе Windows происходит какое-либо событие, создается сообщение журнала о данном событии. Инструмент, позволяющий анализировать данные события — **Event Viewer**. Event Viewer содержит журналы безопасности, приложений и системных событий.

Представьте, что злоумышленник пытается войти в учетную запись пользователя с неверными учетными данными. Для каждой попытки создастся событие сообщения журнала, и по этим данным можно будет обнаружить атаку.

### Основные журналы событий

| Журнал | Описание |
| --- | --- |
| **Security** (Безопасность) | Хранит события безопасности: входы, аудит, доступ к объектам |
| **Application** (Приложение) | Хранит журналы приложений в системе и установленного ПО |
| **Setup** (Установка) | Хранит сведения об установке ОС и обновлений |
| **System** (Система) | Хранит сведения о работе самой системы |
| **Windows PowerShell** | Журналы PowerShell-сессий |
| **Sysmon** | Журналирование Sysmon (требует установки) |

![[Pasted image 20240122103527.png]]

Если вы развернете категорию, такую как **Безопасность**, вы увидите список всех журналов, связанных с безопасностью.

![[Pasted image 20240122103540.png]]

Информация, содержащаяся в сообщениях журнала, помогает специалисту по безопасности определить, что, когда и как произошел инцидент в системе.

### Важные коды событий (Event ID)

> [!info] Коды событий безопасности
> Обратите внимание на код события — **4624**. Этот код соответствует успешному входу в систему Windows. В случае неуспешного входа сгенерируется событие с кодом **4625**. Данные события также будут содержать другую полезную информацию: имя пользователя, информацию о системе, тип входа (интерактивный, удалённый, сетевой, вход сервиса), процесс входа, ID входа и другое.

| Event ID | Описание |
| --- | --- |
| **4624** | Успешный вход в систему |
| **4625** | Неуспешный вход в систему |

| **4634 / 4647** | Выход из системы |
| **4778** | Переподключение к сессии RDP |
| **4779** | Отключение от сессии RDP |

### Настройка аудит-политики

Для полноценного журналирования необходимо настроить **политику аудита** через `secpol.msc` или `gpedit.msc`:

1. Откройте `secpol.msc` (Local Security Policy).
2. Перейдите в **Local Policies** → **Audit Policy**.
3. Включите аудит для нужных категорий:
   - **Audit logon events** — входы в систему (успех/неудача)
   - **Audit account logon events** — аутентификация учётных записей
   - **Audit object access** — доступ к файлам и объектам
   - **Audit process tracking** — отслеживание процессов
   - **Audit privilege use** — использование привилегий
   - **Audit policy change** — изменение политик
   - **Audit system events** — системные события

### Утилиты командной строки для работы с журналами

```powershell
# Экспорт журнала безопасности в XML
wevtutil epl Security C:\temp\security.evtx

# Просмотр последних 50 событий входа
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4624} -MaxEvents 50

# Поиск событий за определённый период
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625; StartTime='2024-01-01'; EndTime='2024-01-31'}

# Подсчёт событий по типу
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4624} | Group-Object -Property { $_.Properties[8].Value } | Sort-Object Count -Descending

# Очистка журнала (требует прав администратора)
wevtutil cl Security
```

## Sysinternals Suite

**Sysinternals Suite** — это набор бесплатных утилит от Microsoft, которые являются незаменимыми инструментами для анализа и диагностики Windows. Скачать можно с [официального сайта Microsoft](https://docs.microsoft.com/en-us/sysinternals/downloads/).

### Ключевые инструменты

#### Process Explorer

**Process Explorer** (`procexp`) — расширенная замена диспетчера задач. Показывает:
- Иерархию процессов (родитель → дочерний)
- Дескрипторы и DLL-библиотеки, загруженные каждым процессом
- Процессы, держащие файловые блокировки
- Информацию о владельце процесса

**Применение в безопасности:** обнаружение вредоносных процессов, маскирующихся под легитимные, поиск процессов с открытыми сетевыми соединениями.

#### Process Monitor

**Process Monitor** (`procmon`) — мониторинг активности файловой системы, реестра и сети в реальном времени. Показывает:
- Все обращения к файлам и папкам
- Все операции с реестром
- Все сетевые соединения
- Все операции с процессами

**Применение в безопасности:** отслеживание поведения подозрительного ПО, анализ всех действий приложения, поиск скрытых операций.

#### Autoruns

**Autoruns** (`autoruns`) — самый полный инструмент для анализа всех точек автозагрузки в Windows. Показывает все места, где ПО может注册 себя для автозапуска:
- Реестр (Run, RunOnce, Services, и т.д.)
- Планировщик задач
- Службы
- Папки автозагрузки
- Драйверы
- Логон-скрипты
- Winlogon-компоненты
- AppInit_DLLs
- и many more

**Применение в безопасности:** поиск persistence-механизмов, используемых злоумышленниками.

#### Другие важные инструменты

| Инструмент | Назначение |
| --- | --- |
| **PsExec** (`psexec`) | Запуск процессов на удалённых системах (часто используется в атаках — PsExec lateral movement) |
| **TCPView** | Просмотр активных сетевых соединений с указанием процессов |
| **Autoruns** | Анализ всех точек автозагрузки |
| **Strings** | Поиск строк в двоичных файлах |
| **Handle** | Просмотр открытых дескрипторов |
| **AccessChk** | Проверка прав доступа к объектам |
| **Sigcheck** | Проверка цифровых подписей файлов |
| **LiveKd** | Отладка работающей системы |
| **RAMMap** | Анализ использования физической памяти |
| **VMMap** | Анализ виртуальной памяти процесса |

## PowerShell как инструмент анализа

**PowerShell** — это не только среда автоматизации, но и мощный инструмент для анализа системы. Специалист по безопасности должен уметь использовать PowerShell для сбора данных о системе.

### Основные команды для анализа

```powershell
# Процессы
Get-Process | Select-Object Name, Id, CPU, WorkingSet64 | Sort-Object CPU -Descending

# Службы
Get-Service | Where-Object {$_.Status -eq "Running"} | Select-Object Name, DisplayName, StartType

# Сетевые соединения
Get-NetTCPConnection | Select-Object LocalAddress, LocalPort, RemoteAddress, RemotePort, State, OwningProcess

# Прослушивающие порты (listening)
Get-NetTCPConnection -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess

# Установленное ПО
Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\* | Select-Object DisplayName, DisplayVersion, Publisher

# Информация о системе
Get-CimInstance Win32_OperatingSystem | Select-Object Caption, Version, BuildNumber, OSArchitecture

# Запланированные задачи
Get-ScheduledTask | Where-Object {$_.State -ne "Disabled"} | Select-Object TaskName, TaskPath, State

# Пользователи и группы
Get-LocalUser | Select-Object Name, Enabled, LastLogon
Get-LocalGroupMember -Group "Administrators"
```

### PowerShell и безопасность

> [!warning] PowerShell как вектор атаки
> PowerShell активно используется злоумышленниками для:
> - Download cradles (загрузка вредоносного кода из интернета)
> - Обход AppLocker через `powershell.exe -ep bypass`
> - Encoded commands (`-enc`)
> - Reflective DLL injection
> - Fileless-атаки (код выполняется только в памяти)

Для защиты рекомендуется:
- Включить **Constrained Language Mode** для ограничения возможностей PowerShell
- Включить **Script Block Logging** (Policy Based)
- Включить **Module Logging**
- Настроить **AppLocker** для ограничения скриптов

```powershell
# Включение Script Block Logging через реестр
Set-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" -Name "EnableScriptBlockLogging" -Value 1

# Просмотр текущего языкового режима
$ExecutionContext.SessionState.LanguageMode

# Включение Constrained Language Mode (требует перезапуска PowerShell)
$ExecutionContext.SessionState.LanguageMode = "ConstrainedLanguage"
```

## Sysmon (System Monitor)

**Sysmon** — это бесплатный инструмент Microsoft, который расширяет возможности журналирования Windows. В отличие от стандартного журналирования, Sysmon предоставляет детальную информацию о:
- Создании и завершении процессов
- Создании потоков в процессах
- Загрузке образов в процессы
- Изменении целостности файлов
- Сетевых подключениях
- Доступе к_REGISTRY_
- Именовании именованных пайпов
- Событиях WMI
- и другие

### Установка и настройка

Sysmon устанавливается через командную строку:

```cmd
sysmon64.exe -i
```

Конфигурация задаётся через XML-файл:

```xml
<Sysmon schemaversion="4.90">
  <HashAlgorithms>md5,sha256</HashAlgorithms>
  <EventFiltering>
    <ProcessCreate onmatch="exclude">
      <Image condition="is">C:\Windows\System32\svchost.exe</Image>
    </ProcessCreate>
    <NetworkConnect onmatch="include">
      <DestinationPort condition="is">4444</DestinationPort>
    </NetworkConnect>
  </EventFiltering>
</Sysmon>
```

### Полезные Event ID Sysmon

| Event ID | Описание |
| --- | --- |
| **1** | Создание процесса (полная командная строка) |
| **2** | Изменение времени создания файла (Timestomping) |
| **3** | Сетевое соединение |
| **6** | Загрузка драйвера (DRIVER_LOAD) |
| **7** | Загрузка DLL в процесс |
| **8** | Создание потока в远程 процессе (Remote thread) |
| **10** | Открытие процесса (ProcessAccess) |
| **11** | Создание файла |
| **12 / 13 / 14** | Создание / изменение / удаление ключа реестра |
| **15** | Добавление в AppCompatCache |
| **17 / 18** | Создание / открытие именованного пайпа |
| **22** | DNS-запрос |
| **23** | Закрытие потока файла |

## NTFS и разрешения файловой системы

**NTFS** (New Technology File System) — основная файловая система Windows, которая предоставляет расширенные возможности безопасности.

### ACL (Access Control Lists)

Каждый объект NTFS (файл, папка, реестр) имеет связанный **DACL** (Discretionary Access Control List), который определяет, какие учётные записи и группы имеют доступ к объекту и какой тип доступа им разрешена.

Типы доступа:
- **Read** — чтение
- **Write** — запись
- **Execute** — выполнение
- **Full Control** — полный контроль
- **Modify** — изменение
- **List Folder Contents** — просмотр содержимого папки

### Анализ разрешений

```powershell
# Просмотр ACL файла
Get-Acl "C:\path\to\file" | Format-List

# Просмотр разрешений папки с наследованием
icacls "C:\path\to\folder" /T

# Поиск файлов с небезопасными разрешениями (например, Everyone: Full Control)
Get-ChildItem -Path C:\ -Recurse -ErrorAction SilentlyContinue | Where-Object { (Get-Acl $_.FullName).Access | Where-Object { $_.IdentityReference -eq "BUILTIN\Users" -and $_.FileSystemRights -match "FullControl" } }
```

> [!danger] Уязвимости файловых разрешений
> Злоумышленники могут эксплуатировать неправильные разрешения NTFS для:
> - **DLL hijacking** — подмена DLL-библиотек в папках с низкими правами
> - **Unquoted service paths** — эксплуатация не quotes путей к сервисам
> - **Modifiable service executable** — замена исполняемого файла сервиса
> - **Token impersonation** — получение токенов с повышенными привилегиями

### sysseccheck / AccessChk

Для поиска уязвимых разрешений можно использовать `AccessChk` из Sysinternals:

```cmd
:: Поиск сервисов с modifiable executable
accesschk.exe /accepteula -quvcvw "Authenticated Users"

:: Поиск папок с Everyone: Full Control
accesschk.exe -w -s -q "C:\Program Files" "Everyone"

:: Поиск сервисов с weak permissions
accesschk.exe /accepteula -uvwqk "Services"
```

## User Account Control (UAC)

**UAC** — механизм безопасности Windows, который предотвращает неавторизованные изменения в системе. При попытке выполнения действия, требующего повышенных привилегий, Windows запрашивает подтверждение у пользователя.

### Режимы UAC

| Уровень | Описание |
| --- | --- |
| **Всегда уведомлять** | Запрос при любых изменениях |
| **Уведомлять, но не блокировать рабочий стол** | Запрос с затемнением экрана |
| **Уведомлять только при попытках запуска приложений** | Запрос только при запуске программ |
| **Никогда не уведомлять** | UAC отключён (небезопасно) |

### Bypass UAC

> [!danger] Обходы UAC
> Существует множество методов обхода UAC:
> - **Fodhelper.exe** — trusted binary, который можно использовать для bypass
> - **Event Viewer** —trusted binary для bypass UAC
> - **ComputerDefaults.exe** — для обхода UAC
> - **SDCLT.exe** — ещё один trusted binary
> - Многие другие trusted binaries, которые можно использовать

Однако важно понимать, что UAC — это **не** механизм аутентификации, а механизм **интеграции**. Уровень	auto-elevation зависит от настроек UAC и типа приложения (native vs. managed).

## Windows Defender и AMSI

**Windows Defender** — встроенный антивирус Windows. Для специалиста по безопасности важно знать:

- **AMSI** (Antimalware Scan Interface) — интерфейс, который позволяет приложениям отправлять контент для анализа в антивирус перед выполнением. PowerShell, VBScript, JScript и другие скриптовые языки используют AMSI для проверки кода перед выполнением.

### Основные компоненты

| Компонент | Назначение |
| --- | --- |
| **Real-Time Protection** | Проверка файлов в реальном времени |
| **Cloud Protection** | Проверка в облаке Microsoft |
| **AMSI** | Интерфейс для проверки скриптов и кода |
| **Exploit Protection** | Защита от эксплойтов |
| **Network Protection** | Защита от вредоносных сайтов |
| **Controlled Folder Access** | Защита папок от шифровальщиков |

### PowerShell и AMSI

```powershell
# Проверка состояния Windows Defender
Get-MpPreference

# Добавление исключения
Add-MpPreference -ExclusionPath "C:\Malware"

# Просмотр последних обнаружений
Get-MpThreatDetection

# Просмотр истории защит
Get-MpThreat | Select-Object ThreatName, IsActive
```

> [!warning] AMSI Baiting
> Существует множество техник обхода AMSI (AMSI bypass), которые активно используются злоумышленниками. Однако MSDN и Microsoft активно патчат обнаруженные обходы. Каждый обход AMSI — это temporary — Microsoft быстро выпускает исправления.

```powershell

```

Здесь можно настроить:
- Входящие правила (Inbound Rules)
- Исходящие правила (Outbound Rules)
- Правила для программ
- Правила для портов
- Правила для служб
- Секции безопасности (Connection Security Rules)

## Credential Guard и защита учётных данных

**Credential Guard** — технология Windows, которая использует виртуализацию для защиты учётных данных отвлечения (credential theft).

### Как работает Credential Guard

Credential Guard изолирует **LSASS** (Local Security Authority Subsystem Service) в отдельном контейнере virtualization-based security (VBS), что делает невозможным чтение хешей паролей из памяти процесса lsass.exe.

### Основные угрозы учётным данным

| Атака | Описание |
| --- | --- |
| **Mimikatz** | Инструмент для извлечения хешей паролей из LSASS |
| **Pass-the-Hash** | Использование хеша пароля без знания самого пароля |
| **Pass-the-Ticket** | Использование Kerberos-тикетов |
| **Kerberoasting** | Запрос服务票ей для offline-атаки |
| **AS-REP Roasting** | Атака на.accounts без pre-authentication |
| **DCSync** | Репликация паролей через DRS (Directory Replication Service) |

### Защитные механизмы

```powershell
# Проверка состояния Credential Guard
Get-CimInstance -ClassName Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard

# Проверка состояния VBS (Virtualization Based Security)
msinfo32.exe → System Summary → Virtualization-based security services running

# Просмотр защищённых процессов
Get-Process -Name lsass | Select-Object Id, ProcessName, Path
```

> [!tip] Защита от credential dumping
> Для защиты от credential dumping рекомендуется:
> - Включить Credential Guard
> - Включить LSA Protection (RunAsPPL)
> - Ограничить доступ к_lsass.exe через AppLocker или WDAC
> - ИспользоватьWindows Defender Credential Guard
> - Регулярно менять пароли
