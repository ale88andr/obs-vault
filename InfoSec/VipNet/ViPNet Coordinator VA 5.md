пошаговая инструкция по развёртыванию, первичной инициализации и сетевой настройке **ViPNet Coordinator VA 5** в среде виртуализации VirtualBox на основе видеообзора.

---

Этап 1. Подготовка файлов и дистрибутивов

1. **Дистрибутив и файлы ключей**: Скачайте образ виртуального координатора ViPNet Coordinator VA 5 (ISO/OVA) и файлы ключевой информации (демо-ключи `DST5` / `DS5`, выпущенные в ЦУС/УЦ).
2. **Образ с ключами**: С помощью утилиты (например, AnyToISO) упакуйте файлы демо-ключей `DST5` в отдельный ISO-образ.
3. **Пароли к ключам**: Подготовьте текстовый файл с паролями к ключевым контейнерам.

---

Этап 2. Создание и настройка ВМ в VirtualBox

1. **Импорт / создание ВМ**:
    - В VirtualBox создайте или импортируйте виртуальную машину с именем (например, `coord-1`).
    - При клонировании/импорте второго координатора обязательно выберите генерацию новых MAC-адресов.
2. **Системные параметры**:
    - В разделе **Система** включите параметр **Hardware Clock in UTC Time** для корректной синхронизации времени.
3. **Сетевые адаптеры**:
    - **Адаптер 1 (****eth0****)**: установите режим **Сетевой мост (Bridged)** — интерфейс смотрит во внешнюю сеть/интернет и получает IP от роутера по DHCP.
    - **Адаптер 2 (****eth1****)**: установите режим **Внутренняя сеть (Internal Network)** (например, `N1`) — интерфейс смотрит во внутреннюю сеть к локальным клиентам.
    - **Адаптеры 3 и 4 (****eth2****,** **eth3****)**: выключите или оставьте неактивными.
4. **Носители**:
    - В разделе **Носители** добавьте оптический привод и смонтируйте ISO-образ с созданными демо-ключами (`DST5`).

---

Этап 3. Первичная инициализация (Full Screen Wizard)

1. **Запуск и авторизация**:
    - Запустите виртуальную машину `coord-1`.
    - Введите первичные учетные данные: логин `user`, пароль `user`.
2. **Выбор режима установки**:
    - Выберите вариант `2` — **Full Screen interface**.
    - Примите лицензионное соглашение.
3. **Часовой пояс**:
    - Укажите континент `Europe`, затем страну `Russia` (код `39`).
4. **Загрузка ключей**:
    - Выберите источник ключей: **CD** (система отсканирует смонтированный ISO-образ).
    - Выберите нужный ключ (например, `5-1`).
    - Введите пароль от ключевого файла из текстового документа.
    - Задайте новый сложный пароль администратора (содержащий заглавные/строчные буквы, цифры и спецсимволы).
    - При запросе аутентификации по токенам выберите **No** (если аппаратный токен не используется).
5. **Настройка сетевых интерфейсов**:
    - **Интерфейс** **eth0** **(внешний)**: переведите в состояние `Up`, тип настройки — `DHCP`.
    - **Интерфейс** **eth1** **(внутренний)**: переведите в состояние `Up`, тип настройки — `Static`. Задайте IP-адрес и маску (например, IP: `10.10.10.1`, Маска: `255.255.255.0`).
    - **Неиспользуемые интерфейсы**: переведите в состояние `Disabled`.
6. **Финализация**:
    - Включите службы DNS и NTP по умолчанию, укажите имя узла (например, `coord-1`).
    - Подтвердите пул виртуальных IP-адресов VPN-сети.
    - Подтвердите автозапуск VPN-сервиса (`Yes`) и нажмите **Finish**.

Этап 4. Вход в консоль CLI и первичная настройка

1. **Авторизация администратора**:
    - Войдите под логином `admin` и новым паролем.
    - Перейдите в привилегированный режим командой `enable` (или `en`).
2. **Проверка интерфейсов**:
    - Проверьте полученные адреса командой: `inet show interface`.
3. **Включение журнала IP-пакетов** _(критически важный шаг для отладки)_:
    - Остановите VPN-драйвер:

````
iplir stop
``` [16]
````

- Включите логирование на рабочих интерфейсах:

```
iplir config eth0
```

Измените параметр `REGISTER_ALL = ON` (сохраните: `Ctrl+S`, затем `Ctrl+X`, `Y`, `Enter`). Повторите для второго интерфейса:

```
iplir config eth1
```

и также установите `REGISTER_ALL = ON`.

- Перезапустите VPN-драйвер:

````

Этап 5. Открытие доступа к Web UI и настройка DHCP

По умолчанию веб-интерфейс Coordinator VA 5 работает по порту `8080`. Чтобы подключиться к нему с клиентской машины в локальной сети (`10.10.10.x`), выполните следующие шаги:

1. **Разрешение доступа к порту 8080 в Firewall**:

````
firewall add 1 rule web source-address 10.10.10.2-10.10.10.10 dst-address 10.10.10.1 tcp dport 8080 pass
``` [17, 19]
````

1. **Настройка встроенного DHCP-сервера в CLI**:

````
inet dhcp-server interface eth1
inet dhcp-server range 10.10.10.2 10.10.10.10 interface eth1
inet dhcp-server router 10.10.10.1 interface eth1
inet dhcp-server mode on
inet dhcp-server start
``` [20]
````

1. **Проверка работы**: На клиентской машине (`Windows 10`), подключенной к сети `N1`, откройте браузер и перейдите по адресу `[suspicious link removed]`. Авторизуйтесь под учетной записью `admin`.

Этап 6. Настройка NAT и выхода клиентов в Интернет

Чтобы виртуальные машины из локальной сети за координатором имели доступ в интернет, необходимо настроить **NAT** и разрешить **транзитный трафик**:

1. **Включение NAT (через Web UI)**:
    - Перейдите в раздел **Межсетевой экран -> NAT** -> **Добавить**.
    - Включите правило и укажите:
        - **Заменять адрес источника на**: IP-адрес внешнего интерфейса `eth0` (например, `192.168.1.8`).
        - **Источники**: подсеть клиентов `10.10.10.0/24`.
        - **Назначение**: `Все`.
        - **Протоколы**: `Все`.
    - Нажмите **Применить**.
2. **Разрешение транзитного трафика (в CLI)**:

````
firewall add 1 rule forward 1 rule transit source-address @any dst-address @any pass
``` [25, 26]
````

1. **Разрешение взаимодействия клиентов с координатором (DNS / ICMP)**:

````
firewall add ip-object N1 10.10.10.2-10.10.10.10
firewall add 1 rule local 1 rule ok_filter source-address @N1 dst-address 10.10.10.1 pass
``` [26, 27]

````

Этап 7. Фильтрация сайтов по доменным именам (Web UI)

Для блокировки интернет-ресурсов (например, `vk.com` или `telegram.org`):

1. В Web UI перейдите в **Межсетевой экран -> Сетевые фильтры -> Транзитные фильтры (Forward)**.
2. Создайте правило с действием **Заблокировать (Drop/Reject)**.
3. В поле **Назначение** выберите тип **DNS-имя** и введите `vk.com` (или `telegram.org`).
4. Переместите данное правило блокировки **выше** общего разрешающего транзитного правила (так как правила обрабатываются сверху вниз).
5. Нажмите **Применить**.

Этап 8. Настройка маршрутизации между двумя координаторами

Если в вашей топологии используются два координатора (`Coord-1` с сетью `10.10.10.0/24` и `Coord-2` с сетью `10.10.20.0/24`):

1. **На** **Coord-1** добавьте маршрут к локальной сети за `Coord-2`:

```
inet add route 10.10.20.0 255.255.255.0 next-hop 192.168.1.12
```

_(где_ _192.168.1.12_ _— внешний IP-адрес_ _eth0_ _у Coord-2)_.

1. **На** **Coord-2** добавьте маршрут к локальной сети за `Coord-1`:

```
inet add route 10.10.10.0 255.255.255.0 next-hop 192.168.1.8
```

_(где_ _192.168.1.8_ _— внешний IP-адрес_ _eth0_ _у Coord-1)_.

1. Проверьте связность между клиентами обеих сетей утилитой `ping`
