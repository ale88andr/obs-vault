Модуль **Network Visibility System** — замена ViPNet State Watcher: мониторинг состояния устройств защищённой сети, инвентаризация активов и дашборды. Состоит из двух частей: **сборщика данных** (nvs-rc) и самого модуля NVS. Заметка — скелет под наполнение практикой.

> [!info] Место заметки в плане обучения
> Относится к этапу 8 плана [[План изучения ViPNet Prime]]. Установка сборщика данных и модуля — в [[2. Установка и настройка ViPNet Prime -  пошаговая инструкция по модулям]].

## Архитектура

- **Сборщик данных** — лёгкий сервис (от 1 ядра, ~400 МБ ОЗУ), принимает телеметрию с узлов через ViPNet Client на своём сервере.
- **Модуль NVS** — тяжёлый компонент (8 ядер, 16 ГБ ОЗУ, ~55 ГБ диска по требованиям первоначальной поставки): хранение, обработка, визуализация.
- Для сетей **более ~150 узлов** выносится на отдельный сервер вместе со сборщиком данных; малые сети живут на одной машине с ядром.

Ориентир масштабирования из документации: заявленные требования соответствуют сети ~80 организаций × ~500 клиентов при периодичности мониторинга «мобильные клиенты — 1 час, остальное — 5 минут».

## Что показывает

- Состояние узлов защищённой сети (доступность, версии ПО).
- Инвентаризацию: устройства, их состав, группы узлов мониторинга.
- Журналы: события ОС, звонков Connect; в новых версиях — журнал сработавших правил.
- Дашборд и уведомления (гибкая настройка в новых версиях).

## Миграция со State Watcher

| Аспект | Что происходит |
| --- | --- |
| Подготовка | Актуальный SW 4.9.2, лицензии NVS + узлы мониторинга ([[4. Лицензирование ViPNet Prime]]) |
| Переносится | Только список устройств, период мониторинга, настройки SNMP-агента |
| Не переносится | Накопленные данные мониторинга |
| Параллельная работа | Возможна: SW продолжает мониторить, пока NVS набирает историю |
| Кластеры HW | Переводятся в режим мониторинга «кластер» |

## Практика на стенде

- [ ] Развернуть сборщик данных на втором сервере, установить `.dst` в его ViPNet Client
- [ ] Добавить корневой сертификат внутреннего УЦ в доверенные (`update-ca-certificates`)
- [ ] Подключить тестовые узлы к мониторингу, выставить периодичность
- [ ] Найти в интерфейсе инвентаризационные данные узла и журнал событий
- [ ] Настроить уведомление о недоступности узла
- [ ] Проследить, как узел, созданный в модуле VPN, появляется в NVS без ручного добавления
