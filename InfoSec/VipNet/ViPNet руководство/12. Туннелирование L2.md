
**Цель темы:** понять, как ViPNet Coordinator HW «растягивает» второй уровень сети между удалёнными офисами: ARP, DHCP, широковещание и обычные Ethernet-кадры проходят через зашифрованный VPN, хотя узлы физически находятся в разных сетях.

## 1. Что такое L2OverIP

**L2OverIP** — технология объединения удалённых сегментов на канальном уровне OSI. Для узлов этих сегментов создаётся **один общий широковещательный домен**.

```
Сервер A                  HW-1                         HW-2                  Сервер B
192.168.10.10 ── Ethernet ──► перехват кадра ── VPN ──► извлечение кадра ── Ethernet ──► 192.168.10.20
                              упаковка в IP           расшифровка
                                     ▲                   ▲
                                     └── зашифрованный канал ──┘
```

HW работает как **виртуальный коммутатор**:

- хранит таблицу MAC-адресов;
- знает, через какой порт какой MAC доступен;
- пересылает кадры между локальным и удалёнными портами;
- шифрует кадры при передаче между координаторами.

### Чем отличается от L3

| Параметр                  | L3-туннель (тема 11)         | L2OverIP (тема 12)                                |
| ------------------------- | ---------------------------- | ------------------------------------------------- |
| Что переносится           | IP-пакеты                    | Ethernet-кадры                                    |
| Кто принимает решение     | Маршрутизатор по IP          | Коммутатор по MAC                                 |
| ARP/DHCP между сегментами | Не проходят «как есть»       | Проходят                                          |
| Адреса узлов              | Могут быть разными подсетями | Должны быть в одном L2-домене                     |
| Ключевая настройка        | `tunnel`, маршруты           | `l2overip interface`, `local-port`, `remote-port` |
| Фильтры                   | `firewall tunnel`            | `firewall vpn proto 97`                           |

## 2. Модель портов виртуального коммутатора

Каждому сегменту сети назначается номер порта.

|Порт|Что это|
|---|---|
|`1–31`|Сегменты сети: локальный и удалённые|
|`0`|Трафик самого ViPNet Coordinator HW|

```
        ┌──────────────────────────────┐
        │   Виртуальный коммутатор HW   │
        │                              │
 eth1 ──┤ port 1  (local segment)      │
        │ port 2  (remote HW-2)        │
        │ port 3  (remote HW-3)        │
        │ port 0  (трафик самого HW)   │
        └──────────────────────────────┘
```

Если кадр пришёл с：（

- **локального порта** — он отправляется на все удалённые порты и на порт 0;
- **удалённого порта** — на локальный порт и на порт 0;
- **порта 0** — зависит от режима `unsolicited-frames`.

### Режимы обработки неизвестных одноадресных кадров

|Режим|Поведение|
|---|---|
|`drop`|По умолчанию. Кадр с неизвестным MAC блокируется.|
|`broadcast`|Рассылается как многоадресный на все порты, включая порт 0.|
|`smart-broadcast`|Как `broadcast`, но кадры от порта 0 **блокируются**. Рекомендуется при агрегировании каналов.|

`smart-broadcast` нужен для схемы с двумя парами HW и асимметричной коммутацией:

```
Офис A              Офис B
 HW-A1 ════════ HW-B1   ── один физический канал
 HW-A2 ════════ HW-B2   ── другой физический канал
   \___ bond ___/
```

Ответный трафик может прийти через другую пару HW, поэтому MAC получателя в таблице может отсутствовать. Без `smart-broadcast` такие кадры отбрасываются.

## 3. Ограничения и требования

|Ограничение|Значение / правило|
|---|---|
|Сегменты|Не более **31** объединяемого сегмента; в CLI не более 31 удалённого порта плюс локальный|
|IP-адреса|Не более **252** во всех объединяемых сегментах|
|Класс интерфейса `access`|Статический IP; eth, vlan или bond|
|Класс `trunk`|Для eth или bond; VLAN-сети должны совпадать по ID на сторонах|
|HW50|Только интерфейсы класса `access`|
|Aggregated channel|Режим `bonding broadcast` нельзя использовать вместе с L2OverIP|
|Изоляция|Сегменты должны соединяться **только через пары HW**; обходных L2-путей быть не должно|
|VA|Promiscuous Mode = Accept, MAC Address Changes = Accept, Forged Transmits = Accept|
|VA adapter|Рекомендуется `vmxnet3`, не VirtIO|
|Кластер|Настройка только на активном узле; таблица MAC не реплицируется|

Почему лимит 252 IP важен: каждый ARP/широковещательный кадр дублируется во все сегменты. При большом числе хостов служебный трафик в широковещательном домене съедает пропускную способность.

## 4. Как это выглядит в CLI

### 4.1. Базовый сценарий: два сегмента без VLAN

Дано:

|Сторона|Интерфейс сегмента|Внешний IP HW|Порт|
|---|---|---|---|
|HW-1|`eth1`|`82.16.10.10`|`1`|
|HW-2|`eth2`|`82.16.10.20`|`2`|

#### На HW-1

```
hostname# iplir set l2overip interface eth1
hostname# iplir set l2overip local-port 1 82.16.10.10
hostname# iplir set l2overip remote-port 2 82.16.10.20

hostname# firewall vpn add src @local dst @any proto 97 pass
hostname# firewall vpn add src @any dst @local proto 97 pass

hostname# iplir set l2overip mode switch
hostname# iplir show l2overip config
```

#### На HW-2

```
hostname# iplir set l2overip interface eth2
hostname# iplir set l2overip local-port 2 82.16.10.20
hostname# iplir set l2overip remote-port 1 82.16.10.10

hostname# firewall vpn add src @local dst @any proto 97 pass
hostname# firewall vpn add src @any dst @local proto 97 pass

hostname# iplir set l2overip mode switch
hostname# iplir show l2overip config
```

Если удалённый HWaccess виден по виртуальному адресу, в `remote-port` указывают именно виртуальный адрес. Если в секции `[id]` удалённого HW несколько параметров `ip`, включают видимость по реальным адресам и указывают реальный IP.

### 4.2. Сценарий с VLAN

Если нужно объединить **все VLAN** двух сегментов:

```
hostname# inet ifconfig eth2 class trunk
hostname# iplir set l2overip interface eth2
hostname# iplir set l2overip local-port 1 82.16.10.10
hostname# iplir set l2overip remote-port 2 82.16.10.20
hostname# firewall vpn add src @local dst @any proto 97 pass
hostname# firewall vpn add src @any dst @local proto 97 pass
hostname# iplir set l2overip mode switch
```

Если нужен только один VLAN:

```
hostname# iplir set l2overip interface eth2.10
```

Можно также объединить VLAN одного сегмента с сегментом без VLAN:

```
HW-1: interface eth2.10   (только VLAN 10)
HW-2: interface eth2      (обычный access-сегмент)
```

Номер VLAN обязан совпадать на обеих сторонах. Нельзя удалить VLAN-интерфейс, который используется включённым L2OverIP.

### 4.3. Команды L2OverIP

|Команда|Назначение|Особенности|
|---|---|---|
|`iplir set l2overip interface <if>`|Рабочий интерфейс сегмента|Физический или VLAN (`eth2.10`)|
|`iplir set l2overip local-port <1-31> <IP>`|Локальный сегмент|Только статический IP внешнего интерфейса|
|`iplir set l2overip remote-port <порт> <IP>`|Удалённый сегмент|Порт != локальному; ≤31 удалённых портов; повторная команда обновляет IP|
|`iplir set l2overip remote-port <порт> delete`|Удалить удалённый порт|Сначала `mode none`, затем удаление с подтверждением|
|`iplir set l2overip mac-ttl <сек>`|Время жизни MAC в таблице|60–86400, по умолчанию **300**|
|`iplir set l2overip unsolicited-frames <режим>`|Неизвестные unicast-кадры|`drop` / `broadcast` / `smart-broadcast`|
|`iplir set l2overip mode {switch|none}`|Включить/выключить|

### 4.4. Что смотреть

```
hostname> iplir show l2overip status
hostname> iplir show l2overip config
hostname> iplir show l2overip mac-address-table
hostname> iplir show l2overip port-table
hostname> iplir show l2overip virtual-switch-stats
hostname> iplir show l2overip clone-fabric-stats
hostname> iplir show l2overip mac-hash-stats
```

Пример вывода `config`:

```
mode = switch
mac_ttl = 300
device = eth0
local_port = 12, 172.16.12.123
remote_port = 13, 172.16.12.124
unsolicited-frames = drop
```

`virtual-switch-stats` показывает общее число обработанных и заблокированных кадров, в том числе кадров с неизвестным MAC. Это первая точка диагностики при «L2 поднят, но узлы не видят друг друга».

### 4.5. Изменение и удаление удалённого порта

```
hostname# iplir set l2overip remote-port 2 82.16.10.99
hostname# iplir set l2overip mode none
hostname# iplir set l2overip mode switch
```

Удаление:

```
hostname# iplir set l2overip mode none
hostname# iplir set l2overip remote-port 2 delete
Do you want to delete remote port number 2 from L2OverIP configuration? [Yes/No]: y
hostname# iplir set l2overip mode switch
```

### 4.6. Кластер и VA

Кластер:

```
# только на активном узле
hostname# iplir set l2overip mode switch
```

После failover:

```
Активный узел сменился
   │
   ├── конфигурация L2OverIP есть на новом активном
   ├── таблица MAC НЕ передана
   └── коммутация восстановится, когда узлы заново пришлют ARP
```

VA (VMware):

|Настройка|Значение|
|---|---|
|Promiscuous Mode|Accept|
|MAC Address Changes|Accept|
|Forged Transmits|Accept|
|Тип адаптера|`vmxnet3` вместо VirtIO|

## 5. Типичные ошибки

|Симптом|Причина|Лечение|
|---|---|---|
|Сегменты не видят друг друга|Нет фильтров `proto 97`|Добавить в обе стороны `firewall vpn add ... proto 97 pass`|
|ARP проходит в одну сторону|Фильтр добавлен только в одном направлении|Добавить зеркальное правило|
|L2OverIP не работает на VA|Promiscuous Mode выключен или VirtIO|Включить Accept, заменить адаптер на `vmxnet3`|
|HW50 не поднимает trunk|Поддерживается только `access`|Использовать access-интерфейс со статическим IP|
|Удалённый HW недоступен|В `remote-port` указан не тот адрес видимости|Выровнять `visibility` и указать реальный/виртуальный адрес корректно|
|После смены удалённого адреса старый ещё работает|Изменение не применено|`mode none` → `mode switch`|
|Не удаляется удалённый порт|L2OverIP включён|Сначала `mode none`|
|Кадры с неизвестным MAC отбрасываются|`unsolicited-frames=drop`|Переключить на `broadcast` или `smart-broadcast`|
|После failover кластера нет L2-связи|Таблица MAC не реплицируется|Дождаться ARP от конечных узлов|
|Просадка пропускной способности|Более 252 IP в широковещательном домене|Уменьшить число хостов или перепроектировать L2-домен|
|Петля/зацыкливание широковещания|Есть обходной L2-путь besides HW|Оставить единственный путь через HW|
|Нельзя удалить VLAN-интерфейс|Он занят L2OverIP|`mode none`, затем удаление VLAN|
|В журнале не находятся пакеты|Ищут по инкапсулированному IP|Искать по исходным IP, TCP/UDP-портам и интерфейсу|
