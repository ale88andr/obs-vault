
**Цель темы:** науться читать и создавать правила в четырёх таблицах фильтров и понимать, почему «правило есть, но трафик не идёт» почти всегда означает неверную таблицу, неверный приоритет или отсутствие зеркального правила.

**Источники:** «Настройка с помощью CLI», с. 131–153, 421–424; «Справочник CLI», с. 53–69.

## 1. Четыре таблицы фильтров плюс NAT

Фильтры разделяются по типу IP-трафика. Каждый тип хранится в **своей таблице**, и правило из другой таблицы трафик не обработает.

|Таблица|Ключ в CLI|Что фильтрует|
|---|---|---|
|**Защищённая сеть**|`vpn`|Обмен между HW и узлами ViPNet, с которыми есть связь|
|**Туннелируемые узлы**|`tunnel`|Трафик между открытыми туннелируемыми узлами и узлами ViPNet|
|**Локальная открытая сеть**|`local`|Трафик между самим HW и открытыми узлами|
|**Транзитная открытая сеть**|`forward`|Открытый транзитный трафик, проходящий через HW|
|**Трансляция адресов**|`nat`|Правила `change src` / `change dst` (тема 15)|

```
Открытый узел ──┐
                ├──► [forward] ──► HW ──► [vpn] ──► ViPNet-узел
Открытый узел ──┘                  │
                                   ├──► [local]   (трафик самого HW)
                                   └──► [tunnel]  (туннелируемые адреса)
```

## 2. Порядок применения фильтров

```
1. Служебные фильтры          предустановлены, пользователем не меняются
        ↓
2. Фильтры политик Prime      пришли из Policy Management, не редактируются
        ↓
3. Настраиваемые фильтры      1 → 2 → 3 → ...  (меньше номер = выше приоритет)
        ↓
4. Блокирующий по умолчанию   @any → @any → drop, не редактируется
```

Правила нумерации:

|Действие|Результат|
|---|---|
|Создать без номера|Фильтр добавляется в конец таблицы, самый низкий приоритет|
|Создать с номером меньше максимального|Следующие фильтры получают номер +1, их приоритет понижается|
|`move rule <текущий> to <новый>`|Приоритет меняется, остальные номера сдвигаются|
|Удалить фильтр|Номера после удалённого уменьшаются на 1|

Имя правила с пробелами заключается в кавычки: `rule "Allow FTP inbound"`.

## 3. Адреса отправителя и получателя

`src` и `dst` — **обязательные** параметры. Синтаксис во многом общий, но у каждой таблицы есть свои ограничения.

### 3.1. По таблицам

|Таблица|Разрешённые адреса|
|---|---|
|`local`|IP, имя, диапазон `1.1.1.1-1.1.1.10`, маска `192.168.1.0/24`, список через запятую, `any`, `local`, `remote`, `broadcast`, `multicast`, группы `@IP_group`, интерфейс `src interface eth0`, страна `src cc BY`, MAC `src mac FF:0B:...`|
|`forward`|То же, но из системных объектов **только `any`**; `local`/`remote` использовать нельзя|
|`vpn`|ViPNet ID узла `0x1a12000a`, ID сети `0x1a12`, `any`, `allcoordinators`, `allclients`, `local`, `remote`, broadcast, группы `@vpn_group`. **Нельзя** IP-адреса, домены, маски, интерфейсы|
|`tunnel`|Комбинация open-адресов и ViPNet-ID; из системных объектов только `any`, `allcoordinators`, `allclients`, `tunneledip`|
|`nat`|IP, имя, диапазон, список, маска, домен, группы `@IP_group`|

### 3.2. Жёсткие правила

> В `vpn`-фильтре **один из адресов обязан быть `local`**. Если `src` не `local`, то `dst` должен быть `local` или `broadcast`.

> В `tunnel`-фильтре: если в `src` указан адрес **защищённого** узла, то в `dst` должен быть **открытый** узел, и наоборот.

> `any`, `local`, `remote` нельзя комбинировать с обычными IP-адресами в одной лексеме.

> `dst interface ...` не существует — интерфейс указывается только в `src`.

> MAC-адрес можно указать только в `src`, только один, и **нельзя** указывать MAC-адреса самих интерфейсов HW.

### 3.3. Доменные имена

Если в фильтре указано доменное имя:

- HW отправляет DNS-запрос;
- запись и TTL кэшируются;
- после истечения TTL запрос повторяется;
- если данные изменились — фильтры перезагружаются в драйвере;
- пока имя не разрешено, фильтр **не загружается** в драйвер ViPNet.

Поэтому blocking по доменам требует сначала настроить внешний DNS и разрешающие DNS-фильтры.

## 4. Условия срабатывания

### 4.1. Протоколы

```
# имена
tcp udp icmp

# порты: sport перед dport, имя протокола перед каждым портом
tcp sport 2525 tcp dport 443 tcp dport 4444-4445

# номер протокола
proto 97

# группа сервисов
service @DNS

# ICMP
icmp type 3 code 1

# TCP-флаги (только local и forward)
tcp +ack +fin +psh
tcp sport 2525 tcp dport 443 +syn -urg -cwr
```

|Правило|Пояснение|
|---|---|
|`+флаг`|Флаг установлен|
|`-флаг`|Флаг сброшен|
|Набор флагов|Должен быть одинаковым для всех пакетов сессии; отличие хотя бы в одном пакете приводит к блокировке|
|`proto <номер>`|Дополнительные параметры (`sport`, `dport`) при числовом виде **нельзя**|
|NAT с портом|При `dport` обязательны `dst` и TCP/UDP|

### 4.2. DPI, пользователи и инспекция

|Параметр|Где доступен|Назначение|
|---|---|---|
|`dpiapp`|`forward`, `tunnel`|Приложение, например `Zoom`, `BitTorrent`, `unknown`|
|`dpiprotocol`|`forward`, `tunnel`|Прикладной протокол, например `SSL`, `HTTP`, `unknown`|
|`dpigroup`|`forward`, `tunnel`|Группа приложений: `Messaging`, `Streaming`, `Gaming`|
|`dnuser`|`forward`, `tunnel`|Пользователь AD или Captive Portal|
|`url-category`|`forward`, `tunnel`|Категория из базы; пользовательская — с префиксом `#`|
|`ssl {decrypt\|bypass}`|только `forward`|SSL/TLS-инспекция|
|`ips {on\|off}`, `av`, `sb`, `dlp`|только `forward`|IPS, ICAP-антивирус, песочница, DLP|
|`url`, `mthd`, `type`, `proxy-client`, `user-agent`|только `forward`|Контентная фильтрация|

Ограничения combinations:

|Нельзя вместе|Почему|
|---|---|
|`dpiapp` + `ssl`, `dpiprotocol` + `ssl`, `dpigroup` + `ssl`|В транзитном фильтре DPI и SSL-инспекция исключают друг друга|
|`dpigroup` + `dpiapp` / `dpiprotocol`|Группа и конкретные приложения — разные режимы классификации|
|`dpiapp` + `reject*`|Нельзя отправлять ICMP-отклонение-filter с DPI-условиями|
|`dnuser` + `reject*`|То же для пользователей|
|`url` + `dpiapp` / `dpiprotocol` / `dpigroup`|Контентная фильтрация и DPI — разные механизмы|

Дополнительно:

- `dpiapp unknown` и `dpiprotocol unknown` — блокировка неклассифицированного трафика;
- если указано приложение, `dpiprotocol` выбирается только из протоколов этого приложения;
- имена с пробелами — в двойных кавычках: `dpiapp "Google Mail",Telegram`;
- пользователи — только латиницей; при нескольких пользователях на одном узле действуют правила **последнего вошедшего**.

### 4.3. Расписание

|Лексема|Пример|
|---|---|
|`daily`|`daily 8:00-20:00`|
|`weekly`|`weekly mo tu we at 09:00-18:00`|
|`calendar`|`calendar 01.01.2026-31.01.2026 at 10:00-12:00`|
|`schedule @group`|Группа объектов типа «Расписания»|

Расписание действует **только на новые сессии**. Сессия, открытая до начала действия расписания, живёт до своего завершения.

## 5. Действие и журналирование

|Действие|Эффект|
|---|---|
|`pass`|Пропустить|
|`drop`|Блокировать без уведомления|
|`reject`|Destination port unreachable|
|`rej-net-unreachable`|Destination net unreachable|
|`rej-host-unreachable`|Destination host unreachable|
|`rej-proto-unreachable`|Destination protocol unreachable|
|`rej-net-prohibited`|Network administratively prohibited|
|`rej-host-prohibited`|Host administratively prohibited|
|`rej-admin-prohibited`|Communication administratively prohibited|
|`rej-tcp-reset`|TCP reset, только для TCP|

### Важная разница в поведении блокировки

|Таблица|Блокирующее правило на уже установленное соединение|
|---|---|
|`vpn`, `local`, `tunnel`|**Не рвет** соединение до истечения времени жизни сессии|
|`forward`|Действует **сразу**, даже на разрешённое ранее соединение|

Если нужно немедленно разорвать stateful-сессии:

```
hostname# firewall conntrack flush
connection tracking table has been emptied
```

### Параметры `log` и `sessions`

|Параметр|По умолчанию `pass`|По умолчанию `drop`/`reject`|
|---|---|---|
|`log on/off`|`off`|`on`|
|`sessions on/off`|`off`|`on` (и для правил из Prime)|

`state`: `all`, `begin`, `begin_end` (по умолчанию).

В выводе `firewall <type> show` включенный `log` помечается префиксом `[LOG]`, включенный `sessions` — `[SESS]`.

```
hostname# firewall rules log-blocked
```

Включает журналирование IP-пакетов для всех пользовательских правил с `drop` и `reject`.

Счётчики срабатываний ведутся с первого включения HW до сброса из ViPNet Prime. **Перезагрузка HW, обновление ПО и failover не обнуляют счётчики.** Просмотр счётчиков — только в веб-интерфейсе.

## 6. Фильтры по умолчанию

### 6.1. `vpn`

Служебные фильтры, которые нельзя трогать:

|Название|Src|Dst|Протокол|Действие|
|---|---|---|---|---|
|ViPNet Service in / out (кластер)|`@any` / `@local`|`@local` / `@any`|UDP 2060|`pass`|
|Block not original udp port|`@local`|`@any`|UDP 0–2045, 2047–63536 → 2046|`drop`|
|Allow ViPNet base services in/out|—|—|UDP 2046, 2048, 2050|`pass`|
|Allow ViPNet MFTP in/out|—|—|TCP 5000–5003|`pass`|
|Allow ViPNet Control services|`@local` ↔ Prime ID|—|—|`pass`|

Настраиваемые по умолчанию: ICMP ping, ICMP redirect (drop), DBViewer, DNS, NTP, DHCP, SSH, syslog, CEF, SNMP, UPS.

Финальный фильтр:

```
Default VPN rule   @any → @any   @any   drop
```

### 6.2. `tunnel`

|Название|Src|Dst|Действие|
|---|---|---|---|
|To all tunnel nodes|`@any`|`@tunneledip`|`pass`|
|From all tunnel nodes|`@tunneledip`|`@any`|`pass`|
|Default tunnel rule|`@any`|`@any`|`drop`|

Именно эти два правила восстанавливали в теме 11.

### 6.3. `local`

Служебные фильтры кластера:

|Название|Src|Dst|Действие|
|---|---|---|---|
|Failover test IP|`@local`|список `testip` из `failover.ini`|`pass`|
|Failover Channel|`@local`|interface синхронизации → `@any`|`pass`|
|Failover Channel|IP синхронизации второго узла|interface синхронизации → `@any`|`pass`|

Настраиваемые: ICMP ping, ICMP redirect (drop), DNS, NTP, DHCP, blackhole.

```
Default local rule   @any → @any   @any   drop
```

### 6.4. `forward`

```
Default transit rule   @any → @any   @any   drop
```

По умолчанию **нет разрешающих транзитных правил**. Любой интернет-трафик через HW не пойдёт, пока вы явно его не разрешите.

## 7. Как это выглядит в CLI

### 7.1. Базовый синтаксис

```
hostname# firewall <тип> add [<номер>] [rule <имя>] \
    src <адрес> dst <адрес> \
    [<протокол>] [dpiapp ...] [dpiprotocol ...] [dpigroup ...] \
    [dnuser ...] [<расписание>] [url-category ...] \
    [ssl ...] [ips ...] [av ...] [sb ...] [dlp ...] \
    [url ...] [proxy-client ...] [user-agent ...] \
    [log {on|off}] [sessions {on|off} [state ...]] \
    <действие>
```

### 7.2. Примеры по типам

```
# vpn: защищённый узел → сам HW
hostname# firewall vpn add src 0x1a12000a dst @local pass

# tунель: открытый адрес → ViPNet ID
hostname# firewall tunnel add src 192.168.0.1 dst 0x1234abab pass

# tunnel: только в рабочее время, с журналом
hostname# firewall tunnel add src 0x1234abab dst 192.168.0.1 daily 8:00-20:00 log on pass

# local: свой узел → открытый сервер по FTP
hostname# firewall local add src @local dst 192.168.2.4 service @FTP pass

# local: блокировка по портам
hostname# firewall local add src 192.168.30.1 dst 172.16.35.1 \
    tcp sport 2525 tcp dport 443 drop

# forward: разрешить транзит между открытыми узлами
hostname# firewall forward add src 192.168.0.1 dst 192.168.30.3 pass

# vpn: разрешить L2OverIP (из темы 12)
hostname# firewall vpn add src @local dst @any proto 97 pass
hostname# firewall vpn add src @any dst @local proto 97 pass

# forward: блокировка приложения для пользователя
hostname# firewall forward add src @any dst @any dpiapp Zoom dpiprotocol SSL dnuser ivanov drop
```

### 7.3. Управление правилами

|Команда|Назначение|
|---|---|
|`firewall rules show`|Все фильтры и правила NAT|
|`firewall <тип> show`|Таблица нужного типа|
|`firewall <тип> show <номер>`|конкретное правило|
|`firewall <тип> show rule <имя>`|по имени|
|`firewall <тип> change append {<номер>\|rule <имя>} ...`|Добавить значения / изменить флаги|
|`firewall <тип> move rule <текущий> to <новый>`|Изменить приоритет|
|`firewall <тип> delete <номер>`|Удалить; numbering сдвигается|
|`firewall <тип> delete src <адрес>`|Поиск по параметру, строгое совпадение, подтверждение|
|`firewall conntrack flush`|Очистить таблицу отслеживаемых соединений|
|`firewall rules log-blocked`|Включить логирование всех `drop`/`reject`|
|`firewall blacklist add/delete src\|dst ip\|mac <addr>`|Аппаратный фильтр|
|`firewall blacklist show`|Список аппаратных фильтров|

При удалении по параметру, если нашлось несколько правил:

- введите номер из колонки `Num` — удалится одно;
- введите `a` — удалятся все из списка;
- если найдено одно — подтвердите `y`.

```
hostname# firewall local change append 8 src 192.168.2.2 weekly sa su at 09:00-23:00
hostname# firewall forward change append 333 log off
```

**Поиск строгий:** `src 192.168.1.10` не найдёт правило с `src 192.168.1.10-192.168.1.11`; `rule Name` не найдёт `Name1`.

### 7.4. Группы объектов

```
hostname# firewall ip-object add name @IP_group_1 110.35.14.0/24 exclude 110.35.14.3
hostname# firewall vpn-object add name @VPN_group 0x1a12000a,0x1a12000b
hostname# firewall interface-object add name @intgroup interface eth0 interface eth1
hostname# firewall schedule-object add name @weekend weekly sa su at 09:00-23:00
hostname# firewall service-object add name @myproto tcp sport 2525 tcp dport 443
```

Типы: `ip-object`, `vpn-object`, `interface-object`, `service-object`, `schedule-object`. Имя уникально среди всех типов, 1–64 символа, до **1000** объектов в группе.

## 8. Типичные ошибки

|Симптом|Причина|Лечение|
|---|---|---|
|Правило есть, но трафик не идёт|Правило создано не в той таблице|对于 open-транзит — `forward`; для ViPNet-ID — `vpn`; для туннелей — `tunnel`|
|`firewall vpn add src 192.168.1.10 ...` не работает|В `vpn` нельзя IP-адреса|Использовать ViPNet ID или перенести правило в `forward`/`local`|
|Транзитный фильтр с `local` не создаётся|В `forward` только системный объект `any`|Переписать на `@any`|
|Односторонний доступ|Создано правило только в одну сторону|Добавить зеркальное|
|Новое правило «не перебивает» старое|Создано без номера, получило последний приоритет|`move rule` или создать с меньшим номером|
|Блокировка не подействовала сразу|`vpn`/`local`/`tunnel` не рвут установленную сессию|Ждать окончания сессии или `firewall conntrack flush`|
|Блокировка по домену не работает|Имя не разрешено DNS, фильтр не загружен|Настроить forwarders и разрешающие DNS-фильтры|
|`reject` не создаётся с DPI|ICMP-отклонение несовместимо с `dpiapp`/`dnuser`|Использовать `drop` или убрать DPI-условие|
|`ssl` не работает вместе с `dpiapp`|Запрещённая комбинация в `forward`|Выбрать один механизм|
|TCP-сессия падает|Набор TCP-флагов отличается в пакетах сессии|Убрать условие по флагам|
|Расписание «не сработало»|Сессия была открыта до начала действия|Расписание действует только на новые сессии|
|Поиск не находит правило|Строгое совпадение параметров|Посмотреть `firewall <тип> show` и скопировать параметр точно|
|Фильтр по пользователю не срабатывает|Имя в кириллице или несколько пользователей на узле|Только латиница; действует последний вошедший|
|MAC-фильтр не применяется|Указан MAC интерфейса HW|Указать MAC конечного узла|
|Журнал пуст|Не задан `log on`, либо способ регистрации не «по фильтрам»|`log on` / `firewall rules log-blocked`|
|Трафик идёт открытым|`proto 97` или `tunnel` не разрешены|Вернуть разрешающие правила из тем 11–12|
