**Цель темы:** разделить четыре независимых плоскости интерфейса — физический линк, класс, адресацию и учёт в `iplir.conf` — и научиться понимать, на какой из них сломалось.

## 1. Четыре плоскости, которые постоянно путают

Интерфейс в ViPNet Coordinator — это не одна сущность, а четыре слоя настройки. Команды разных групп работают с разными слоями, и успех в одном не означает успеха в другом.
```
┌──────────────────────────────────────────────────────────────┐
│ 4. Роль в VPN: internal / external                           │
│    [adapter] type в iplir.conf                               │
│    видно в: inet show interface state                        │
├──────────────────────────────────────────────────────────────┤
│ 3. Учёт трафика: enable / disable (allowTraffic)             │
│    inet ifconfig <if> enable | disable                       │
│    iplir adapter traffic <if> on | off                       │
│    видно в: iplir show adapters                              │
├──────────────────────────────────────────────────────────────┤
│ 2. Адресация: static / DHCP / alias                          │
│    inet ifconfig <if> address | dhcp | address add           │
│    видно в: inet show interface <if>                         │
├──────────────────────────────────────────────────────────────┤
│ 1. Линк: up / down, speed, duplex, autoneg, MTU              │
│    inet ifconfig <if> up | down | speed | mtu                │
│    видно в: inet show interface <if>                         │
└──────────────────────────────────────────────────────────────┘
```

|Симптом|Слой|Чем проверять|
|---|---|---|
|Кабель вставлен, `Link detected: no`|1|`inet show interface <if>`|
|Линк есть, но трафик не идёт|3|`inet show interface state`, `iplir show adapters`|
|Пинг по IP не идёт|2|`inet show interface`, `inet show routing`|
|VPN не понимает, где внешняя сеть|4|`inet show interface state`, `iplir show adapter <if>`|
|Всё работает, но после перезагрузки пропало|3|Интерфейс не был добавлен в `iplir.conf`|

> Главная ошибка темы: считать, что `up` и `enable` — одно и то же. `up` поднимает линк. `enable` добавляет интерфейс в конфигурацию VPN и разрешает обработку IP-трафика. Можно иметь поднятый линк и полностью «невидимый» для VPN интерфейс.

## 2. Имена и классы

Имена физических интерфейсов: `eth0`, `eth1`, … по количеству портов.

|Класс|Для чего|Ограничения|
|---|---|---|
|`access`|Обычный интерфейс с адресом|По умолчанию у всех физических|
|`trunk`|Трафик нескольких VLAN через 802.1Q|Только физический или агрегированный; адреса при установке теряются|
|`slave`|Подчинённый интерфейс агрегированного канала|Нельзя для bond и VLAN; нельзя, пока он входит в bond|

```
hostname# inet ifconfig eth1 class trunk
hostname# inet ifconfig eth2 class slave
```

Нюансы смены класса:

- При первой смене класса запрашивается подтверждение.
- Установка `trunk` на интерфейсе с адресами требует отдельного подтверждения и **удаляет все адреса**.
- Перед переходом в `access` или `slave` нужно удалить все виртуальные интерфейсы на базе этого интерфейса.
- Перед выходом из `slave` интерфейс должен быть исключён из агрегированного канала.
- `trunk` нельзя установить, если на интерфейсе работает или настроен на автозапуск DHCP-сервер либо DHCP-relay.

## 3. Базовая настройка Ethernet

Канонический порядок:

```
hostname# inet ifconfig eth1 class access
hostname# inet ifconfig eth1 address 192.168.10.1 netmask 255.255.255.0
hostname# inet ifconfig eth1 up
hostname# inet show routing
```

|Шаг|Команда|Что делает|
|---|---|---|
|Класс|`inet ifconfig eth1 class access`|Обычный интерфейс|
|Статический адрес|`inet ifconfig eth1 address <IP> netmask <маска>`|Назначает IPv4-адрес|
|DHCP|`inet ifconfig eth1 dhcp`|Получает адрес, DNS, NTP, маршруты|
|Включить линк|`inet ifconfig eth1 up`|Поднимает интерфейс|
|Разрешить трафик|`inet ifconfig eth1 enable`|Добавляет в `iplir.conf`, `allowTraffic on`|
|Проверить|`inet show interface eth1`|Флаги, адрес, класс, скорость|

### Ограничения адресации

|Запрещено|Причина|
|---|---|
|`0.*.*.*`|Невалидный адрес|
|Маски `0.0.0.0`, `255.255.255.254`, `255.255.255.255`|Не поддерживаются|
|Два интерфейса в одной подсети или broadcast-домене|Конфликт маршрутизации|
|DHCP-адрес из подсети другого интерфейса|Конфликт маршрутизации|

### Шлюз по умолчанию

Если хотя бы на одном интерфейсе включён DHCP с получением маршрутов, проверьте:

```
hostname> inet show routing
```

Маршрут по умолчанию должен появиться. Если его нет — задайте статический. Это не «желательно», а критично: при недоступном шлюзе ломаются виртуальные IP-адреса, обработка прикладных протоколов, сетевые службы и многое другое. Подробно — тема 8.

### Смена DHCP → статика

При назначении статического адреса на интерфейсе, который работал по DHCP, **теряются DNS- и NTP-серверы, полученные по DHCP**. Их надо прописать заново. Это типичная причина «интернет есть, а время и имена не работают».

## 4. Дополнительные IP-адреса (alias)

Нужны, чтобы разделить сеть на логические подсети на одном порту.

Условия:

- основной адрес статический;
- класс `access`;
- `Configured by DHCP: no`.

```
hostname# inet ifconfig eth1 address add 192.168.10.2 netmask 255.255.255.0
```

Создаётся виртуальный интерфейс `eth1:0`. Нумерация начинается с 0. Просмотр:

```
hostname> inet show interface eth1:0
```

Удаление:

```
hostname# inet ifconfig eth1 address delete 192.168.10.2 netmask 255.255.255.0
```

Alias-интерфейсы входят в общий лимит интерфейсов: 128 у HW50, 512 у остальных исполнений.

## 5. VLAN: trunk и виртуальные интерфейсы

```
Коммутатор 802.1Q
   │  trunk: теги 10, 20, 30
   ▼
eth1 (class trunk)
   ├── eth1.10  ── 10.10.10.1/24
   ├── eth1.20  ── 10.20.20.1/24
   └── eth1.30  ── 10.30.30.1/24
```

Идентификатор VLAN: **1–4094**. Значения 0 и 4095 зарезервированы.

Порядок:

```
hostname# inet ifconfig eth1 class trunk
hostname# inet ifconfig eth1 vlan add 10
hostname# inet ifconfig eth1.10 address 10.10.10.1 netmask 255.255.255.0
hostname# iplir adapter add eth1.10 traffic on
hostname# inet ifconfig eth1 up
```

Ключевой момент: **создание VLAN не означает, что через него пойдёт трафик**. Виртуальный интерфейс нужно добавить в `iplir.conf`:

```
hostname# iplir adapter add eth1.10 traffic on
```

По умолчанию у добавленного интерфейса `traffic off`. Если не указать `on` — интерфейс есть, адрес есть, трафика нет.

Альтернатива:

```
hostname# inet ifconfig eth1.10 enable
```

`enable` добавляет интерфейс в `iplir.conf`, если его там нет, и включает `allowTraffic`.

### MTU и VLAN

- MTU задаётся на `trunk` и автоматически применяется ко всем VLAN на нём.
- Отдельно для VLAN MTU не настраивается.
- То же для bond: MTU задаётся на агрегированном интерфейсе и наследуется подчинёнными `slave`.

## 6. Агрегирование каналов (bonding)

До **8** агрегированных интерфейсов: `bond0`…`bond7`.

### Режимы

|Режим|Логика|Когда применять|
|---|---|---|
|`balance-rr`|Пакеты по очереди через подчинённые интерфейсы|HW ↔ HW, простая топология|
|`balance-xor`|Один поток всегда через один интерфейс по хэшу|HW ↔ коммутатор|
|`balance-tlb`|Балансировка по объёму исходящего трафика|HW ↔ коммутатор, много разных пакетов|
|`802.3ad`|LACP, агрегаторы по скорости|HW ↔ коммутатор с поддержкой LACP|
|`active-backup`|Один основной, остальные в резерве|Резервирование без балансировки|
|`broadcast`|Пакет во все подчинённые интерфейсы|Специальные схемы резервирования|

### Какой режим где

```
HW ↔ коммутатор
   MAC/IP/порты отправителя не подменяются
   → balance-xor, balance-tlb, 802.3ad

HW ↔ HW
   MAC/IP/порты подменяются координатором
   → balance-rr, active-backup, broadcast
```

Это не рекомендация «на вкус», а следствие того, меняются ли заголовки на пути. Если выбрать `802.3ad` между двумя координаторами без промежуточного коммутатора с LACP, канал не поднимется. Если выбрать `balance-rr` между HW и коммутатором, пакеты одного потока пойдут по разным линкам и могут переупорядочиться — для видео и голоса это деградация.

### Создание

```
hostname# inet ifconfig eth2 class slave
hostname# inet ifconfig eth3 class slave
hostname# inet bonding add 0 mode 802.3ad slaves eth2 eth3
hostname# inet ifconfig bond0 bonding xmit-hash-policy layer3+4
hostname# iplir adapter add bond0 traffic on
hostname# inet ifconfig bond0 address 10.10.10.1 netmask 255.255.255.0
hostname# inet ifconfig eth2 up
hostname# inet ifconfig eth3 up
hostname# inet ifconfig bond0 up
```

Параметры режимов:

|Параметр|Команда|По умолчанию|
|---|---|---|
|Частота проверки линка|`inet ifconfig bond0 bonding miimon <1–1000>`|100 мс|
|Хэш для `balance-xor` / `802.3ad`|`... bonding xmit-hash-policy {layer2 \| layer2+3 \| layer3+4}`|`layer2`|
|Выбор агрегатора для `802.3ad`|`... bonding ad-select {stable \| bandwidth \| count}`|`stable`|
|Частота LACP|`... bonding lacp-rate {slow \| fast}`|`slow` (30 с)|
|Основной интерфейс|`... bonding primary {<slave> \| none}`|Авто|

Ограничения:

- Изменить режим bond нельзя «на месте»: удалить и создать заново. Возможен обрыв до 1 секунды.
- Удалить последний подчинённый интерфейс из bond нельзя.
- MC-LAG/MLAG не поддерживается: порты разных координаторов нельзя объединить в один bond.
- `broadcast` требует настройки сети против дублирования пакетов; с L2OverIP несовместим.
- На VA работоспособность bonding не гарантируется — настраивайте на платформе виртуализации.

## 7. DHCP-клиент

DHCP даёт четыре вещи:

1. IP-адрес и маску.
2. DNS-серверы.
3. NTP-серверы.
4. Маршруты.

Каждую категорию можно отключить отдельно:

```
hostname# inet ifconfig eth1 dhcp dns off
hostname# inet ifconfig eth1 dhcp ntp off
hostname# inet ifconfig eth1 dhcp route off
hostname# inet ifconfig eth1 dhcp route-metric 50
```

|Нюанс|Последствие|
|---|---|
|DHCP только для `access` или bond|На trunk/slave не работает|
|Включение DHCP удаляет дополнительные адреса|Alias пропадут|
|Переход на статику теряет DNS/NTP от DHCP|Пропишите вручную|
|DHCP-адрес не должен быть из подсети другого интерфейса|Иначе конфликт|
|Маршрут по умолчанию может не прийти|Проверьте `inet show routing`, задайте статический|

## 8. Мобильная сеть 3G/4G

Доступно на HW50 A1, HW50 N3, HW100 N3. Интерфейс — `ppp0`, группа `ppp`.

```
hostname# inet usb-modem mode off
hostname# inet usb-modem set provider mts
hostname# inet usb-modem set pin 1234
hostname# inet usb-modem mode on
hostname> inet show usb-modem
```

Предустановлены MTS, Beeline, Megafon, SkyLink. Для другого оператора:

```
hostname# inet usb-modem add provider xtelecom
hostname# inet usb-modem set connection address internet.xtelecom.ru
hostname# inet usb-modem set phone *99***1#
hostname# inet usb-modem set user xtelecom
hostname# inet usb-modem set password xtelecom
hostname# inet usb-modem set provider xtelecom
```

Управление тем, что приходит от оператора:

```
hostname# inet usb-modem set route off
hostname# inet usb-modem set route-metric 100
hostname# inet usb-modem set dns off
```

Успешный вывод:

```
3G/4G modem is found
Cellular provider: MTS
SIM card: OK
PIN verification: OK
3G/4G connection is enabled
Connection interface: ppp0
```

Если `SIM card: error` или `PIN verification: failed` — выключите модем, устраните причину, включите заново.

Динамические интерфейсы `ppp` не требуют секции `[adapter]` в `iplir.conf`: они активны и пропускают трафик по умолчанию.

## 9. Wi-Fi

Только HW50 N2 и HW100 N2. Интерфейс — `wlan0`.

|Ограничение|Следствие|
|---|---|
|Не поддерживается в кластере|Не используйте Wi-Fi в HA-схеме|
|Нельзя одновременно клиент и точка доступа|Выберите роль|
|Настройка только при выключенном интерфейсе|Сначала `inet wifi mode off`|

```
hostname# inet wifi mode off
hostname# inet show wifi
hostname# inet wifi role client
hostname# inet wifi scan
hostname# inet wifi client authentication wpa2-psk
hostname# inet wifi mode on
hostname> inet show wifi
```

`wlan0` по умолчанию работает по DHCP. Можно отключить получение DNS, NTP, маршрутов и задать метрику — теми же командами `inet ifconfig wlan0 dhcp ...`.

## 10. Просмотр: два разных отчёта

### `inet show interface` — паспорт интерфейса

```
hostname> inet show interface eth0
eth0  Link encap:Ethernet  HWaddr 00:15:17:e4:6c:5a
      inet addr:192.168.0.1  Bcast:192.168.0.255  Mask:255.255.255.0
      UP BROADCAST RUNNING MULTICAST  MTU:1500  Metric:70
      ...
      Configured by DHCP: yes
      Information requested from DHCP server: IP address, routes, DNS servers, NTP servers
      DHCP route metric: default (70)
      Class: access
      Speed: 1000Mb/s
      Duplex: Full
      Auto-negotiation: off
      Link detected: yes
```

|Поле|Что означает|
|---|---|
|`UP RUNNING`|Линк поднят и работает|
|`UP` без `RUNNING`|Интерфейс включён, но кабеля/связи нет|
|Нет `UP`|Интерфейс выключен программно|
|`Link detected`|Физическое наличие линка|
|`Speed` / `Duplex`|Согласованные параметры|
|`Class`|`access`, `trunk`, `slave`|
|`Configured by DHCP`|Откуда адрес|

### `inet show interface state` — роль и учёт в VPN

```
hostname> inet show interface state
Interface   Type         State
-------------------------------------
eth0        internal     enabled
eth0.1      internal     enabled
eth1        external     enabled
eth2        external     disabled
```

|Колонка|Что означает|Где задаётся|
|---|---|---|
|`Type`|`internal` / `external`|`[adapter] type` в `iplir.conf`|
|`State`|`enabled` / `disabled`|`inet ifconfig enable/disable`, `iplir adapter traffic`|

Вот здесь и видно расхождение: интерфейс может быть `UP RUNNING`, но `disabled` — линк есть, VPN его не использует.

### Прочие проверки

|Команда|Что показывает|
|---|---|
|`inet show routing`|Таблицу маршрутов, наличие default|
|`iplir show adapters`|Все активные интерфейсы и `allowTraffic`|
|`iplir show adapter eth1`|Секцию конкретного адаптера: группа, трафик, тип|
|`iplir show adapters groups`|Активные динамические интерфейсы (`ppp`, `wifi`)|
|`inet show usb-modem`|Состояние модема, SIM, PIN, оператор|
|`inet show wifi`|Режим, роль, подключение|
|`iplir info ethX`|Статистика фильтрации и туннелей по интерфейсу|

## 11. `up/down` против `enable/disable`

Это самое важное различие темы.

| |`up` / `down`|`enable` / `disable`|
|---|---|---|
|Что меняет|Состояние линка|Учёт интерфейса в `iplir.conf` и `allowTraffic`|
|Где видно|Флаги `UP`, `Link detected`|`State: enabled/disabled`, `iplir show adapters`|
|Влияет на VPN|Только косвенно|Напрямую|
|Сохраняется ли|Да, состояние интерфейса|Да, запись в конфигурации|
|Типичная ошибка|«Всё поднято, почему не работает»|«Почему после перезагрузки пропало»|

`inet ifconfig eth1 disable` не только выключает трафик, но и **удаляет интерфейс из `iplir.conf`**. После этого нужно снова `enable`, а не только `up`. И каждый раз выводится предупреждение проверить сетевые фильтры — оно не декоративное: фильтры могли быть написаны в расчёте на этот интерфейс.

## 12. Типичные ошибки

|Симптом|Причина|Лечение|
|---|---|---|
|`Link detected: yes`, трафика нет|Интерфейс не добавлен в `iplir.conf`|`inet ifconfig <if> enable` или `iplir adapter add <if> traffic on`|
|VLAN создан, адрес есть, трафика нет|Не выполнен `iplir adapter add ... traffic on`|Добавить и проверить `iplir show adapters`|
|После перезагрузки пропал интерфейс|Был только `up`, без `enable`|Добавить в конфигурацию|
|`inet ifconfig eth1 address` отказывает|Адрес из подсети другого интерфейса|Разнести подсети|
|Пропали DNS/NTP|Перешли с DHCP на статику|Прописать серверы вручную|
|Нет интернета при наличии линка|Нет маршрута по умолчанию или шлюз недоступен|`inet show routing`, проверить шлюз|
|Установили `trunk` — пропали адреса|Штатное поведение|Сначала создать VLAN, потом адресовать их|
|Bond не поднялся|Режим не соответствует топологии|HW↔HW: `balance-rr`/`active-backup`; HW↔switch: `802.3ad`/`balance-xor`|
|В bond «прыгает» голос/видео|`balance-rr` переупорядочивает пакеты|Использовать хэш-режим|
|Bond на VA нестабилен|Виртуализация не гарантирует bonding|Настроить на гипервизоре|
|Не применяется MTU на VLAN|MTU задают на trunk|Задать на физическом интерфейсе|
|Wi-Fi не подключается|Настройка при включённом `wlan0`|`inet wifi mode off`, настроить, включить|
|После `reset all` конфликт имён VLAN/bond|Записи остались в `iplir.conf`|Сначала `iplir adapter delete`, потом reset|
|Сломался кластер после правки интерфейсов|Изменены интерфейсы, задействованные в кластере|Не трогать их без окна обслуживания|

## 13. Чек-лист темы

1. Различаете четыре плоскости: линк, класс, адресация, учёт в VPN.
2. Понимаете разницу `up/down` и `enable/disable`.
3. Умеете настроить `access`-интерфейс с нуля до `enabled`.
4. Знаете ограничения адресов и масок.
5. Проверяете маршрут по умолчанию после DHCP.
6. Понимаете, что при переходе на статику теряются DNS/NTP от DHCP.
7. Умеете добавить alias и знаете про лимит интерфейсов.
8. Настраиваете VLAN через `trunk` + `vlan add` + добавление в `iplir.conf`.
9. Выбираете режим bond по топологии, а не по «скорости».
10. Знаете ограничения: 8 bond, нет MC-LAG, VA не гарантирует bonding.
11. Понимаете, где задаётся MTU для VLAN и bond.
12. Читаете `inet show interface` и `inet show interface state` без подсказки.
13. Не меняете интерфейсы кластера без окна.
14. Проверяете результат через `iplir show adapters`, а не только по линку.
