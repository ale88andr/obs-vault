## 1.1. Одна фраза, из которой всё вытекает

**ViPNet — это наложенная (overlay) защищённая сеть поверх обычных IP-сетей, в которой узлы адресуются не IP-адресами, а идентификаторами ViPNet ID, а трафик между ними шифруется на сетевом уровне по ГОСТ.**

Из этого следуют три инварианта, которые надо помнить всегда:

1. **Адресация отделена от транспорта.** Узел имеет ViPNet ID (не меняется) и может менять реальный IP хоть каждый день.
2. **Связь существует только там, где она разрешена в справочнике.** Нет связи в справочнике — нет ключа — нет трафика. Это не «открытый интернет с шифрованием».
3. **Политика задаётся центром.** Структура сети, связи, ключи и политики безопасности формируются в ViPNet Prime и рассылаются на узлы; локальная настройка — вторична

## 1.2. Два пространства адресов

| Пространство       | Что это                                                                                    | Кто использует                                             |
| ------------------ | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| **Реальный IP**    | адрес в физической сети (Ethernet, провайдер, NAT)                                         | маршрутизаторы, провайдеры                                 |
| **ViPNet ID**      | 4-байтовый идентификатор узла, в CLI пишется как `0x00010101`                              | сам ViPNet: маршрутизация защищённого трафика, выбор ключа |
| **Виртуальный IP** | «псевдо-IP» для приложений, привязанный к ViPNet ID или к реальному IP туннелируемого узла | приложения на защищённом узле                              |

Пример из документа: координатор `0x00010101`, второй `0x00020201`, клиенты `0x00020202…0x00020204`. Логика: старшие два байта — номер сети ViPNet, младшие — номер узла. Поэтому «сеть 1» и «сеть 2» — это разные ViPNet-сети, которые могут быть связаны между собой.

Зачем виртуальные IP: две локальные сети могут иметь одинаковую адресацию `192.168.1.0/24`. Приложения обращаются к «своему» виртуальному адресу, драйвер ViPNet подменяет его на реальный при отправке и обратно при приёме — **но только после успешной расшифровки пакета ключом отправителя**. Это одновременно решает конфликт адресов и даёт защиту от подмены адреса источника.
