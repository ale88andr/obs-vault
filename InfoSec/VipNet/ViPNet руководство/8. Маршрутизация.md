**Цель темы:** понять, как Coordinator выбирает маршрут из нескольких источником, чем административная дистанция отличается от метрики и веса, и как устроена маршрутизация по политикам (MultiWAN + DGD). Это мост между темой 7 (интерфейсы) и темой 9 (VPN): пока не исправна таблица маршрутов, шифрование не поможет.

## 1. Уровни принятия решения

Есть два независимых уровня: **какую таблицу использовать** и **какой маршрут внутри неё выбрать**.

```
IP-пакет
   │
   ▼
Активная политика маршрутизации
   ├── default → таблица Main
   └── пользовательская → правила по приоритету (1024–2048)
          ├── все признаки совпали → table N / table default / block
          └── не совпал хотя бы один → следующее правило
   ▼
Выбор лучшего маршрута в выбранной таблице
   1. Административная дистанция
   2. Метрика (для DHCP/PPP) → ECMP при равенстве
   3. Наиболее длинный префикс
   4. Объединение в multi-hop route с весами
   ▼
FIB → отправка пакета
```

|Таблица|Что содержит|Для чего|
|---|---|---|
|**Main** (по умолчанию)|`Connected`, `Static`, `DHCP`, `PPP`, `OSPF`, `BGP`|Обычная маршрутизация; политику изменить нельзя|
|**Пользовательские**|Только `Static`|MultiWAN, резервирование каналов, политика по адресу/интерфейсу/DSCP|

Ключевое следствие: **маршруты в локальные сети (`Connected`) есть только в Main**. Поэтому в каждой пользовательской политике обязательно нужно правило «весь трафик → table default», иначе локальная связность ломается.

## 2. Административная дистанция

Дистанция — приоритет **источника** маршрута. Меньше — приоритетнее.

|Источник|По умолчанию|Можно изменить|Команда|
|---|---|---|---|
|Static|**10**|Да, 1–255|`inet route add ... distance <1–255>`|
|DHCP / PPP|**70**|Да, 1–255|`inet dhcp client route-distance <1–255>`|
|OSPF|**110**|Нет|—|
|eBGP|**20**|Нет|—|
|iBGP|**200**|Нет|—|

Правила:

- Дистанция статического маршрута **не может совпадать** с дистанцией OSPF или BGP — такой маршрут будет отклонён.
- PPP использует дистанцию DHCP отдельно не задаётся — она равна дистанции DHCP.
- Дистанция OSPF/BGP задаётся для протокола целиком, а не для отдельного маршрута.

Пример выбора:

```
10.0.5.0/24:
  S  via 10.0.1.1  distance 10    → > выбрать
  D  via 10.0.2.1  distance 70
  O  via 10.0.3.1  distance 110
```

Если у двух маршрутов из **одного источника** дистанции равны, участвуют оба и они объединяются в один `multi-hop route`. Если префиксы разные (`10.0.0.0/8` и `10.0.0.0/16`), лучшими считаются оба, а для конкретного пакета побеждает более длинный префикс.

## 3. Метрика и вес

|Параметр|Где используется|Смысл|
|---|---|---|
|**Метрика**|DHCP, PPP, OSPF|Приоритет внутри одного источника; меньше — лучше|
|**Вес**|Static, multipath BGP|Доля трафика через конкретный шлюз|

- Метрика DHCP задаётся **на каждом интерфейсе**, где включён DHCP с получением маршрутов: `inet ifconfig <if> dhcp route-metric <1–255>`.
- Метрика по умолчанию для DHCP/PPP — **70**: `inet dhcp client route-default-metric <1–255>`.
- Метрика PPP задаётся отдельно: `inet usb-modem set route-metric <1–255>`.
- Метрика OSPF вычисляется автоматически, вручную не настраивается.
- Вес по умолчанию = **1**, вес **0 недопустим**.

```
10.100.2.0/24 [30/23] (weight 1) via 10.1.30.202, eth1
                       (weight 1) via 10.1.31.201, eth2
```

Здесь `[30/23]` = дистанция/метрика. Соотношение весов 1:2:3 даёт распределение трафика 1/6, 2/6, 3/6. Балансировка работает **только если маршруты признаны лучшими**.

> Осторожно: если хотя бы один шлюз в `multi-hop route` выходил из строя, работоспособность всего маршрута **не гарантируется**. Резервирование надо строить через политики и DGD, а не только через несколько `next-hop`.

## 4. Просмотр таблицы маршрутизации

```
hostname> inet show routing
hostname> inet show routing static table default
hostname> inet show routing dhcp
hostname> inet show routing ospf
hostname> inet show routing bgp
hostname> inet show routing static table 1024
hostname> inet show routing static table name GW-1
```

|Атрибут|Расшифровка|
|---|---|
|`C`|`connected` — подсеть подключённого интерфейса|
|`S`|`static`|
|`O`|`OSPF`|
|`B`|`BGP`|
|`D`|`DHCP` / `PPP`|
|`>`|`selected route` — лучший по дистанции|
|`*`|`FIB route` — реально участвует в маршрутизации|

`>` и `*` — разные вещи: `>` выбирается среди маршрутов с разной дистанцией, `*` попадает в FIB. Если маршрут лучший, но не попал в FIB — смотрите политики.

## 5. Статические маршруты

```
# Default route
hostname# inet route add default next-hop 192.168.0.1 [distance 20 [weight 1]]

# Сеть
hostname# inet route add 10.0.5.0 netmask 255.255.255.0 next-hop 10.0.1.1 distance 20 weight 1

# Пользовательская таблица (создаётся автоматически, если её нет)
hostname# inet route add default next-hop 89.135.15.2 table 1024 name GW-1

# Удаление
hostname# inet route delete default next-hop 192.168.0.1
hostname# inet route delete 10.0.5.0 netmask 255.255.255.0 next-hop 10.0.1.1
hostname# inet route clear [table 1024 | table name GW-1]
```

Если при удалении не указать маску или шлюз и маршрутов несколько — Coordinator покажет список и предложит удалить все (`y`).

Балансировка:

```
hostname# inet route add 10.0.5.0 netmask 255.255.255.0 next-hop 10.0.1.1 distance 20 weight 1
hostname# inet route add 10.0.5.0 netmask 255.255.255.0 next-hop 10.0.4.3 distance 20 weight 1
```

Одинаковая дистанция, разные шлюзы, заданные веса — единственный корректный рецепт.

## 6. Маршруты DHCP и PPP

```
# Административная дистанция всех DHCP-маршрутов
hostname# inet dhcp client route-distance 80
# Отдельно для default (если не задано — как у остальных)
hostname# inet dhcp client route-distance 80 default-route 60

# Метрика на конкретном интерфейсе
hostname# inet ifconfig eth1 dhcp route-metric 50
hostname# inet ifconfig eth1 dhcp route-metric none

# Метрика по умолчанию для DHCP/PPP
hostname# inet dhcp client route-default-metric 70

# Метрика PPP (3G/4G)
hostname# inet usb-modem set route-metric 40
hostname# inet usb-modem set route-metric none

hostname> inet show dhcp client
hostname> inet show routing dhcp
```

Специфичная метрика DHCP поддерживается на Ethernet, VLAN, Wi-Fi и bond. Если на двух интерфейсах метрики одинаковы — маршруты объединяются в multi-hop.

Типовая задача: есть DHCP и 3G/4G. Чтобы резервный канал не перехватил default, задайте PPP-метрику **меньше** любой DHCP-метрики — и наоборот, если.basic primary — DHCP.

## 7. OSPF: что реально поддерживается

Условия применимости: OSPF v2, multicast, соседи напрямую, политика безопасности разрешает IP proto 89.

|Ограничение|Что это значит на практике|
|---|---|
|Толькоarea `backbone` (0) и `standard`|Нет stub / totally stubby / NSSA|
|Тип сети только `Broadcast`|Не настраивается|
|Нельзя менять Hello/Dead|Не настраиваются|
|Нет `reference-bandwidth`, `cost`, `auto-cost`|Метрика вычисляется автоматически|
|Redistribute только `static` и `dhcp`|Нельзя импортировать BGP/connected произвольно|
|Нет import/export policy|Фильтрация маршрутов недоступна|
|Нет Virtual Links|Удалённые сегменты — только через L2OverIP|
|Не более **128** сетей|Жёсткий предел|

```
hostname# inet ospf mode on
hostname# inet ospf network add 192.168.1.0 netmask 255.255.255.0 area 1
hostname# inet ospf area 1 auth on md5
hostname# inet ospf interface eth1 keys add 1
hostname# inet ospf redistribute add static
hostname# inet ospf priority 200 interface eth1
hostname# inet ospf router-id 10.0.0.1

hostname> inet ospf show configuration
hostname> inet ospf show neighbour
hostname> inet ospf show database
hostname> inet show routing ospf
```

Аутентификация обязательна на практике: `pswd` (пароль в открытом виде) или `md5` (зашифрованный ключ). Настройки должны совпадать на обеих сторонах. На каждом интерфейсе — до 255 ключей с уникальным `keyid` и не более одного пароля.

Фильтры — три обязательных правила:

```
hostname# firewall local add 1 rule "OSPF unicast" src <IP-соседа> dst @local service @OSPF pass
hostname# firewall local add 2 rule "OSPF multicast" src <IP-соседа> dst @multicast service @OSPF pass
hostname# firewall local add 3 rule "OSPF out" src @local dst @any service @OSPF pass
```

Между координаторами дополнительно нужны `firewall vpn` на proto 89. Без этих фильтров OSPF не заработает.

DR/BDR: приоритет по умолчанию **1**, диапазон 0–255; `0` — нельзя стать DR/BDR; router-id по умолчанию — максимальный IP интерфейса; одинаковые router-id мешают установить соседство. Появление新的 роутера с большим приоритетом не смещает текущего DR.

Нюанс из Manual: если HW напрямую связан с другими координаторами, у IP-адресов доступа этих координаторов стоит задавать **метрику 1** — тогда защищённый трафик пойдёт через соседнего координатора по кратчайшему пути.

Для удалённых сегментов OSPF работает поверх **L2OverIP** (proto 97), при этом на HW-1/HW-2, terminating L2, OSPF не нужен.

## 8. BGP и BFD (обзорно, но с командами)

Порядок выбора лучшего маршрута в BGP:

|№|Критерий|Направление|
|---|---|---|
|1|Weight — больше|Локально|
|2|Local preference — больше|Только внутри AS|
|3|Локальный маршрут|Локально|
|4|AS-path — короче|Анонсируется|
|5|Origin: IGP优于 EGP|Анонсируется|
|6|MED — меньше|Внутрь AS и в соседнюю AS|
|7|eBGP优于 iBGP|Локально|
|8|Router ID — меньше|Локально|
|9|IP соседа — меньше|Локально|

```
hostname# inet bgp on
hostname# inet bgp router as 65001
hostname# inet bgp router id 10.0.0.1
hostname# inet bgp neighbor add 10.1.1.2 remote-as 65002 [port 179]
hostname# inet bgp neighbor 10.1.1.2 set password
hostname# inet bgp neighbor 10.1.1.2 set ttl-security 2
hostname# inet bgp neighbor 10.1.1.2 set ebgp-multihop 5
hostname# inet bgp network add 192.168.0.0 netmask 255.255.255.0
hostname# inet bgp network redistribute static on
hostname# inet bgp neighbour 10.1.1.2 set default-originate on

hostname> inet bgp show summary
hostname> inet bgp show neighbors list
hostname> inet bgp show network
hostname> inet show routing bgp
hostname# inet bgp clear all
hostname# inet bgp off
```

По умолчанию HW **не анонсирует** свои подсети — только принимает и передаёт дальше.socinclude `network add` или `redistribute`. Механизм `default-originate` не требует статического маршрута и не добавляет default в BGP-таблицу.

Фильтрация: `inet prefix-list`, `inet bgp as-path-filter`, `inet bgp community-list`, `inet route-map` с `match` / `set` / `on-match`. Route map можно повесить на соседа (`in`/`out`) или на redistribute.

iBGP: `next-hop-self` и Route Reflection (`cluster-id`, `route-reflector client add`, `outbound-policy on`). ECMP/UCMP: `inet bgp router bestpath as-path-relax on`, `... bandwidth {ignore|skip|min|default}`; UCMP требует поддержки community `Link bandwidth` соседями.

**BFD** ускоряет detection отказа по сравнению с BGP Hello:

```
hostname# inet bfd on
hostname# inet bfd profile add FAST 3 100 100
hostname# inet bgp neighbor 10.1.1.2 set bfd profile FAST
hostname> inet bfd show
hostname> inet bfd show status 10.1.1.2
```

Профиль по умолчанию: `detect-multiplier 3`, `receive-interval 300 мс`, `transmit-interval 300 мс`. Для iBGP и eBGP с TTL ≠ 1 BFD-сессия поднимается только после BGP-сессии; для eBGP с TTL = 1 — независимо.

## 9. MultiWAN: политики + DGD

Сценарий: два провайдера, основной GW-1 и резервный GW-2.

```
              GW-1 (основной)
                 │
   LAN ── HW ────┤
                 │
              GW-2 (резерв)
   DGD проверяет GW-1 → при down активирует политику через GW-2
```

### Шаг 1. Убрать default из Main и создать таблицы

```
hostname# inet route delete default
hostname# inet route add default next-hop 89.135.15.2 table 1024 name GW-1
hostname# inet route add default next-hop 210.11.0.2 table 1025 name GW-2
```

### Шаг 2. Политики

```
hostname# inet policy rule add route-via-GW-1-policy 1024 table default
hostname# inet policy rule add route-via-GW-1-policy 1025 table name GW-1

hostname# inet policy rule add route-via-GW-2-policy 1024 table default
hostname# inet policy rule add route-via-GW-2-policy 1025 table name GW-2

hostname> inet show policy rule active
```

Правило с приоритетом 1024 (`table default`) обязательно: через Main идут `connected`-маршруты локальных сетей. Приоритет 1024–2048, меньше — выше.

Признаки трафика:

```
hostname# inet policy rule add P 1024 match address from 192.168.1.0/30
hostname# inet policy rule add P 1024 match address to 10.0.0.0/8
hostname# inet policy rule add P 1024 match inbound-interface eth1
hostname# inet policy rule add P 1024 match outbound-interface eth2
hostname# inet policy rule add P 1024 match dscp 0x80
hostname# inet policy rule add P 1024 table name PROXY-DEFAULT   # или block
hostname# inet policy active P
hostname# inet policy active default
```

### Шаг 3. DGD

```
hostname# inet dgd mode on
hostname# inet dgd next-hop add GW-1 address 89.135.15.2 check icmp
hostname# inet dgd next-hop add GW-2 address 210.11.0.2 check icmp

hostname# inet dgd rule add GW-1-up match-next-hop GW-1 up
hostname# inet dgd rule add GW-1-up action-priority 1 service route command policy active route-via-GW-1-policy

hostname# inet dgd rule add GW-1-down match-next-hop GW-1 down
hostname# inet dgd rule add GW-1-down match-next-hop GW-2 up
hostname# inet dgd rule add GW-1-down action-priority 1 service route command policy active route-via-GW-2-policy

hostname# inet dgd rule add all-down match-next-hop GW-1 down
hostname# inet dgd rule add all-down match-next-hop GW-2 down
hostname# inet dgd rule add all-down action-priority 2 service log command All-Routers-Down

hostname# inet dgd mode off
hostname# inet dgd mode on
hostname> inet show dgd next-hop
```

Параметры: `interval-time` 1–120 (по умолчанию 3 с), `response-time` 1–120 (3 с), `retries-count` 1–10 (3), `syslog-level` 0–4 (3). Если проверка идёт через `tcp80`/`tcp443` — нужен разрешающий `firewall local`.

### Запреты и ловушки MultiWAN

|Не делайте|Почему|
|---|---|
|Добавлять в пользовательские таблицы маршруты, противоречащие Main|Непредсказуемый выбор|
|Использовать DHCP/OSPF-маршруты для резервного канала|Они попадают в Main и перебивают политику; `inet ifconfig <if> dhcp route off`|
|Активировать политику, не проверив доступ к себе|Можно потерять управление устройством|
|Использовать один IP одновременно для DGD и `testip` кластера|Циклическая перезагрузка обоих узлов кластера|
|Забыть правило `table default`|Пропадут маршруты в локальные сети|

Резервным каналом может быть встроенный модем: отключить `route`, в `inet usb-modem modify config` добавить в первую строку `:10.255.255.254`, затем table 1026 `ModemTable`.

## 10. DSCP и приоритизация

8 классов приоритета по RFC 2474/2475: Assured Forwarding, Class Selector, Default PHB (Best Effort). При шифровании метка переносится из открытой части IP-пакета в закрытую, при расшифровании — обратно; по пути она может быть изменена или сброшена.

Гарантия приоритета выполняется **только если** коммутатор поддерживает QoS и включён Ethernet Flow Control. Метку DSCP можно использовать как признак в политике маршрутизации (`match dscp 0x80`).

## 11. Типичные ошибки

|Симптом|Причина|Лечение|
|---|---|---|
|Нет интернета при поднятом линкe|Нет default-маршрута|`inet show routing`, `inet route add default ...`|
|Маршрут есть в таблице, но не работает|Нет `*` FIB — политика отправляет по другой таблице|`inet show policy rule active`|
|Статический маршрут не добавился|`distance` совпал с OSPF (110) или BGP (20/200)|Выбрать другое значение|
|DHCP перехватил default у 3G/4G|Метрики равны 70|`inet usb-modem set route-metric <70` или поднять DHCP-метрику|
|OSPF-сосед не поднимается|Нет фильтров proto 89 / multicast|`firewall local` + `firewall vpn`|
|OSPF-сосед не поднимается|Одинаковый `router-id`|`inet ospf router-id <другой>`|
|OSPF не видит удалённый сегмент|Попытались сделать Virtual Link|Только L2OverIP (proto 97)|
|BGP ничего не анонсирует|Нет `network add` / `redistribute`|Добавить анонс|
|BGP-сессия есть, маршрутов нет|Route map по умолчанию отбрасывает несовпавшие маршруты|Добавить permit-блок|
|Резервный канал не переключается|DHCP-маршруты активны в Main|`dhcp route off`, убрать default из Main|
|После активации политики потеряли доступ|Не было правила `table default`|Добавить правило 1024 и проверить заранее|
|DGD переключает постоянно|Тестовый адрес совпадает с `testip` кластера|Разные адреса|
|Кластер ушёл в цикл перезагрузки|Одинаковый IP в DGD и cluster `testip`|Немедленно развести адреса|
|Голос/видео «прыгает» между каналами|`multi-hop route` с балансировкой по пакетам|Политики по адресу/DSCP вместо ECMP|
