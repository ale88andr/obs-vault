**Цель темы:** пройти полный цикл ввода координатора в эксплуатацию — от получения `ds5` до проверки связи с узлом сети, — и понять, какие действия необратимы, а какие можно откатить.

## 1. Что такое «ввод в эксплуатацию»

Ввод в эксплуатацию — это не «настройка». Это **одноразовая операция**, которая создаёт на устройстве личность: ViPNet ID, ключи, справочники, начальную конфигурацию.

Три фазы:

```
Фаза A. Подготовка (в Prime и у заказчика)
   узел создан, связи заданы, ds5 выпущен, лицензии назначены
        │
        ▼
Фаза B. Инициализация (на устройстве)
   мастер: часовой пояс → ds5 → admin → интерфейсы → NAT → проверка связи
        │
        ▼
Фаза C. После инициализации
   первое подключение к Prime, обновления, резервная копия, регламент
```

Ключевая особенность: **успешная инициализация ещё не означает, что координатор введён в эксплуатацию**. Пока он не связался с Prime и не получил актуальные справочники и ключи, это устройство с локальной конфигурацией и потенциально устаревшей картиной сети.

## 2. Что должно быть готово до включения

| Что                                            | Кто даёт                       | Зачем                                        | Цена ошибки                                                     |
| ---------------------------------------------- | ------------------------------ | -------------------------------------------- | --------------------------------------------------------------- |
| Файл `ds5` + пароль к нему                     | Администратор сети ViPNet      | Справочники, ключи, лицензии, параметры узла | Без него инициализация не начнётся                              |
| Доменное имя и ViPNet ID сервера Prime         | Администратор сети             | Проверка связи, диагностика                  | Неверный адрес — проверка связи не пройдёт                      |
| USB-токен (если аутентификация по сертификату) | Администратор сети / УЦ        | Сертификат и закрытый ключ `admin`           | Токен придётся переинициализировать, данные на нём будут стёрты |
| Настройка ViPNet SafeBoot                      | Администратор устройства       | Доверенная загрузка на HW-платформах         | Устройство не выйдет в рабочий режим по политике                |
| SIM-карта                                      | Для HW50 A1, HW50 N3, HW100 N3 | Мобильный канал                              | Разбирать корпус повторно                                       |
| План IP-адресации                              | Сетевая служба                 | Интерфейсы, шлюз, DNS, NTP                   | Переделка на месте                                              |
| Решение по NAT                                 | Архитектор                     | Static или Dynamic NAT                       | Неверный режим — VPN не поднимется                              |
| Носитель                                       | Вы                             | USB (FAT32/ext2/ext3/ext4) или CD            |                                                                 |

> **Правило, которое надо проговорить заказчику до выезда:** после первого успешного подключения к Prime дистрибутив ключей, использованный для ввода в эксплуатацию, **становится недействительным**. Его нельзя применить для повторной инициализации. Хранить его «на всякий случай» бессмысленно.

## 3. Три канала доставки `ds5`

```
                    ┌──────────────────────────────┐
                    │  ViPNet Coordinator HW / VA  │
                    └──────────────┬───────────────┘
                                   │
        ┌──────────────────────────┼──────────────────────────┐
        │                          │                          │
   USB / CD                   TFTP (eth1)              Консоль/серийный
   монитор+клавиатура         ПК ↔ eth1 напрямую       порт + USB/CD
   или COM-консоль            169.254.241.5 ↔ .1       38400 8N1, VT100+
        │                          │                          │
   «u» или «c» в мастере      «t» + tftp put             «u»/«c» в мастере
```

|Канал|Когда выбирать|Подводные камни|
|---|---|---|
|USB / CD|Есть физический доступ, HW или VA с пробросом USB|На Hyper-V и Oracle VM Server USB в ВМ не поддерживается|
|TFTP|Нет USB-порта, VA без проброса, выезд «с ноутбуком»|Windows по умолчанию не имеет TFTP-клиента; брандмауэр, Defender, обновления и ViPNet Client блокируют передачу|
|Консоль|Нет монитора, есть COM-порт|Неверная скорость или кодировка — «кракозябры» вместо мастера|

### TFTP: точные параметры

```
ПК: 169.254.241.5  ──кабель RJ45 Cat.5──  eth1 координатора: 169.254.241.1
```

На ПК должны быть включены «Клиент TFTP» и «Простые службы TCPIP», отключены брандмауэр, Defender, Windows Update и защита ViPNet Client. Передача:

```
tftp -i 169.254.241.1 put <имя_файла_ds5>
```

Подключение к мастеру — по адресу `169.254.241.1`, терминал VT100+, кодировка KOI8-R, terminal type `linux`, ширина 120 символов.

### Консоль: точные параметры

|Параметр|Значение|
|---|---|
|Скорость|38400|
|Данные / чётность / стоп-биты|8 / None / 1|
|Управление потоком|None|
|Терминал|VT100+|
|Кодировка|KOI8-R|

## 4. Мастер инициализации: два режима, один сценарий

| |Консольный режим|Полноэкранный режим|
|---|---|---|
|Как выбрать|Ввести `1` после входа|Ввести `2`|
|Для чего|COM-порт, TFTP, удалённая работа|Локальный монитор и клавиатура|
|Навигация|Цифры и `Enter`|`Next` / `Yes` / `No`|
|Логика шагов|Идентична|Идентична|

Вход в мастер — временной учётной записью:

```
login: user
password: user
```

Это не `admin`. Учётная запись `user/user` существует только для первичной инициализации; пароль суперадминистратора вы задаёте в мастере.

### Маршрут мастера

```
1. Соглашение
2. Континент / UTC → страна → часовой пояс → подтверждение → дата/время
3. Способ доставки ds5: t / u / c
4. Выбор файла ds5 (если их несколько)
5. Пароль к ds5
6. Способ настройки: 1 — вручную, 2 — загрузить конфигурацию
7. Пароль суперадминистратора admin
8. Токен (если в ds5 включена сертификатная аутентификация)
9. Интерфейсы eth0, eth1, … : UP/DOWN → DHCP/StaticIP → адрес/маска
10. Шлюз по умолчанию (если нет DHCP)
11. DNS-сервер: автозапуск on/off → дополнительный DNS
12. NTP-сервер: автозапуск on/off → дополнительный NTP
13. Имя устройства
14. Диапазон виртуальных адресов
15. Проверка связи с узлом ViPNet
16. Режим подключения к внешней сети: static NAT / dynamic NAT
17. Запуск драйверов и служб
18. «ViPNet Coordinator HW successfully deployed!»
```

## 5. Разбор ключевых шагов

### 5.1 Часовой пояс и время

Сначала континент (или UTC), затем страна, затем часовой пояс. Если в стране один пояс — он выбирается автоматически. Дату и время можно изменить вручную.

Это не формальность: от времени зависят `timediff` (окно допустимого расхождения), проверка сертификатов и корректность журналов. Часы, ушедшие на час, дают «туннель есть, трафика нет» ещё до того, как вы доедете до офиса.

### 5.2 Выбор `ds5`

Если на носителе один файл — он выбирается автоматически. Если несколько — мастер показывает список с именами и идентификаторами узлов:

```
Found several application initialization files
  1. HW1000-270E033A  0x270e033a
  2. HW1000-270E033B  0x270e033b
```

В консольном режиме список длиннее 20 файлов выводится постранично. В полноэкранном длинные имена обрезаются — полное имя показывается под списком при выборе.

> Проверяйте ID, а не только имя. Одинаковые имена узлов в разных сетях — обычная история.

### 5.3 Пароль `admin`

Задаётся в мастере и подтверждается. Это единственный суперадминистратор; второго создать нельзя, восстановления по email нет. Пароль должен быть в хранилище секретов, а не в заметках выездного инженера.

### 5.4 Токен

Если в `ds5` указана сертификатная аутентификация, мастер попросит токен:

```
Insert token and press Enter
Do you want to reinitialize token? [Yes/No]
Enter admin-token pincode
Enter new user-token pincode
```

Два PIN: администратора (запись сертификата) и пользователя (вход). При инициализации **все данные на токене удаляются**. Несколько неверных PIN администратора подряд блокируют токен навсегда — записать сертификат больше не получится.

Если нужен существующий сертификат: на вопрос о переинициализации отвечаете `No` и вводите PIN пользователя.

### 5.5 Интерфейсы

Мастер идёт по порядку, начиная с `eth0`. Для каждого:

- `UP` — настраиваем, `DOWN` — пропускаем;
- `DHCP` или `StaticIP`;
- для статики — IP-адрес и маска.

Ограничения, которые проверяет мастер:

|Запрещено|Почему|
|---|---|
|`0.0.0.0`|Невалидный адрес|
|Маски `0.0.0.0`, `255.255.255.254`, `255.255.255.255`|Не поддерживаются|
|Два интерфейса в одной подсети|Конфликт маршрутизации|

Если ни на одном интерфейсе не выбран DHCP, мастер попросит шлюз по умолчанию.

### 5.6 DNS и NTP

Для каждого сервера два вопроса: запускать ли службу при загрузке и добавлять ли внешний сервер.

- По умолчанию для DNS используются корневые серверы; для NTP — публичные.
- В закрытом контуре публичные адреса бесполезны: нужен внутренний DNS/NTP.
- NTP критичен: без синхронизации времени VPN будет «мигать».

### 5.7 Имя устройства

Шаблон по умолчанию:

```
<исполнение>-<идентификатор узла>
например: HW1000-270E033A
```

Имя можно изменить. Практика: использовать схему `роль-площадка-номер`, а ID оставлять в документации. Имя видно в Prime и в журналах.

### 5.8 Диапазон виртуальных адресов

По умолчанию:

```
11.0.0.1 – 11.255.255.254   (11.0.0.1/8)
```

Для диапазонов туннелируемых узлов адреса берутся из `<x+1>.0.0.1 – <x+1>.255.255.254`, где `x` — первый октет. То есть при базе `11.0.0.0/8` диапазоны получат `12.0.0.0/8`.

Если `11.0.0.0/8` пересекается с реальной адресацией заказчика — **менять здесь**, на инициализации, а не после ввода в эксплуатацию. Смена базы на работающей сети пересчитывает виртуальные адреса у всех и рвёт established-сессии.

### 5.9 Проверка связи

Мастер предлагает выбрать узел из списка связей и проверить с ним VPN:

```
Now the special temporary network settings will be applied
and ViPNet will be launched in order to probe the VPN connection
```

Что происходит:

1. Применяются временные сетевые настройки.
2. Запускается VPN-драйвер.
3. Проверка может занять несколько минут.
4. При успехе **все настройки, сделанные до проверки, сохраняются в `iplir.conf`**.
5. При неудаче предлагается журнал IP-пакетов; `Ctrl+C` — вернуться к настройке, `Enter` — продолжить.

Если интерфейсы не настраивались, шаг пропускается.

> Проверка — единственная возможность узнать до выезда, что схема NAT, порт и адресация сходятся. Пропускать её «потому что и так понятно» — худшая экономия времени в проекте.

## 6. Static NAT и Dynamic NAT на инициализации

Это первый развилка, от которой зависит, поднимется ли VPN вообще.

```
Статическая трансляция (Static NAT)
   координатор имеет предсказуемый внешний адрес/порт
   ┌──────────┐    UDP 55777    ┌────────┐    ┌──────────┐
   │ Coord A  │ ──────────────► │  NAT   │ ──►│ Internet │
   └──────────┘  port forwarding└────────┘    └──────────┘
   в мастере: выбрать внешний интерфейс и при необходимости изменить UDP-порт

Динамическая трансляция (Dynamic NAT)
   внешний адрес меняется, координатор сам регистрируется у сервера соединений
   ┌──────────┐    исходящий    ┌────────┐    ┌──────────────────┐
   │ Coord B  │ ──────────────► │  NAT   │ ──►│ Сервер соединений│
   └──────────┘                 └────────┘    └──────────────────┘
   в мастере: выбрать координатор из списка связей + внешний интерфейс
```

|Вопрос мастера|Static NAT|Dynamic NAT|
|---|---|---|
|UDP-порт|По умолчанию 55777; можно изменить|Не спрашивается|
|Внешний интерфейс|Выбирается|Выбирается|
|Координатор-посредник|Не нужен|Выбирается из связей в `ds5`|
|IP координатора|Не нужен|Может потребоваться ввести вручную|
|Условие работы|Проброс порта на NAT|Наличие связи с координатором|

### Две ловушки

1. **Несколько координаторов за одним NAT.** Их UDP-порты должны быть разными, иначе проброс неоднозначен. Документ говорит это прямо.
2. **Нет связей с координаторами.** При выборе Dynamic NAT появится:

```
Your VPN host has no links with VPN coordinators
```

Это не ошибка мастера, а ошибка планирования в Prime: связи не заданы или в `ds5` попал не тот узел.

## 7. Что происходит после «successfully deployed»

Мастер завершается, но работа только начинается.

|Шаг|Что сделать|Зачем|
|---|---|---|
|1|Войти как `admin`, выполнить `enable`|Проверить пароль и режим настройки|
|2|Проверить `version`|Убедиться в исполнении, платформе, версии ПО и лицензии|
|3|Проверить `iplir show key-info`|Даты ключа, `My network ID` / `My host ID`, состояние криптодрайвера|
|4|Проверить `iplir info eth0`|Драйвер работает, туннели считаются|
|5|Выполнить `iplir ping 0x...`|Связь с конкретным узлом|
|6|Дождаться первого контакта с Prime|Получить актуальные справочники, ключи, лицензии|
|7|Проверить `machine show backup`|Резервное копирование включено и работает|
|8|Настроить MFTP-транзит, если в сети есть координаторы ниже 4.5.1|Совместимость|
|9|Осознанно решить судьбу DPI|См. предупреждение ниже|

### Про DPI после инициализации

Документ предлагает при ненужности DPI освободить ресурсы:

```
hostname# service dpi mode off
```

Но с версии 5.4.0 DPI включена по умолчанию **независимо от лицензии**, потому что обеспечивает работу части фильтров. После выключения нельзя создавать фильтры по:

- приложениям и прикладным протоколам;
- SSL/TLS-инспекции;
- флагам TCP-сегмента;
- URL, HTTP-методу, MIME-типу;
- действительному IP прокси-клиента;
- группам «Веб-клиенты».

Это не «оптимизация», а смена функциональности. Решение фиксируется в проекте, а не принимается «по привычке».

### Доступ после инициализации

- Веб-интерфейс по HTTP/HTTPS разрешён **только с защищённых узлов ViPNet**, связанных с координатором. С произвольного ноутбука в открытой сети он недоступен — это не поломка.
- CLI: локальная консоль, COM-порт или SSH с защищённых узлов.
- Одновременно — не более 32 подключений с разными типами учётных записей.

## 8. Проверки в CLI

|Задача|Команда|Что считать нормой|
|---|---|---|
|Кто мы и с какой лицензией|`version`|Product, Platform, Serial, License, версия 5.4.2|
|Ключ обновлений и драйвер|`iplir show key-info`|Даты в будущем, `GOST ... Ready`, ID совпадает с ожидаемым|
|Драйвер и туннели|`iplir info eth0`|`Tunnels statistics`, `Current`/`Peak` в пределах `License`|
|Связь с узлом|`iplir ping 0x270e000a`|`Connection successful`|
|Итоговая конфигурация|`iplir show config`|Секции `[id]`, `[misc]`, `[adapter]` соответствуют проекту|
|Резервное копирование|`machine show backup`|Расписание включено, есть последняя копия|
|Состояние IPS/лицензий|`service ips show status`|Если IPS используется — базы и сроки|
|Очередь обновлений|`machine update-queue`|Нет «зависших» обновлений|

Пример успешной проверки:

```
hostname> iplir ping 0x15ea000d
Check connection with 0x15ea000d...
Connection successful
```

`iplir ping` работает по ViPNet ID, а не по IP. Автодополнение берёт данные из списка связей; служба `iplircfg` должна быть запущена (`iplir start`).

## 9. Повторная инициализация и восстановление

Есть два разных сценария, и их постоянно путают.

||Индивидуальная конфигурация|Универсальная конфигурация|
|---|---|---|
|Расширение|`.ecf`|`.vbe`|
|Чем защищена|Ключом обмена с Prime|Паролем, заданным при экспорте|
|Что содержит|Всё: VPN, интерфейсы, маршруты, фильтры, NAT, кластер, MFTP, журналы, SSH-ключи|Только МЭ, интерфейсы, маршрутизацию|
|Переносимость|Только при том же ключе обмена|Между исполнениями и версиями 4.3.2/4.5.x, xFirewall 5.x|
|Когда использовать|Восстановление после сбоя, замена узла, кластер|Миграция площадки, тиражирование|

### Восстановление `.ecf` на работоспособном устройстве

```
hostname# machine config import
```

Далее: подключить USB, выбрать файл, перезагрузиться.

### Восстановление `.ecf` на неработоспособном устройстве

```
1. Получить новый ds5 (или убедиться, что старый ещё валиден)
2. Записать на носитель: .ecf + ds5
3. hostname# admin remove keys
4. Перезагрузить
5. Пройти шаги 1–14 мастера инициализации
6. На шаге 15 выбрать «2» — загрузку конфигурации
7. Выбрать файл .ecf
8. На вопрос об импортированных настройках аутентификации ответить No
9. Перезагрузить
```

### Когда старый `ds5` ещё годится

Только при одновременном выполнении трёх условий:

1. Он создан **после** первого ввода устройства в эксплуатацию и подключения к Prime.
2. С момента его создания **не обновлялся ключ обмена** для связи с Prime.
3. **Не менялся способ аутентификации**.

Дату последнего обновления ключа показывает `Key effective date` в `iplir show key-info`. Это прямая связь с темой 2: если дата позже даты вашего дистрибутива — дистрибутив непригоден.

> `admin remove keys` — команда с глобальной блокировкой: завершаются сессии всех пользователей. Это не «удалить один ключ», это обнуление ключевой информации.

## 10. Типичные ошибки

|Симптом|Причина|Лечение|
|---|---|---|
|Мастер не видит `ds5` на USB|Файловая система не FAT32/ext2/ext3/ext4, или файл не на корне|Переформатировать носитель, положить файл в корень|
|TFTP «висит» и файл не передаётся|Брандмауэр/Defender/обновления/ViPNet Client на ПК|Отключить на время, проверить связь `169.254.241.5 ↔ .1`|
|В консоли «кракозябры»|Неверная кодировка или скорость|KOI8-R, 38400 8N1, VT100+|
|«Your VPN host has no links with VPN coordinators»|В Prime не заданы связи или выбран не тот узел|Исправить связи, перевыпустить `ds5`|
|Проверка связи не проходит|NAT, порт, маршрут, время, фильтр|Смотреть журнал IP-пакетов, проверить UDP-порт и часы|
|Два координатора за одним NAT не работают одновременно|Одинаковый UDP-порт|Разные порты на каждом|
|После повторной инициализации «нет ключей»|Использован старый `ds5` после первого контакта с Prime|Запросить новый дистрибутив|
|Кластер не синхронизируется|Узлы инициализированы разными `ds5`|Один дистрибутив на оба узла|
|Восстановление `.ecf` не применяется|С момента копии обновлён ключ обмена|Новая копия; либо новый `ds5` и повторная инициализация|
|После восстановления `.ecf` не пускает `admin`|Перезаписали настройки аутентификации|Восстанавливать с ответом `No` на вопрос об overwrite|
|Веб-интерфейс «не открывается» с ноутбука|Доступ разрешён только с защищённых узлов|Подключаться с ViPNet-узла или локально|
|После `service dpi mode off` не создаются фильтры|Отключена подсистема, от которой зависят функции МЭ|Включить DPI или принять ограничения|
|Устройство не грузится по политике|Не настроен SafeBoot|Настроить до инициализации|
|VA не видит USB-токен|Платформа без проброса USB|Использовать платформу с пробросом или пароль|

## 11. Чек-лист темы

1. До выезда получены `ds5`, пароль, доменное имя и ViPNet ID Prime.
2. Проверены связи узла в Prime и назначенные лицензии.
3. Известно, будет ли сертификатная аутентификация, и есть ли токен.
4. Для HW настроен SafeBoot; для N3/A1 установлена SIM.
5. Выбран канал доставки `ds5` и проверен на практике.
6. Для TFTP подготовлены ПК, адрес `169.254.241.5`, службы и отключённые блокировки.
7. Для консоли зафиксированы 38400/8N1/VT100+/KOI8-R.
8. Определён режим NAT: static или dynamic, и UDP-порт.
9. Виртуальный диапазон не пересекается с реальной адресацией.
10. Проверка связи выполнена и завершилась успешно.
11. После инициализации выполнен первый контакт с Prime.
12. Проверены `version`, `key-info`, `iplir info`, `iplir ping`.
13. Настроено резервное копирование и проверено `machine show backup`.
14. Решение по DPI зафиксировано.
15. Понятно, что использованный `ds5` больше недействителен, а для восстановления нужен `.ecf` + валидный `ds5`.
