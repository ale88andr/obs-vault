**Цель темы:** перестать воспринимать CLI как список команд из методички. Понять его грамматику, карту групп, правила сокращений и безопасный цикл изменения конфигурации.

## 1. Где живёт CLI и как в него попадают

```
┌─────────────────────────────────────────────────────────────┐
│ Варианты подключения                                        │
│  • монитор + клавиатура (VGA / PS/2)                        │
│  • COM-порт (DB9 / RJ45): 38400 8N1, VT100+, KOI8-R         │
│  • SSH с защищённого узла: порт 22, KOI8-R                  │
└───────────────────────────┬─────────────────────────────────┘
                            │
                   аутентификация
             локальная учётка | prime/<имя>
                            │
                            ▼
                 ┌──────────────────────┐
                 │  режим просмотра     │  hostname>
                 └──────────┬───────────┘
                     enable │ exit
                            ▼
                 ┌──────────────────────┐
                 │  режим настройки     │  hostname#
                 └──────────┬───────────┘
                            │
        группы команд: inet, iplir, firewall, machine, ...
                            │
                 службы и файлы: iplircfg, failoverd,
                 mftpd, iplir.conf, failover.ini, mftp.conf
```

Важные факты:

- Интерпретатор запускается **автоматически** после аутентификации.
- По SSH по умолчанию подключение **запрещено**; его разрешают при инициализации или после неё.
- Одновременно может быть открыто несколько сессий; CLI — не более **32**, веб-интерфейс — без ограничения количества подключений.
- Локально можно подключить две консоли; при загрузке выбирается та, на которой нажата клавиша. Если не нажали за 10 секунд — выбирается монитор с клавиатурой.

## 2. Грамматика команд

Команда — это слова, разделённые пробелами. Никаких флагов `-v`, никаких `--help`.

|Обозначение в документации|Что значит|Как вводится|
|---|---|---|
|`<параметр>`|Обязательный параметр|Без угловых скобок|
|`[параметр]`|Необязательный|Без квадратных скобок|
|`{on \| off}`|Выбор из вариантов|Одно значение, без фигурных скобок|
|`0x...`|ViPNet ID в hex|Обязательно с префиксом `0x`|

Пример разбора:

```
firewall ip-object add name @IP_group_1 110.35.14.0/24 exclude 110.35.14.3,110.35.14.13
│        │         │    │             │                │       │
│        │         │    │             │                │       └ исключения
│        │         │    │             │                └ разделитель
│        │         │    │             └ состав объекта
│        │         │    └ имя объекта с @
│        │         └ действие
│        └ подобъект
└ группа
```

### ViPNet ID, а не IP

Там, где команда ждёт узел, указывается **идентификатор**, а не адрес:

```
hostname> iplir ping 0x270e000a
```

Если ввести IP — команда не поймёт. Автодополнение ID берёт из списка связей, но полагаться на него в документации нельзя.

## 3. Сокращения: удобно, но опасно

Лексема распознаётся по **минимальному числу символов**, отличающих её от других. В текущем наборе только две команды начинаются с `i` — `inet` и `iplir`:

|Полная команда|Сокращение|
|---|---|
|`inet`|`in`|
|`iplir`|`ip`|
|`iplir option mode`|`ip o mo`|
|`enable`|`en`|

Две ловушки:

1. **Одна буква меняет подсистему.** `in` — это сеть, `ip` — это VPN. Опечатка в первом слове отправляет команду не туда.
2. **Ошибка в любом символе делает команду недействительной**, даже если правильный префикс уже однозначен. `iplor o mo` — ошибка, а не «почти iplir».

> Инженерная рекомендация: в интерактивной работе сокращайте, в регламентах и скриптах пишите полные команды. Минимальный префикс зависит от текущего набора команд и не является стабильным API.

## 4. Tab, `?` и редактирование строки

### Автодополнение

Tab дополняет **текущее слово**, если введённых символов достаточно для однозначности:

```
hostname> en<Tab>
hostname> enable _
```

Tab **не работает для значений**, которые вы задаёте: имена объектов, пароли, произвольные строки. Их придётся вводить руками.

### Контекстная справка

`?` в пустом приглашении показывает все группы команд с описаниями:

```
hostname# ?
license   shows information about license status and expiration date
inet      a group of commands intended for working with routing, interfaces and network tools
iplir     ...
machine   a group of system commands
...
```

`?` внутри набора — варианты продолжения:

```
hostname> servi?
service   manage additional services

hostname> service ?
http-proxy   manage HTTP proxy
cert         manage certificates
ips          manage IPS services
vpn          manage VPN services
dpi          manage DPI services
user-control setup commands of user-control service
```

Это быстрее, чем искать команду в 620-страничном справочнике. Привычка «сначала `?`, потом ввод» экономит часы.

### Сочетания клавиш

|Клавиши|Действие|
|---|---|
|`Ctrl+U`|Стереть всю команду|
|`Ctrl+K`|Стереть от курсора до конца строки|
|`Ctrl+A`|В начало строки|
|`Ctrl+E`|В конец строки|
|`Ctrl+B` / `Ctrl+F`|На символ назад / вперёд|
|`Ctrl+H`|Стереть символ перед курсором|
|`Ctrl+W`|Стереть слово перед курсором|

История команд в документации не описана. Не стройте на ней процедуры и не обещайте коллегам «нажми стрелку вверх».

## 5. Карта групп: что где искать

|Группа|Зона ответственности|Типичные команды|
|---|---|---|
|`admin`|Обновление ПО, пароли, ключи, отладка|`admin upgrade software`, `admin passwd`, `admin remove keys`|
|`alg`|Прикладной шлюз (ALG)|Настройка обработки прикладных протоколов|
|`failover`|Кластер и защита от сбоев|`failover config edit`, `failover show config`|
|`firewall`|Фильтры, объекты, NAT|`firewall local show`, `firewall ip-object add`|
|`healthmond`|Демон контроля состояния|`healthmond`|
|`inet`|Интерфейсы, маршруты, DNS, NTP, DHCP, VLAN, bonding|`inet show interface`, `inet ping`, `inet ntp mode`|
|`iplir`|VPN-драйвер, ключи, узлы, конфигурация|`iplir info`, `iplir ping`, `iplir config`, `iplir show config`|
|`machine`|Система: время, имя, журналы, backup, обновления|`machine show backup`, `machine reboot`|
|`mftp`|Транспортный сервер MFTP|`mftp config`, `mftp show`|
|`service`|VPN, DPI, IPS, сертификаты, user-control|`service vpn show status`, `service dpi mode off`|
|`ups`|ИБП|`ups show status`|
|`users`|Учётные записи|`users show`, `users add`|
|`vpn`|Копии конфигурации VPN|`vpn config save`, `vpn config load`|
|`webui`|HTTPS-сертификат веб-интерфейса|`webui https-cert`|
|Прочие|Режимы, версия, сессии, отладка|`enable`, `exit`, `version`, `license`, `who`, `debug`|

Мнемоника: **`inet` — сеть, `iplir` — VPN, `firewall` — политика, `machine` — железо и система, `service` — службы.**

## 6. Режимы и выходы: три разных `exit`

|Действие|Команда|Результат|
|---|---|---|
|Перейти в настройку|`enable`|`hostname>` → `hostname#`|
|Вернуться в просмотр|`exit` в режиме `#`|`hostname#` → `hostname>`|
|Выйти из CLI|`exit` в режиме `>`|Приглашение аутентификации|
|Выйти из CLI из любого режима|`Ctrl+D`|Приглашение аутентификации|
|Посмотреть сессии|`who`|Список запущенных сессий|

Классическая ошибка: набрать `exit` в режиме настройки и удивиться, что сессия не закрылась. Это штатное поведение: сначала выход из режима, потом из интерпретатора.

## 7. Просмотр конфигурации vs редактирование

Две команды отличаются одной буквой и ведут себя принципиально по-разному.

| |`iplir show config`|`iplir config`|
|---|---|---|
|Что делает|Показывает файл в постраничном просмотрщике|Открывает файл в редакторе|
|Режим|Просмотр и настройка|Только настройка|
|Требует остановки службы|Нет|Да|
|Выход|`Q`|`Ctrl+X`|
|Что редактирует|—|`iplir.conf` или `iplir.conf-<интерфейс>`|

### Что именно редактируется

|Команда|Файл|Содержимое|
|---|---|---|
|`iplir config`|`iplir.conf`|Параметры защищённой сети: `[id]`, `[misc]`, `[adapter]`, `[visibility]` и т.д.|
|`iplir config eth0`|`iplir.conf-eth0`|Параметры **журнала трафика** интерфейса, а не его IP-адрес|
|`failover config edit`|`failover.ini`|Кластер и защита от сбоев|
|`mftp config`|`mftp.conf`|Транспортный сервер MFTP|

> **Ловушка №1 темы.** `iplir config eth0` не настраивает адрес интерфейса. Адрес задаётся командами группы `inet`. `iplir.conf-eth0` — это параметры журналирования трафика на интерфейсе.

### Рабочий цикл редактирования

```
hostname# iplir stop
        │
        ▼
hostname# iplir config [ethX]
        │  GNU nano
        │  правка
        │  Ctrl+O — сохранить
        │  Ctrl+X — выйти
        ▼
hostname# iplir start
        │
        ▼
hostname> iplir show config     (проверка файла, Q — выход)
hostname> iplir info eth0       (проверка работы)
```

Если попытаться открыть конфигурацию при работающей службе, будет отказ:

```
error: Changing the settings is invalid when the process iplir is running.
Please stop the process (iplir stop)
```

Это не баг, а защита от правки файла, который служба держит в работе.

### Про остановку службы и собственную сессию

Если вы подключены по SSH **через защищённый канал, который обслуживает этот же `iplir`**, команда `iplir stop` оборвёт ваш канал. Дальше — либо локальная консоль, либо резервный путь управления. Это надо проверять до изменения, а не после.

## 8. Копии конфигурации: сохранить до, откатить после

Перед рискованным изменением сохраните копию:

```
hostname# vpn config save before_change
```

Список:

```
hostname# vpn config list
"before_change", version 5.4.2, full, saved on 24.11.2026 at 10:12, never loaded
```

Формат: имя, версия ПО, тип (`full` / `part`), дата и время сохранения, дата и время последней загрузки.

Что входит в копию:

- настройки VPN;
- сетевые интерфейсы;
- система защиты от сбоев;
- транспортный сервер MFTP;
- сетевые фильтры.

Откат:

```
hostname# iplir stop
hostname# failover stop
hostname# mftp stop
hostname# vpn config load before_change
hostname# iplir start
hostname# failover start
hostname# mftp start
```

`vpn config load` сам предложит сохранить текущую конфигурацию перед загрузкой — не отказывайтесь, это ваша страховка.

> Не путайте `vpn config save` с индивидуальной конфигурацией `.ecf` из темы 5. Копия VPN — локальный откат настроек. `.ecf` — средство восстановления/замены устройства, зашифрованное ключом обмена с Prime.

## 9. CLI и веб-интерфейс: что где делать

|Задача|CLI|Веб-интерфейс|
|---|---|---|
|Интерфейсы, маршруты|Да|Да|
|Фильтры, NAT, объекты|Да|Да, нагляднее|
|VPN-режимы, ключи, узлы|Да|Ограниченно|
|Кластер|Да|Ограниченно|
|MFTP-транзит|Да|Нет|
|Обновление ПО и DPI|Да|Нет|
|Редактирование конфигурационных файлов|Да|Нет|
|Копии конфигурации VPN|Да|Нет|
|Журналы и мониторинг|Да|Да, удобнее|
|Учётные записи|Да|Да|
|Отладка (`debug`, `admin escape`)|Да|Нет|

Веб-интерфейс — это «частичная настройка» по документации. CLI — более полный инструмент, но менее наглядный. Нормальная практика: проектировать и разбирать инциденты в CLI, повседневные фильтры и журналы смотреть в вебе.

## 10. Десять команд, которые надо уметь читать

|Команда|Что показывает|На что смотреть|
|---|---|---|
|`?`|Группы команд|Что вообще доступно вашей роли|
|`version`|Продукт, платформа, лицензия, версия ПО|Совпадение с проектом|
|`license`|Статус и сроки лицензий|Что истекает|
|`who`|Активные сессии|Кто ещё работает и не мешает ли вам|
|`iplir show config`|`iplir.conf`|`[id]`, `[misc]`, `[adapter]`|
|`iplir info eth0`|Статистика интерфейса и туннелей|`License` / `Current` / `Peak`|
|`iplir node list`|Список связанных узлов|Все ли ожидаемые узлы на месте|
|`iplir show exchange-keys warning`|Ключи обмена с истекающим сроком|Что обновлять в первую очередь|
|`vpn config list`|Копии конфигурации|Есть ли точка отката|
|`machine show backup`|Резервное копирование|Расписание и последняя копия|

### Отладочный вывод в консоль

```
hostname# debug on daemon err
```

Включает поток сообщений служб на текущую консоль. Полезно на 2–3 минуты, чтобы увидеть, почему не поднимается туннель. Выключить:

```
hostname# debug off
```

Без параметров `debug off` выключает всё. Оставлять `debug on` на боевом устройстве — значит засорять сессию и журналы.

## 11. Типичные ошибки

|Симптом|Причина|Лечение|
|---|---|---|
|`iplir config` выдаёт ошибку про запущенный процесс|Служба `iplircfg` работает|`iplir stop`, правка, `iplir start`|
|Файл изменён, поведение прежнее|Служба не перезапущена|`iplir start`; проверять `iplir info`, а не только файл|
|`iplir config eth0` «не меняет IP»|Это файл журналирования, а не адресация|Адрес — командами `inet`|
|`exit` не закрывает сессию|Вы в режиме `#`|Ещё раз `exit` или `Ctrl+D`|
|`Ctrl+D` в редакторе удаляет символ|В nano `Ctrl+D` — не выход|Выход — `Ctrl+X`, сохранение — `Ctrl+O`|
|`ip ...` ушло не туда|`ip` — это `iplir`, `in` — это `inet`|Писать полные имена в регламентах|
|Tab не дополняет имя объекта|Автодополнение работает только для команд и параметров|Вводить значение вручную|
|Команда с IP вместо ID не работает|Ожидается `0x...`|Использовать ViPNet ID|
|Скопировали строку вместе с `hostname#`|Приглашение — не часть команды|Копировать только команду|
|Изменения «исчезли» после обновления из Prime|Часть параметров управляется централизованно|См. тему 10; не править то, что перезаписывается|
|Откат `vpn config load` не применился|Не остановлены `iplir`, `failoverd`, `mftpd`|Остановить все три, загрузить, запустить|
|Сессия оборвалась при `iplir stop`|SSH шёл через защищённый канал этого же узла|Работать через локальную консоль или резервный путь|

## 12. Чек-лист темы

1. Понимаете разницу между `>` и `#` и умеете переключаться.
2. Знаете три способа выхода и чем они отличаются.
3. Читаете синтаксис `< >`, `[ ]`, `{ | }` без подсказки.
4. Понимаете правило минимального уникального префикса и его риски.
5. Умеете пользоваться `?` на уровне групп и подкоманд.
6. Знаете, что Tab не дополняет значения.
7. Ориентируетесь в карте групп: `inet`, `iplir`, `firewall`, `machine`, `service`, `vpn`.
8. Различаете `iplir show config` и `iplir config`.
9. Помните, что `iplir config eth0` — это журнал интерфейса, а не IP.
10. Выполняете цикл `stop → config → nano → start` без ошибок.
11. Умеете сохранить и загрузить копию через `vpn config`.
12. Понимаете, какие задачи решаются только в CLI.
13. Проверяете результат по `iplir info` и журналам, а не по факту правки файла.
