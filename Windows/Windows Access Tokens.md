## 1. Что такое Access Token?

**Access Token (маркер доступа)** — объект безопасности, описывающий контекст безопасности процесса или потока. Его можно представить как «паспорт» пользователя в операционной системе, содержащий всю необходимую информацию для проверки прав доступа.

## 2. Жизненный цикл токена (от входа в систему до Explorer)

Процесс создания и распространения токена при входе пользователя выглядит следующим образом:

|Этап|Компонент|Описание|
|---|---|---|
|**1. Ввод учётных данных**|`LogonUI.exe`|Пользователь вводит логин и пароль.|
|**2. Передача данных**|`winlogon.exe`|Получает учётные данные и передаёт их в подсистему безопасности.|
|**3. Аутентификация и создание токена**|`lsass.exe` (Local Security Authority Subsystem Service)|Выполняет проверку учётных данных. При успешной аутентификации создаёт маркер доступа (Access Token) для данной сессии входа.|
|**4. Запуск пользовательской оболочки**|`winlogon.exe` → `userinit.exe` → `explorer.exe`|Winlogon запускает начальные процессы пользовательской сессии.|
|**5. Распространение токена**|Родительский процесс|Любой новый процесс, запущенный в рамках этой сессии, получает **копию первичного токена (Primary Token)** родительского процесса.|

## 3. Анатомия Access Token

Маркер доступа содержит следующую ключевую информацию о субъекте:

|Элемент|Описание|
|---|---|
|**SID пользователя**|Уникальный идентификатор учётной записи пользователя (Security Identifier).|
|**SID групп**|Список групп, членом которых является пользователь.|
|**Privileges (привилегии)**|Перечень прав, предоставленных пользователю (например, `SeDebugPrivilege`, `SeBackupPrivilege`). Могут быть включены или отключены.|
|**Logon ID (LUID)**|Уникальный идентификатор сессии входа (Locally Unique Identifier). Позволяет отличить разные сеансы одного и того же пользователя.|
|**Default DACL**|Список управления доступом по умолчанию. Применяется ко всем новым объектам (файлам, папкам), создаваемым процессом с этим токеном.|

## 4. Проверка прав доступа (Субъект → Объект)

Механизм разграничения доступа в Windows основан на сравнении токена субъекта с дескриптором безопасности объекта.

|Этап|Описание|
|---|---|
|**1. Запрос доступа**|Процесс пытается выполнить операцию над объектом (например, открыть файл).|
|**2. Получение токена**|Система берёт маркер доступа процесса (или потока при импперсонации).|
|**3. Анализ дескриптора безопасности**|Изучается дескриптор безопасности объекта (Security Descriptor), содержащий DACL.|
|**4. Сопоставление**|SID'ы из токена сравниваются с записями ACE (Access Control Entries) в DACL.|
|**5. Принятие решения**|Если находится совпадающее разрешающее правило — доступ предоставляется. В противном случае доступ блокируется.|

## 5. Имперсонация (Impersonation)

Имперсонация позволяет потоку временно действовать от имени другого субъекта с его правами доступа.

|Понятие|Описание|
|---|---|
|**Primary Token (первичный маркер)**|Основной маркер процесса. Определяет права всего процесса по умолчанию. У каждого процесса есть ровно один первичный токен.|
|**Impersonation Token (маркер имперсонации)**|Временный маркер, используемый отдельным потоком внутри процесса. Позволяет потоку действовать от имени другого пользователя/клиента.|
|**Назначение**|Широко применяется в службах Windows. Вместо выполнения всех действий от имени учётной записи службы (например, `SYSTEM` или `Network Service`), служба может временно использовать права клиента, который к ней обратился.|
|**Принцип работы**|Поток проверяет доступ не по правам всего процесса, а по маркеру имперсонации, что ограничивает привилегии и повышает безопасность.|

## Ключевой принцип

**«Субъект запрашивает доступ к объекту — система сравнивает маркер доступа субъекта с DACL объекта»**. Именно на этом основан весь механизм дискреционного управления доступом в Windows.
