# 01. Архитектура Windows

## Цель изучения
Понять, как устроена Windows: какие режимы работы, основные компоненты, как взаимодействуют пользовательский и ядреный режимы.

## Ключевые понятия

### Режимы работы
- **User Mode** (пользовательский режим) — изолированная среда. Приложения не имеют прямого доступа к аппаратуре. К сожалению нарушить работу всей системы напрямую нельзя.
- **Kernel Mode** (режим ядра) — привилегированный режим. Имеет полный доступ ко всем ресурсам системы: память, устройства, CPU.

### Основные компоненты

| Компонент | Описание |
| --- | --- |
| **NTOSKRNL.EXE** | Ядро Windows NT. Содержит Executive, ядро, менеджеры памяти, планировщик и др. |
| **HAL (Hardware Abstraction Layer)** | Абстрагирует железо. Позволяет Windows работать на разных архитектурах/платформах. |
| **Executive** | Набор служб ядра: Object Manager, Security Reference Monitor, I/O Manager, Memory Manager, Process Manager и др. |
| **Win32k.sys** | Ядреный драйвер, отвечающий за графику, пользовательский интерфейс и ввод-вывод в рамках Win32 подсистемы. |
| **Подсистемы** | Win32, WoW64, POSIX (исторически) — обеспечивают совместимость с разными API. |

### Сессии
- **Session 0** — служебная сессия. С сервисами Windows. Изолирована от интерактивных пользователей с Vista+ (Session 0 Isolation).
- **Interactive Sessions** (Session 1, 2...) — сессии для входящих пользователей с графическим интерфейсом.

## Практика
- Посмотри в Process Explorer: у каких процессов базовый модуль `ntoskrnl.exe`? У каких системных процессов нет родителя в привычном понимании?
- В `msinfo32` посмотри информацию о системе и попробуй сопоставить с компонентами выше.
