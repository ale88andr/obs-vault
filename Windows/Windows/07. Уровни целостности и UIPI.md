# 07. Уровни целостности и UIPI

## Цель изучения
Понять Mandatory Integrity Control (MIC), уровни целостности, UIPI и как они дополняют ACL/UAC.

## Ключевые понятия

### Mandatory Integrity Control (MIC)
**Mandatory Integrity Control** — обязательный контроль целостности. В отличие от DACL (дискреционный, разрешается/запрещается владельцем), MIC является **обязательным**. Правила применяются системой вне зависимости от желаний владельца объекта.

Главный принцип: **низкоцелостный процесс не может модифицировать объект с более высоким уровнем целостности**.

### Уровни целостности (Integrity Levels)
Назначаются токену процесса и дескриптору объекта.

| Уровень | Значение | Применение |
| ---
| --- |
| **Untrusted** (0) | Минимальный | Редко используется |
| **Low** (0x1000) | Низкий | IE Protected Mode (исторически), некоторые изолированные процессы, sandbox'ы |
| **Medium** (0x2000) | Средний | Обычные процессы пользователя. Стандартный уровень для большинства приложу | 
| **High** (0x3000) | Высокий | Процессы с повышенными правами (elevated). Administrators при elevation |
| **System** (0x4000) | Системный | Системные процессы, services.exe, lsass.exe, smss.exe |
| **Protected Process** | Специальный | Защищённые процессы (например, некоторые DRM, LSASS в некоторых конфигурациях) |

### Как работает MIC
При обращении к объект:
1. Сравниваются уровни целостности субъекта (токен) и объекта (Security Descriptor, SACL/часть SD)
2. Если субъект **ниже** по уровню целостности — система может запретить запись/modification
3. Чтение может быть разрешено в некоторых случаях (No-Write-Up принцип)

**No-Write-Up** — процесс с меньшим уровнем целостности **не** может писать/изменить ресурс более высокого уровня целостности.

### UIPI (User Interface Privilege Isolation)
**UIPI** — механизм, ограничивающий межпроцессное взаимодействие на уровне пользовательского интерфей Integrity Level). Он предотвращет отправку сообщений (SendMessage/PostMessage), хоткеев, симуляции ввода из более низкоцелостного процесса в более высокоцелостный.

Например: низкоцелостный процесс не может посылить нажатие клавиш в elevated cmd.exe или установить хук в высокий процесс.

### Важные нюансы
- MIC не отменяет DACL. Оба механизма работают одновременно: сначала может быть проверка DACL, затем MIC/UIPI.
- Стандартный пользователь работает Medium. Elevated администратор — High.
- Session 0 Isolation связан, но не идентичен Integrity Level.
- UIPI ограничивает именно UI-взаимодействие, не все типы межпроцессного взаимодействия

## Практика
- В Process Explorer посмотри колонку Integrity у: explorer.exe, блокнота, cmd, cmd Run as administrator, svchost.exe, lsass.exe
- Открой `whoami /all` и найди `Mandatory Label`
- Попробуй перетаскивать/взаимодействовать между Low и High процессами (наблюдение)
- Посмотри в `icacls` или Security Descriptor объекта — есть ли упоминание Mandatory Label? (не всегда явно видно)
