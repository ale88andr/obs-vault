# 05. Привилегии Windows

## Цель изучения
Разобраться, что такое привилегии, как они отличаются от прав доступа (ACL), и почему они мощные.

## Ключевые понятия

### Привилегия vs Права доступа
- **Права доступа (ACL-based)** — проверяются по DACL объекта. Дают возможность работать *с конкретным объектом* (прочесть файл, записать в ключ реестра).
- **Привилегии (Privileges)** — системные привилегии, выданные токену. Дают возможность выполнять *определённые системные операции*, которые обычно недоступны обычному пользователю. Проверяются отдельно от DACL.

Коротко: ACL — "что можно сделать с этим объектом", Privilege — "что можно сделать в системе".

### Состояние привилегий
У привилегии в токене есть состояние:
- **Enabled (включена)** — активна, используется при выполнении операции
- **Disabled (отключена)** — присутствует в токене, но не активна. Процесс может временно её включить (если это разрешено политикой)
- **Removed** — отсутствует

### Важные привилегии для понимания

| Привилегия | Назначение | Опасность |
| --- | --- | --- |
| **SeDebugPrivilege** | Отладка процессов, чтение/запись памяти чужих процессов | Очень высокая. Позволяет инспектировать/манипулировать почти любым процессом |
| **SeImpersonatePrivilege** | Имперсонация клиента. Используется многими системными службами | Высокая. Часто эксплуатируется в атакующих техниках (Potato-атаки) |
| **SeAssignPrimaryTokenPrivilege** | Замена primary token у процесса | Высокая |
| **SeTakeOwnershipPrivilege** | Захват владения объектом без явных прав | Высокая. Позволяет стать владельцем файла/объекта и затем поменять DACL |
| **SeBackupPrivilege** | Резервное копирование, обход ACL при чтении | Высокая. Позволяет читать файлы вне собственных прав |
| **SeRestorePrivilege** | Восстановление, запись вне ACL | Высокая. Позволяет перезаписывать защищённые файлы/ключи |
| **SeShutdownPrivilege** | Выключение/перезагрузка системы | Средне-высокая |
| **SeLoadDriverPrivilege** | Загрузка драйверов | Крайне высокая |

### Учет привилегий
Привилегии назначаются через **User Rights Assignment** (локальная политика безопасности) или доменную политику. Наличие группы "Администраторы" не означает, что *все* привилегии всегда включены — особенно в контексте UAC (будет рассмотрено далее).

## Практика
- `whoami /all` — найти секцию Privileges. Посмотри какие включены/отключены
- В Process Explorer свойства процесса -> Security/Privileges — сопоставь с whoami
- Подумай: почему системные службы типа `services.exe` имеют много привилегий
