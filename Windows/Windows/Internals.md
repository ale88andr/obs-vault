**Программа** — статическая последовательность команд

### Процессы

**Процесс** — контейнер для набора ресурсов, используемых для выполнения программы.

процесс Windows включает следующие компоненты:

- **закрытое виртуальное адресное пространство** — множество адресов виртуальной памяти, которая может использоваться процессом;
- **исполняемая программа**, которая определяет первоначальный код и данные и отображается в виртуальное адресное пространство процесса; 
- **список открытых дескрипторов** для различных системных ресурсов (семафоров, объектов синхронизации портов, файлов и т. д.), доступных для всех программных потоков в процессе; 
- **контекст безопасности** — маркер доступа (access token), который идентифицирует пользователя, группы безопасности, привилегии, состояние виртуализации UAC (User Account Control), сеанс и ограниченное состояние учетной записи пользователя, связанное с процессом, а также идентификатор контейнера приложения и связанная с ним информация изоляции;
- **по меньшей мере один программный поток (thread)**. Пустые процессы теоретически могут существовать, но особой пользы не принесут.

Каждый процесс также содержит идентификатор своего родительского процесса или процесса-создателя (они могут совпадать, но это не обязательно)

### Потоки

Программный **поток** (или просто поток) — последовательность команд внутри процесса, планируемая Windows для исполнения. Без потоков программа процесса не сможет выполняться. Поток содержит следующие важнейшие компоненты:
- Содержимое набора регистров CPU, представляющих состояние процессора.
- Два стека: один для программного потока, который должен использоваться при выполнении в режиме ядра, другой — для выполнения в пользовательском режиме.
- Закрытая область памяти, называемая локальной памятью потока команд (TLS, Thread-Local Storage); используется подсистемами, библиотеками времени вы полнения и динамическими библиотеками DLL.
- Уникальный идентификатор, называемый идентификатором потока (TID, Thread ID); является частью внутренней структуры идентификатора клиента (client ID). Идентификаторы процесса и потока генерируются из одного пространства имен, поэтому они никогда не перекрываются.

Регистры, стеки и закрытая область памяти называются **контекстом потока**.

Так как переключение выполнения между потоками требует участия планировщика ядра, эта операция может быть довольно затратной, особенно если два потока часто передают управление между собой. В Windows реализованы два механизма для сокращения этих затрат: волокна (fibers) и планирование пользовательского режима (UMS, User Mode Scheduling).

Помимо закрытого адресного пространства и одного или нескольких потоков, у каждого процесса имеется **контекст безопасности** и список **открытых дескрипторов** объектов ядра: файлов, разделов общей памяти, объектов синхронизации (мьютексы, события или семафоры)

Контент безопасности каждого процесса хранится в объекте, называемом маркером доступа (access token). Маркер доступа процесса содержит идентификационные данные безопасности и учетные данные процесса. По умолчанию потоки не имеют собственного маркера доступа, но могут получить его

Дескрипторы виртуальных адресов (VAD, Virtual Address Descriptors) — структуры данных, используемые диспетчером памяти для отслеживания виртуальных адресов, используемых процессом.

### Виртуальная память 

В Windows реализована система виртуальной памяти, основанная на модели плоского (линейного) адресного пространства, которая создает для каждого процесса иллюзию огромного закрытого адресного пространства. Виртуальная память формирует логическое представление памяти, которое может не соответствовать физической структуре. Во время выполнения диспетчер памяти — при поддержке оборудования — транслирует (отображает) виртуальные адреса в физические, где фактически хранятся данные. Управляя защитой и отображением адресов, ОС может предотвращать столкновения отдельных процессов или перезапись данных ОС

Так как в большинстве систем объем физической памяти гораздо меньше суммарно го объема виртуальной памяти, используемой работающими процессами, диспетчер памяти переносит (выгружает) часть содержимого памяти на диск. Выгрузка дан ных на диск освобождает физическую память, чтобы она могла использоваться для других процессов или самой ОС. Когда поток обращается по виртуальному адресу, выгруженному на диск, диспетчер виртуальной памяти подгружает информацию обратно в память с диска.

На рис. продемонстрировано использование виртуальной памяти двумя процессами; части памяти отображаются в физическую память (ОЗУ), а другие части выгружаются на диск. Обратите внимание на то, что непрерывные блоки виртуальной памяти могут отображаться в несмежные блоки физической памяти. Эти блоки называются страницами, а их размер по умолчанию составляет 4 Кбайт.

## Режим ядра и пользовательский режим

#### Основные понятия

|Понятие|Описание|
|---|---|
|**Пользовательский режим (User Mode)**|Режим работы процессора, в котором выполняется код пользовательских приложений. Имеет ограниченные привилегии.|
|**Режим ядра (Kernel Mode)**|Режим работы процессора, в котором выполняется код ОС, системные службы и драйверы устройств. Доступен весь набор команд процессора и вся системная память.|

#### Ключевые отличия

###### Привилегии и безопасность

- **Разделение привилегий** — код ОС имеет более высокий уровень привилегий, чем пользовательские процессы, что предотвращает сбой приложения от нарушения стабильности всей системы.
- **Защита адресного пространства** — у каждого процесса Windows есть собственное закрытое виртуальное адресное пространство.
- **Общее пространство ядра** — код ОС режима ядра и драйверы устройств совместно используют единое виртуальное адресное пространство.

###### Организация памяти

- **Метки страниц** — каждая страница виртуальной памяти помечается, указывая, из какого режима можно осуществлять чтение/запись.
- **Системное пространство** — страницы доступны только из режима ядра.
- **Пользовательское пространство** — страницы доступны как из пользовательского, так и из режима ядра.
- **Защита от записи** — страницы только для чтения (например, со статическими данными) недоступны для записи ни из какого режима.
- **Защита от исполнения (DEP)** — на поддерживающих её процессорах страницы с данными помечаются как неисполняемые, предотвращая выполнение кода в областях данных.

###### Отсутствие защиты в режиме ядра

- **Полный доступ** — компоненты режима ядра (ядро, драйверы) имеют полный доступ к памяти системного пространства и могут обойти механизмы безопасности Windows.
- **Критичность качества кода** — из-за работы основной части Windows в режиме ядра, код ядра и драйверов должен быть максимально тщательно спроектирован и протестирован.
- **Опасность сторонних драйверов** — неподписанные драйверы особенно опасны, т.к. в режиме ядра они получают полный доступ ко всем данным ОС.

#### Переключение между режимами

Процесс переключения пользовательский режим ↔ режим ядра происходит при вызове системных функций:

1. **Вызов из пользовательского режима** — приложение вызывает системную функцию (например, `ReadFile`).
2. **Инициализация перехода** — специальная команда процессора переключает процессор из пользовательского режима в режим ядра и передаёт управление диспетчеру системных вызовов ядра.
3. **Выполнение в режиме ядра** — диспетчер вызывает соответствующую внутреннюю функцию (`Ntoskrnl.exe` или `Win32k.sys`), которая работает с внутренними системными структурами.
4. **Возврат** — после завершения процессор переключается обратно в пользовательский режим и управление возвращается пользовательскому потоку.

## Безопасность

В состав базовых средств безопасности Windows входят:
- защита на уровне пользователей (дискреционная, т. е. предоставляемая на усмотрение) и обязательная защита для всех совместно используемых системных объектов: файлов, каталогов, процессов, потоков и т. д.;
- система аудита безопасности для учета субъектов (пользователей) и выполня емых ими действий;
- проверка пользователя при входе;
- предотвращение доступа со стороны пользователя к неинициализированным ресурсам (например, свободной памяти или дисковому пространству), освобожденным другим пользователем
