# 1. Концепции

**Программа** — статическая последовательность команд

### Процессы

**Процесс** — контейнер для набора ресурсов, используемых для выполнения программы.

процесс Windows включает следующие компоненты:

- **закрытое виртуальное адресное пространство** — множество адресов виртуальной памяти, которая может использоваться процессом;
- **исполняемая программа**, которая определяет первоначальный код и данные и отображается в виртуальное адресное пространство процесса; 
- **список открытых дескрипторов** для различных системных ресурсов (семафоров, объектов синхронизации портов, файлов и т. д.), доступных для всех программных потоков в процессе; 
- **контекст безопасности** — маркер доступа (access token), который идентифицирует пользователя, группы безопасности, привилегии, состояние виртуализации UAC (User Account Control), сеанс и ограниченное состояние учетной записи пользователя, связанное с процессом, а также идентификатор контейнера приложения и связанная с ним информация изоляции;
- **по меньшей мере один программный поток (thread)**. Пустые процессы теоретически могут существовать, но особой пользы не принесут.

Каждый процесс также содержит идентификатор своего родительского процесса или процесса-создателя (они могут совпадать, но это не обязательно)

---
### Потоки

Программный **поток** (или просто поток) — последовательность команд внутри процесса, планируемая Windows для исполнения. Без потоков программа процесса не сможет выполняться. Поток содержит следующие важнейшие компоненты:
- Содержимое набора регистров CPU, представляющих состояние процессора.
- Два стека: один для программного потока, который должен использоваться при выполнении в режиме ядра, другой — для выполнения в пользовательском режиме.
- Закрытая область памяти, называемая локальной памятью потока команд (TLS, Thread-Local Storage); используется подсистемами, библиотеками времени вы полнения и динамическими библиотеками DLL.
- Уникальный идентификатор, называемый идентификатором потока (TID, Thread ID); является частью внутренней структуры идентификатора клиента (client ID). Идентификаторы процесса и потока генерируются из одного пространства имен, поэтому они никогда не перекрываются.

Регистры, стеки и закрытая область памяти называются **контекстом потока**.

Так как переключение выполнения между потоками требует участия планировщика ядра, эта операция может быть довольно затратной, особенно если два потока часто передают управление между собой. В Windows реализованы два механизма для сокращения этих затрат: волокна (fibers) и планирование пользовательского режима (UMS, User Mode Scheduling).

Помимо закрытого адресного пространства и одного или нескольких потоков, у каждого процесса имеется **контекст безопасности** и список **открытых дескрипторов** объектов ядра: файлов, разделов общей памяти, объектов синхронизации (мьютексы, события или семафоры)

Контент безопасности каждого процесса хранится в объекте, называемом маркером доступа (access token). Маркер доступа процесса содержит идентификационные данные безопасности и учетные данные процесса. По умолчанию потоки не имеют собственного маркера доступа, но могут получить его

Дескрипторы виртуальных адресов (VAD, Virtual Address Descriptors) — структуры данных, используемые диспетчером памяти для отслеживания виртуальных адресов, используемых процессом.

### Виртуальная память 

В Windows реализована система виртуальной памяти, основанная на модели плоского (линейного) адресного пространства, которая создает для каждого процесса иллюзию огромного закрытого адресного пространства. Виртуальная память формирует логическое представление памяти, которое может не соответствовать физической структуре. Во время выполнения диспетчер памяти — при поддержке оборудования — транслирует (отображает) виртуальные адреса в физические, где фактически хранятся данные. Управляя защитой и отображением адресов, ОС может предотвращать столкновения отдельных процессов или перезапись данных ОС

Так как в большинстве систем объем физической памяти гораздо меньше суммарно го объема виртуальной памяти, используемой работающими процессами, диспетчер памяти переносит (выгружает) часть содержимого памяти на диск. Выгрузка дан ных на диск освобождает физическую память, чтобы она могла использоваться для других процессов или самой ОС. Когда поток обращается по виртуальному адресу, выгруженному на диск, диспетчер виртуальной памяти подгружает информацию обратно в память с диска.

На рис. продемонстрировано использование виртуальной памяти двумя процессами; части памяти отображаются в физическую память (ОЗУ), а другие части выгружаются на диск. Обратите внимание на то, что непрерывные блоки виртуальной памяти могут отображаться в несмежные блоки физической памяти. Эти блоки называются страницами, а их размер по умолчанию составляет 4 Кбайт.

## Режим ядра и пользовательский режим

#### Основные понятия

|Понятие|Описание|
|---|---|
|**Пользовательский режим (User Mode)**|Режим работы процессора, в котором выполняется код пользовательских приложений. Имеет ограниченные привилегии.|
|**Режим ядра (Kernel Mode)**|Режим работы процессора, в котором выполняется код ОС, системные службы и драйверы устройств. Доступен весь набор команд процессора и вся системная память.|

#### Ключевые отличия

###### Привилегии и безопасность

- **Разделение привилегий** — код ОС имеет более высокий уровень привилегий, чем пользовательские процессы, что предотвращает сбой приложения от нарушения стабильности всей системы.
- **Защита адресного пространства** — у каждого процесса Windows есть собственное закрытое виртуальное адресное пространство.
- **Общее пространство ядра** — код ОС режима ядра и драйверы устройств совместно используют единое виртуальное адресное пространство.

###### Организация памяти

- **Метки страниц** — каждая страница виртуальной памяти помечается, указывая, из какого режима можно осуществлять чтение/запись.
- **Системное пространство** — страницы доступны только из режима ядра.
- **Пользовательское пространство** — страницы доступны как из пользовательского, так и из режима ядра.
- **Защита от записи** — страницы только для чтения (например, со статическими данными) недоступны для записи ни из какого режима.
- **Защита от исполнения (DEP)** — на поддерживающих её процессорах страницы с данными помечаются как неисполняемые, предотвращая выполнение кода в областях данных.

###### Отсутствие защиты в режиме ядра

- **Полный доступ** — компоненты режима ядра (ядро, драйверы) имеют полный доступ к памяти системного пространства и могут обойти механизмы безопасности Windows.
- **Критичность качества кода** — из-за работы основной части Windows в режиме ядра, код ядра и драйверов должен быть максимально тщательно спроектирован и протестирован.
- **Опасность сторонних драйверов** — неподписанные драйверы особенно опасны, т.к. в режиме ядра они получают полный доступ ко всем данным ОС.

#### Переключение между режимами

Процесс переключения пользовательский режим ↔ режим ядра происходит при вызове системных функций:

1. **Вызов из пользовательского режима** — приложение вызывает системную функцию (например, `ReadFile`).
2. **Инициализация перехода** — специальная команда процессора переключает процессор из пользовательского режима в режим ядра и передаёт управление диспетчеру системных вызовов ядра.
3. **Выполнение в режиме ядра** — диспетчер вызывает соответствующую внутреннюю функцию (`Ntoskrnl.exe` или `Win32k.sys`), которая работает с внутренними системными структурами.
4. **Возврат** — после завершения процессор переключается обратно в пользовательский режим и управление возвращается пользовательскому потоку.

## Безопасность

### Базовые средства безопасности

В состав базовых средств безопасности Windows входят:

- **Защита объектов** — дискреционная (предоставляемая на усмотрение владельца) и обязательная защита для всех совместно используемых системных объектов (файлы, каталоги, процессы, потоки и др.).
- **Система аудита безопасности** — учёт субъектов (пользователей) и выполняемых ими действий.
- **Проверка пользователя при входе** — аутентификация пользователя перед доступом к системе.
- **Предотвращение доступа к неинициализированным ресурсам** — защита от чтения освобождённых ресурсов (например, свободной памяти или дискового пространства), ранее использованных другим пользователем.

### Формы управления доступом к объектам

В Windows существует три формы управления доступом к объектам:

#### 1. Дискреционное управление доступом (DAC)

Это основной механизм защиты, наиболее привычный для пользователей.

- **Владение объектом** — владелец объекта (например, файла или принтера) самостоятельно решает, кому предоставлять или запрещать доступ.
- **Контекст безопасности** — при входе в систему пользователю присваивается набор учётных данных безопасности (контекст безопасности).
- **Проверка доступа** — при попытке обращения к объекту контекст безопасности пользователя сравнивается со списком управления доступом (ACL) этого объекта. Результат определяет, разрешена ли запрашиваемая операция.
- **Динамическое управление доступом (Dynamic Access Control, DAC)** — усовершенствование данного механизма, реализованное в Windows Server 2012 и Windows 8.
    - **На основе атрибутов** — в ACL вместо перечисления конкретных пользователей и групп могут указываться атрибуты или _утверждения_ (_claims_).
    - **Примеры утверждений**: «Уровень допуска: Совершенно секретно», «Стаж: 10 лет».
    - **Автоматизация** — такие атрибуты могут автоматически заполняться на основе данных из баз данных и схем SQL через Active Directory.
    - **Гибкость** — позволяет значительно упростить управление правами доступа, избавившись от громоздких групп и иерархий групп.

#### 2. Привилегированное управление доступом

Применяется в случаях, когда дискреционного механизма недостаточно для получения доступа к объекту.

- **Назначение** — гарантирует доступ к защищённому объекту даже в том случае, если его владелец недоступен.
- **Пример** — если сотрудник уволился из компании, администратор может получить доступ к его файлам.
- **Механизм** — администратор может назначить себя владельцем объекта, после чего получить возможность управлять его правами доступа в необходимом объёме.

#### 3. Контроль целостности учётных данных (Mandatory Integrity Control, MIC)

Дополнительный уровень защиты, который используется для контроля доступа **в рамках одной и той же учётной записи пользователя**.

- **Назначение** — ограничивает взаимодействие между объектами и процессами с разным уровнем целостности.
- **Примеры применения**:
    - **Изоляция приложений Windows Apps** — частичная изоляция для повышения безопасности.
    - **Защищённый режим браузеров** — изоляция Защищённого режима Internet Explorer (и других браузеров) от конфигурации и данных пользователя.
    - **Защита объектов с повышенными правами** — предотвращение доступа к объектам, созданным учётной записью администратора с повышенными правами, со стороны той же учётной записи, но без повышенных прав.

|Механизм|Тип управления|Кто определяет доступ|Особенности|
|---|---|---|---|
|**Дискреционный (DAC)**|Дискреционный|Владелец объекта|Основной механизм. Доступ проверяется по контексту безопасности и ACL объекта. Может использовать утверждения (Claims) в рамках Dynamic Access Control.|
|**Привилегированный**|Административный (принудительный)|Администратор|Позволяет стать владельцем объекта и изменить права доступа при недоступности исходного владельца.|
|**Контроль целостности (MIC)**|Обязательный по целостности|Система|Работает внутри одной учётной записи. Разделяет процессы и объекты по уровням целостности для предотвращения нежелательных взаимодействий.|

## Реестр

**Реестр Windows** — централизованная иерархическая системная база данных, содержащая информацию, необходимую для загрузки, настройки и нормальной работы операционной системы.

## Что хранится в реестре

|Вид информации|Описание|
|---|---|
|**Параметры загрузки и конфигурации**|Данные, необходимые для запуска и начальной настройки Windows.|
|**Общесистемные параметры**|Настройки, управляющие работой операционной системы в целом.|
|**База данных безопасности**|Сведения, используемые механизмами защиты и разграничения доступа Windows.|
|**Текущие настройки**|Действующие на данный момент настройки системы и пользователя (например, используемая экранная заставка).|

## Доступ к динамическим данным

Помимо постоянных настроек, реестр также предоставляет доступ к временным данным, хранящимся в оперативной памяти:

|Данные|Описание|
|---|---|
|**Текущее состояние оборудования**|Информация о сконфигурированном и работающем в данный момент аппаратном обеспечении.|
|**Сведения о драйверах устройств**|Данные о том, какие драйверы загружены, а также какие системные ресурсы (прерывания, порты ввода-вывода и др.) они используют.|
|**Счётчики производительности Windows**|Динамические показатели работы системы, используемые для её мониторинга и анализа производительности.|

## Особенности реестра

- **Единое хранилище конфигурации** — объединяет настройки системы, приложений, оборудования и безопасности в одной базе данных.
- **Сочетание постоянных и временных данных** — часть информации сохраняется между перезагрузками системы, а часть формируется динамически и отражает текущее состояние системы.
- **Связь с аппаратной частью** — позволяет отслеживать загруженные драйверы и используемые ими ресурсы в реальном времени.

# 2. Архитектура системы

## Модель операционной системы

### Разделение режимов работы процессора

Windows использует модель с двумя режимами работы процессора:

|Режим|Назначение|Права доступа|
|---|---|---|
|**Пользовательский режим (User Mode)**|Выполнение кода пользовательских приложений|Ограниченный набор интерфейсов и системных данных. Прямой доступ к оборудованию запрещён.|
|**Режим ядра (Kernel Mode)**|Выполнение кода ядра ОС, системных служб и драйверов устройств|Привилегированный доступ ко всем системным данным и оборудованию.|
### Механизм переключения между режимами

1. **Вызов** — приложение пользовательского режима вызывает системную функцию.
2. **Переход** — процессор выполняет специальную команду и переключает вызывающий поток в режим ядра.
3. **Выполнение** — ОС выполняет запрошенную операцию, используя привилегированный доступ.
4. **Возврат** — по завершении системной функции контекст потока переключается обратно в пользовательский режим и приложение продолжает работу.

### Монолитная архитектура Windows

- **Единое адресное пространство** — как и многие UNIX-системы, Windows является монолитной ОС. Большая часть кода ядра и драйверов устройств использует одно защищённое пространство памяти защищённого режима.
- **Потенциальный риск** — любой компонент ядра или драйвер устройства теоретически может повредить данные, используемые другими системными компонентами.
- **Способы снижения риска**:
    - **Контроль происхождения драйверов** — использование программ _WHQL_ (Windows Hardware Quality Labs) и _KMCS_ (Kernel Mode Code Signing).
    - **Технологии защиты ядра** — внедрение _Virtualization-Based Security_ (VBS), _Device Guard_ и _Hyper Guard_.

### Надёжность и производительность

- **Надёжность и стабильность** — сочетание разделения режимов и мер по контролю драйверов делает Windows надёжной платформой для рабочих станций и серверов приложений.
- **Быстрота и гибкость** — при этом система остаётся эффективной в работе базовых сервисов: управление виртуальной памятью, файловый ввод-вывод, сетевые коммуникации и совместное использование принтеров.

### Объектная модель и язык реализации

- **Широкое использование объектов** — Windows повсеместно применяет объекты для представления общих системных ресурсов.
- **Не является чисто объектно-ориентированной** — несмотря на это, Windows не относится к объектно-ориентированным ОС в прямом смысле слова.
- **Реализация на языке C** — большая часть кода ОС написана на языке C для обеспечения переносимости.
- **Особенность реализации** — в C отсутствует прямая поддержка полиморфизма, наследования классов и других объектно-ориентированных конструкций. Объектная модель Windows реализована на базе C, заимствуя некоторые принципы ОО-языков, но не завися от них напрямую.

## Обзор архитектуры

На рис. прежде всего обратите внимание на линию, разделяющую части пользовательского режима и режима ядра ОС Windows. Блоки выше линии представляют процессы пользовательского режима, а компоненты ниже линии — сервисные средства ОС режима ядра. Потоки пользовательского режима выполняются в закрытом адресном пространстве процессов (хотя во время выполнения в режиме ядра они получают доступ к системному пространству)
